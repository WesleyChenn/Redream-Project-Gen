# Lesson: 组团内 layout 单一化 — 不能既横排又竖排

## 一句话

一个 FRAME 内部, 子节点必须能用**单一一种 layout 描述** (NONE / HORIZONTAL / VERTICAL 三选一)。 **禁止**在同一个 FRAME 内混合 HORIZONTAL + VERTICAL 关系。 混合时拆 wrapper 子 FRAME, 父用 NONE, 子各自统一。

## 易犯错的场景

RoyalPass 节点行内有:
- 左奖励气泡: 心 icon + "30m" 文本 (上下竖排)
- 中间黄色框: 2 根上下线 (竖排)
- 右奖励气泡: 大炮 icon + "x2" 文本 (上下竖排)
- 三组之间是横向关系

❌ **错** (整行打 HORIZONTAL AL, 把气泡里的竖排关系一刀切):
```text
组_行 (HORIZONTAL AL)  ← 错
├── 心 icon
├── "30m" 文本
├── 黄线1
├── 黄线2
├── 大炮 icon
└── "x2" 文本
```

后果:
- 7 个子节点强行打横排, 心和 "30m" 本应该竖排, 但 AL 把它们摆成水平
- 视觉错位严重, AL 完全失去意义

## 正确做法

```text
组_行 (HORIZONTAL AL 或 NONE)  ← 外层关系单一 (3 个子 wrapper 横排) → 可以 AL
├── 组_左奖励气泡 (VERTICAL AL)  ← 心 + 30m 竖排, 内部统一
│   ├── 图标_心
│   └── 文本_30m
├── 角标_黄框 (VERTICAL AL)  ← 2 根线竖排, 语义共存强制聚类
│   ├── 线_上
│   └── 线_下
└── 组_右奖励气泡 (VERTICAL AL)  ← 大炮 + x2 竖排
    ├── 图标_大炮
    └── 文本_x2
```

每个 FRAME 内部都是单一 layout, 收敛 ✓

## 识别 + 聚类算法 (#3.1 Step 1-6 简要)

判定一个 FRAME 是否能直接打单一 AL, 走这 6 步:

1. **量测**: 子节点 cx/cy
2. **关系矩阵**: 任意两两标"竖排 / 横排 / 无对齐" (容差 ±3/±5/±10 按父 FRAME 短边查表)
3. **聚类成原子组**:
   - 依据 A: 位置强关系 (距离近 + 中心对齐)
   - 依据 B: 语义共存 (5 信号: 视觉镜像/对称/边框性质/同步现身/装饰依附)
   - B 优先于 A
4. **原子组之间关系**: 决定父 FRAME 用 NONE / HORIZONTAL / VERTICAL
5. **覆盖度判定** (union(bbox)/parent_area):
   - ≥ 80%: A 类 — 各原子组包独立 wrapper
   - 30~80%: 灰区 — 主动问用户
   - < 30%: B 类 — 局部混合包 1 wrapper, 其余平铺
6. **递归**: 每个新 wrapper 跑 Step 1-6, 直到内部单一

## 通用兜底规则 ⛔

任何 Step 1-5 进不下去, **父 FRAME 强制 NONE, 所有子节点平铺**:
- 子节点 ≤ 1 → NONE
- 完全重叠 → NONE
- 递归 3 轮不收敛 → 当前层 NONE
- 依据 A vs B 冲突 → B 优先

## 语义共存 (依据 B) 的 5 个视觉信号

不依赖主观判定, 命中任一即聚类:

| # | 信号 | 例子 |
|---|---|---|
| ① | 视觉镜像 | 左花纹 ↔ 右花纹镜像 |
| ② | 视觉对称 | 进度条左 icon ↔ 右 icon |
| ③ | **边框性质** (多元素组成闭合框) | 上线+下线 / 左线+右线 / 四角装饰 |
| ④ | 跨多实例同步现身 | N 个元素永远一起出现 |
| ⑤ | 装饰依附 (无独立交互) | 角标依附按钮 |

> RoyalPass 黄框: 上下 2 根黄线 → 信号 ③ 命中 → 强制聚成黄框 wrapper

## S3 执行顺序 (跟 #2 / #5 衔接)

```
□ Step 1: #2 标准 1+2 聚类 (结构相似 / 成排成列)
□ Step 2: #2 标准 3 聚类 (语义化功能成组)
□ Step 3: #2 角标父本识别
□ Step 4: #3 给每个组团 layout 初判
□ Step 5: 对每个组团跑 #3.1 入口判定 (前 1-3 已聚类的跳过依据 B 避免重复)
□ Step 6: 跑 #3.1 Step 1-6
□ Step 7: #4 y 坐标计算
□ Step 8: #5 填表 B
```

⚠️ Step 5 关键: #3.1 依据 B 不重复跑已聚类元素, 避免跟 #2 标准 3 + 角标父本概念冲突。
