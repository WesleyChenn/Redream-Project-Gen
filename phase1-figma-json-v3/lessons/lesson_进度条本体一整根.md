# Lesson: 进度条本体永远画一整根 100% 满

## 一句话

不管进度条上是否压有节点 icon / 里程碑节点, Figma 侧的 `进度条_XXX` RECT **永远只画一整根 100% 满**, **不要按节点位置拆成多段 RECT**。 引擎运行时按 percentage 切割整根, 节点 icon 视觉上自然显示"已过/未过"。

## 易犯错的场景

### 场景 1: 单节点进度条画当前进度

❌ **错**: 视频里进度条显示 65% 满, 设计稿就把 `进度条_经验` RECT 画成 65% 宽度

```json
{ "底板_经验": { "w": 500 } }
{ "进度条_经验": { "w": 325 } }    ← 错: 写了当前数值
```

✅ **对**: 永远画 100% 满, 引擎运行时切

```json
{ "底板_经验": { "w": 500 } }
{ "进度条_经验": { "w": 480 } }    ← 100% 满模板 (含内缩 10/边)
```

### 场景 2: 多节点进度条拆段

视频里 RoyalPass 类型条上有 4 个里程碑节点, 设计师以为每段进度独立:

❌ **错**:
```json
节点行 (大组团):
├── 进度条_段1 RECT (起点到节点1)        ← 错: 拆段
├── 进度条_段2 RECT (节点1到节点2)        ← 错
├── 进度条_段3 RECT (节点2到节点3)        ← 错
├── 节点1 INSTANCE
├── 节点2 INSTANCE
├── 节点3 INSTANCE
└── 节点4 INSTANCE
```

后果:
- 引擎拿不到完整 `CCProgressTimer`, 无法运行时切割
- "已过 / 未过"状态被硬编码进设计, 无法按玩家数据动态调整
- 进度从 60% 变 75% 需要改设计稿, 而不是改数据

✅ **对**:
```json
组_进度_RoyalPass (FRAME, 三层):
├── 底板_RoyalPass RECT (100% 满)
└── 进度条_RoyalPass RECT (100% 满模板, 引擎 CCProgressTimer)

节点 INSTANCE 叠在条上方 (不拆段):
├── 节点1 INSTANCE
├── 节点2 INSTANCE
├── 节点3 INSTANCE
└── 节点4 INSTANCE
```

引擎运行时: `progress=0.6` → 切割整根 `进度条_RoyalPass` 到 60% 处 → 节点 1/2 视觉上"已过", 节点 3/4 "未过"。

### 场景 3: 短进度段抽 Variant

❌ **错**: 把"节点 N 到节点 N+1 之间的短进度段"抽成 Component, 做"已完成 / 未完成" 2 Variants

后果: 短进度段本质是进度条本体的一部分, 应该由引擎切割整条, 不是设计阶段切 Variant。

✅ **对**: 短进度段也是进度条本体, **不抽 Component, 不做 Variant**。 引擎按每段数据切割整根。 节点 icon (里程碑) 才抽 Component + 多 Variant (已完成 / 未完成 / 当前)。

## 区分: 进度条本体 vs 进度条 icon

这两个**严格区分**:

| 类型 | 例子 | 抽 Component? | 抽 Variant? | 实现 |
|---|---|---|---|---|
| **进度条本体** (横向) | key 进度条 / 体力进度条 / 经验进度条 | 通常不抽 | ❌ 不做 | 双层 RECT, 引擎 CCProgressTimer |
| **进度条本体** (纵向/多段) | 节点之间的短进度段 | ❌ 不抽 | ❌ 不做 | 同上, 引擎切割每段 |
| **进度条 icon / 里程碑节点** | 节点六边形 / 端点装饰 icon | ✅ 抽 (跨多实例) | ✅ 多 Variants | 子节点 visible 切换 |
| **进度条数值文本** | "39/40" / "x/y" | ❌ 不抽 | ❌ 不做 (dynamic) | TEXT.content, S11 自动 overrides |

## 原因 (为什么必须一整根)

1. 引擎用 `CCProgressTimer` 在运行时按 percentage 切割整根 RECT, 不是切多段
2. 节点"已过 / 未过"状态本来就由节点自身 Variant 表达 (已完成 / 未完成 icon)
3. 拆段 = 把"动态数据"硬编码到设计阶段, 失去引擎按数据动态切割的能力
4. 多节点进度条的"节点位置" 跟"进度填充百分比" 是两个独立维度, 不应耦合
