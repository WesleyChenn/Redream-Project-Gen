# S4 · 识别交互

> **阶段**: 识别阶段, 第 4 步
> **前置**: S0 上下文已读, S1-S3 已完成
> - 输入是录屏 → S1 帧序列 + S2 元素清单 + S3 组团/布局 都有
> - 输入是多张截图 → S2 + S3 有, 但**没帧间对比信息**, 触摸点和按钮缩放识别受限 (只能识别明显的反馈, 不能做帧间动画推断)

---

## 这一步做什么

基于 S1 帧序列 + S2 元素清单 + S3 组团结构, 识别**屏幕里的交互行为**:

1. **滚动区识别** — 哪些区域可滚动 (方向 / 单元 / 锚点帧)
2. **触摸点识别** — 用户在哪一帧、点了哪个位置、命中哪个 UI 元素
3. **按钮被点的视觉反馈** — 帧间对比按钮缩放 / 位移 / 高亮变化, 推断点击事件

**这一步只识别"哪里发生了什么交互"**, 不关心:
- 点击导致的屏幕跳转关系 (S5 提取 flow)
- 哪个按钮是触控层 / REDNodeButton (S7 生成阶段决定)
- 写 JSON (S7-S9)

---

## 输入

- S1 帧序列 (录屏) 或 用户提供的多张截图
- S2 页面元素清单
- S3 骨架 + 组团结构

## 该步做的事

### 1. 滚动区识别 (谁在动谁不动)

逐帧比对同一屏幕连续帧, 标注三类区域:

- **固定区** (不动): 顶部标题/HUD / 底部导航 / 全局浮层按钮
- **滚动区** (在动): 列表卡片区 / 网格区 / 排行榜条目区
- **Viewport**: 滚动内容可见窗口的上/下边界

强制规则:
- **固定区必须单独成组** (S3 已组团化), 禁止并入滚动容器
- **滚动区是独立父容器**, 明确 x/y/w/h
- 仅中间内容变化、上下栏稳定 → **单屏 + 滚动**, 不是多屏

### 2. 滚动方向与单元

- **纵向位移** → `VERTICAL`
- **横向位移** → `HORIZONTAL`

滚动单元模板:
- **列表型**: 行高基本一致, 按行重复
- **网格型**: 固定列数, 单元等宽, 按行推进
- **混合型**: 先按区块拆分, 每个区块内再判定

### 3. 锚点帧记录

每个滚动区**至少记录三组锚点**:

- `anchor_start`: 滚动前首帧 (顶部可见项)
- `anchor_mid`: 滚动中段帧 (验证模板是否成立)
- `anchor_end`: 滚动后稳定帧 (底部新项)

### 4. 触摸点识别 (像素扫描)

对**每一帧**, 用像素扫描找触摸点 — 半透明白色圆形区域:

| 判定条件 | 值 |
|---|---|
| RGB 均值 | > 200 |
| 与周围像素亮度差 | > 40 |
| 直径范围 | 20-60px (源帧像素) |

记录圆心坐标 `(x, y)`。

⛔ **强制执行, 不得跳过任何一帧**。

### 5. 触摸点映射 UI 元素

将触摸点坐标映射到当前帧的 UI 层级 (用 S2/S3 的元素 + 组团清单), 确认被点击的**具体节点**。

特别注意:
- **触摸点落在场景背景/建筑/地图区域时**, 视为点击该区域**对应的隐式交互目标**, **必须记录** (不得因"不是明显按钮"而忽略)
- 触摸点不可见 (录屏未开启触摸显示) → 标"**来源未确认**", 走 #6 兜底

#### 🔴 触摸点落在装饰元素时 → 归属到父按钮

S0 第 14 节: **装饰** (角标 / 徽章 / 底标 等) 作为按钮 children, 但**自己不是触控层**, 没有独立点击响应。视觉上触摸点落在装饰位置, **实际点击的是包含它的父按钮** (装饰跟父按钮一起响应)。

S4 阶段映射触摸点时, 必须做这个**归属转换**:

| 触摸点视觉落在 | 表 E 命中 UI 元素 写 |
|---|---|
| `按钮_xxx` FRAME 自身 | `按钮_xxx` (直接) |
| `按钮_xxx` 内的 `底板_xxx` / `图标_xxx` / `文本_xxx` (主元素) | 父按钮 `按钮_xxx` |
| `按钮_xxx` 内的 `角标_xxx` / `徽章_xxx` / `底标_xxx` (**装饰**) | **父按钮 `按钮_xxx`** (装饰不可独立点击) |
| 做法 B 包装的 `component_ref` 内部 (按钮组件) | 外层 `按钮_xxx` FRAME |

⛔ **禁止**: 表 E 命中 UI 元素写"角标_红点" / "徽章_新" / "底标_倒计时" 等**装饰 name** — 必须归属到父按钮。

例:
- 触摸点 `(864, 250)` 视觉上在 `角标_红点` 内 (该角标是 `按钮_设置` 的 children)
- ❌ 错误: 表 E 命中 UI 元素 = `角标_红点`
- ✅ 正确: 表 E 命中 UI 元素 = `按钮_设置` (角标_红点 是装饰, 不可独立点击)

这条规则同时影响 **S5 表 G flow.from** 和 **S9 flow 数组写入** — 源头在 S4 修正后, 下游自动正确。

### 6. 触摸点不可见兜底 (候选推断)

当录屏没开触摸点显示, 不能看到点击位置, 按以下规则推断触发元素:

#### 规则

1. **按目标屏幕主题反推候选** — 从目标屏的内容主题 (标题/主 icon/场景元素) 倒推源屏里哪些按钮"视觉契合"
2. **列 2-3 个候选 (有序)** — 按契合度从高到低, **不是只列一个**自信的候选
3. **明确标注"来源未确认"**, 把最终判断权交给用户
4. **等用户确认后再写最终结论**, 不要绕过

#### 契合度判定示例

| 目标屏主题 | 源屏按钮 | 契合度推理 |
|---|---|---|
| Easter Pass (复活节, 篮子+彩蛋) | 按钮_活动篮子 (篮子图标) | 高契合 (篮子直接对应) |
| Easter Pass | 按钮_活动花朵 (花朵图标) | 高契合 (花朵=复活节装饰) |
| Mission Pursuit (侦探, 国王+放大镜) | 按钮_活动放大镜 (放大镜图标) | 极高契合 (放大镜=侦探标志) |
| Mission Pursuit | 按钮_活动紫罐 (罐子+金币+卷轴) | 中契合 (卷轴=任务线索) |

#### 输出格式

```text
事件 #N (frame 38):
  触摸点: 来源未确认
  候选 (按契合度降序):
    1. 按钮_活动放大镜   [极高契合] 放大镜=侦探标志, 目标屏主题是侦探
    2. 按钮_活动紫罐     [中契合]   卷轴可能=任务线索
    3. 按钮_活动花朵     [低契合]   花朵与侦探主题弱相关
  视觉反馈 (帧间对比): 按钮_活动放大镜 在 frame 37→38 有缩放 0.9x
```

#### 禁止

- ❌ 只列一个候选就断定 ("肯定是放大镜")
- ❌ 不标"来源未确认"就写结论
- ❌ 猜一个就直接用, 不给用户选择空间
- ❌ 因为上一屏用过"紫罐", 这次默认也是 (**每个事件独立推断**)

#### 实操建议: 提示用户开启触摸点显示

如果发现整段录屏**完全没有触摸点** (每帧 #4 像素扫描都扫不到), 大概率是用户录屏时**没开 Show taps**。

主动告知用户下次录屏前开启:

| 平台 | 路径 |
|---|---|
| **iOS** | Settings → Developer Options → Show taps |
| **Android** | 设置 → 系统 → 开发者选项 → 显示点按操作反馈 |

开启后录屏会自动显示触摸点圆圈, 大幅提升识别准确率, 减少 #6 兜底候选推断的次数。

> #6 候选推断**不是常态**, 是"用户没开 Show taps 时的退化方案"。每次走兜底都要**主动提醒用户**, 而不是默默推断完事。

### 7. 按钮缩放/位移推断点击 (帧间对比)

除了触摸点像素扫描, 还可以通过**对比相邻帧的按钮视觉变化**推断点击:

| 视觉变化 | 推断 |
|---|---|
| 按钮在 frame N → N+1 缩放 0.9x (按下态) | 该帧附近发生了点击 |
| 按钮在 frame N → N+1 颜色变深 / 描边变化 (激活态) | 该按钮被选中 |
| 按钮在 frame N → N+1 位移 (按下回弹) | 该帧附近发生了点击 |

**用法**:
- 主要用于**触摸点不可见**的兜底验证
- 跟 #6 的候选推断结合 — 看哪个候选按钮在帧间有视觉反馈, 优先级最高

⚠️ **截图输入限制**: 如果输入是单张/多张静态截图 (不是录屏), 没有"帧间对比"信息, #7 无法执行 — 只能依赖 #4-#6 触摸点路径。

## 下游验证提示 (留给 S10 自检)

S4 识别的**滚动区**, 在 S10 自检 / 生成进 Figma 后, **必须手动滚一下验证**:

- ✅ **正确**: 顶部 / 底部的固定区保持不动, 只有滚动区内容在移动
- ❌ 整屏跟着滚 → 99% 是 `clip_content` 字段写成了 `clipsContent` (驼峰)
- ❌ 滚动区能滚到负数位置 (列表顶还能继续上滑, 露出空白) → 子容器 `layoutSizingVertical` 没设 `HUG`
- ❌ 滚动区一直不动 → 父容器 `overflow` 写成 `"NONE"` 或缺失

具体字段命名 / 修法在 **S7** (生成阶段) + **S10** (自检) 处理, S4 不修。
