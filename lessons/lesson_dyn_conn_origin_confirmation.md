# Lesson: dyn 连线起点"坐标源 vs 视觉父级"必须先对齐不准猜

**日期:** 2026-04-14
**状态:** ✅ 已修复（六格烧烤 feedback_effect 改从 element.完成反馈特效定位点 出发）

## 事件

六格烧烤结构图中，完成反馈特效的 dyn 连线起点我自己选了 `main.特效层`（视觉父级），用户看 GIF 后指出：
> 完成反馈特效在 GIF 里很明显是创建在元素上的，元素应该要有一个"完成反馈特效定位点"告诉程序特效创建的坐标信息；具体的特效实例才挂载到游戏主界面的特效层。

用户还补了一句铁律：
> **这种不确定的你必须要先和我做确认和对齐。**

## 根因

dyn 连线在结构图里有三种可能的物理含义：
1. **坐标源**（spawn-at-where）：特效/单位的初始世界坐标由这个 node 决定
2. **逻辑触发**（triggered-by）：这段 rebolt func 发起了 instantiate 调用
3. **视觉父级**（attached-to）：实例最终挂载/渲染的 parent node

当三者落在不同卡片时（本例就是：触发者=container 的 "通知元素播放完成反馈" func，坐标源=element.完成反馈特效定位点，视觉父级=main.特效层），随便挑一种都不够准确，必须向用户对齐该项目想表达的含义。

第一版我默认选了 (3) 视觉父级，没问用户，于是丢了最关键的坐标绑定信息。

## 规则（硬性）

结构图 dyn 连线起点出现歧义时（三种含义落在不同卡片、或对应的原型图里特效明显"长"在某个子元素上但挂载在另一个层），**必须先用 AskUserQuestion 对齐**再画线。不允许默认选一种然后事后再改。

具体触发条件（满足任一即需对齐）：
- 原工程/GIF 里看到特效出现在 A，但源码显示 instantiate 调用在 B，父节点是 C（ABC 不相等）
- 道具/UI 元素既能从多个位置生成（商店/关卡奖励/广告位）又挂到同一个层，无法仅靠单一连线表达
- 文档未明说的任何 "触发 vs 挂载" 不一致情形

### 对齐话术模板

```
完成 X 的 dyn 连线应该从哪里出发？
A. 从 <坐标源 node>（语义=位置来源）
B. 从 <触发者 func/card>（语义=rebolt 发起实例化）
C. 从 <视觉父级 layer>（语义=最终挂载位置）
D. 画两条（最精准但会多一条线）
```

### 命中原则：优先选"坐标源"

在 Redream 这类 2D 坐标驱动的引擎里，**特效/飞行单位/反馈类实例**的结构图连线 **默认从坐标源节点出发**（比如 `element.完成反馈特效定位点` → `feedback_effect`），attach parent 在 feedback_effect 的 desc 字段里文字说明。理由：坐标源是设计师需要在节点树中"摆"的硬资产，视觉父级只是一个层级归属，后者在 rebolt 里改变 parent 成本低，前者不行。

但这仍是默认推测，涉及具体项目时**还是要对齐**——写死规则会掉另一个坑（用户的特定设计意图）。

## How to apply

1. 画结构图 conns 前，列一份"可疑连线清单"：找出所有"触发/坐标源/挂载"不一致的候选
2. 对清单里每一条用 AskUserQuestion 让用户选 A/B/C/D
3. 用户选完才落 conn 到 generator script
4. 脚本自检加一条：`feedback_effect` 这类挂特效层/反馈类的 card，其 conns 起点应标注在 `node.label` 里含"特效定位点/反馈定位点/<目标>定位点"的节点
