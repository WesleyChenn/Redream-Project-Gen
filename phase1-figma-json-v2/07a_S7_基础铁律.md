> **范围**: 命名白名单 / JSON 格式 / 字段命名 / fill / children 顺序 / 卡片底板 / 无一层底 / 额外字段约束

## 1. 命名白名单 (来自 旧 00a)

所有 JSON 节点 `name` 前缀必须来自以下白名单, **违反 = 幻觉错误**:

`界面_` `浮层_` `组_` `底板_` `内容区_` `内容_` `容器_` `导航_` `列表项_` `网格行_` `网格项_` `弹窗_` `按钮_` `图片_` `图标_` `背景_` `遮罩_` `文本_` `文字_` `弹性缝隙` `角标_` `徽章_` `进度_` `进度条_` `Tab_` `切换_` `请求_` `消息项_` `活动_` `底标_`

> **预制特例**(v20.7.x+ 2026-05-15):当前仅 `钟表_指针动画` 一个预制 (沿用旧命名, 走白名单内 `钟_` 不规范作为唯一特例)。Figma frame 命名 `钟表_指针动画` 严格匹配即触发引擎自动复用预制 .red, 无需 `component_ref` / `components[]`。详细规约见 **`08a_S8_预制组件.md`**。其他子 ccb 都走 `components[]` 普通生成, 参考 **`06a_S6_ccb抽取标准.md`** 决定怎么抽。

## 2. JSON 格式铁律

| 正确 | 错误 |
|---|---|
| `"RECTANGLE"` | ~~`RECT`~~ |
| `"content"` (TEXT 内容) | ~~`text`~~ |
| `"textAlignHorizontal"` | ~~`text_align`~~ |
| `"flow"` (S9 写) | ~~`flows`~~ |
| 屏幕顶层用 `layers`, 内部用 `children` | ~~屏幕顶层 children~~ |
| 屏幕对象 `{ "name", "type": "FRAME", "w", "h", "layers" }` | ~~`{ type, children }`~~ |
| 手搓节点 fill **一律省略** | ~~`"fill": "#xxx"`~~ ~~`"fill": "transparent"`~~ |
| **screens 尺寸用 `"w"` / `"h"`** | ~~`"width"` / `"height"`~~ |

### 字段命名铁律 — 下划线 vs 驼峰 🔴 (来自 旧 05)

插件 `code.js` 里有些字段读下划线, 有些读驼峰, **必须严格按这个表写**。**字段名错 → 插件读不到, 字段完全失效**。

**读下划线的字段** (插件特有):

| 字段 | 错误写法 | 用途 |
|---|---|---|
| `clip_content` | ~~`clipsContent`~~ | 裁切子节点 (滚动容器必需) |
| `corner_radius` | ~~`cornerRadius`~~ | 圆角半径 |
| `font_size` | ~~`fontSize`~~ | TEXT 字号 |
| `font_weight` | ~~`fontWeight`~~ | TEXT 粗细 |
| `component_ref` | ~~`componentRef`~~ | 组件库引用 key |

**读驼峰的字段** (按 Figma API):

| 字段 | 用途 |
|---|---|
| `layoutMode` | NONE / HORIZONTAL / VERTICAL |
| `primaryAxisSizingMode` / `counterAxisSizingMode` | FIXED / AUTO |
| `primaryAxisAlignItems` / `counterAxisAlignItems` | MIN / CENTER / MAX / SPACE_BETWEEN |
| `layoutSizingHorizontal` / `layoutSizingVertical` | FIXED / HUG / FILL |
| `textAlignHorizontal` / `textAlignVertical` | LEFT / CENTER / RIGHT / TOP / BOTTOM |
| `paddingLeft` / `paddingRight` / `paddingTop` / `paddingBottom` | 内边距 |
| `itemSpacing` | AL 子元素间距 |
| `overflow` | VERTICAL / HORIZONTAL / NONE |
| `layoutPositioning` | ABSOLUTE (仅 AL 容器内使用) |
| `constraints` | `{ horizontal: SCALE/LEFT/RIGHT/CENTER, vertical: SCALE/TOP/BOTTOM/CENTER }` |

> ⚠️ Figma 节点属性在 Figma API 里叫 `clipsContent` / `cornerRadius` (驼峰), 但**插件 JSON 输入端读的是下划线**。

⛔ **后果**: 字段名错 → 插件**完全忽略**该字段 (本轮 `clipsContent` 错写导致 Easter Pass 整屏跟滚 = 这个原因)。

#### 不确定字段命名时的查证方法 (来自 旧 05)

碰到上表没列的字段, 不确定下划线还是驼峰, **唯一正确的方法是去 `code.js` grep `layer.xxx` 查证**:

```bash
grep "layer\." /path/to/figma-plugin/code.js
```

例子:

```js
// code.js L381:
fr.clipsContent = !!layer.clip_content;     // ← 插件读 layer.clip_content (下划线)
// code.js L380:
if (layer.corner_radius) fr.cornerRadius = layer.corner_radius;
```

看 `layer.xxx` 这个 xxx 就是 JSON 输入端字段名。**以 `layer.xxx` 为准**。

## 3. fill 规则 (来自 旧 00a)

- **FRAME**: 永远不填色, fill 一律省略 (插件强制透明)
- **RECTANGLE 手搓**: fill 一律省略, 由插件按命名前缀自动分配灰色
- **`component_ref`** 节点: 不受此规则约束 (组件库内部 fill 由 Figma 维护)

## 4. children 排序铁律 🔴 (来自 旧 05)

**children 数组从底到顶排序** — 底板 / 背景在前, 内容 / 按钮在后。

```text
按钮_xxx FRAME children:
  [
    { "type": "RECTANGLE", "name": "底板_xxx" },     ← 索引 0, 最底层
    { "type": "RECTANGLE", "name": "图片_xxx" },     ← 索引 1
    { "type": "TEXT", "name": "文本_xxx" },          ← 索引 2
    { "type": "FRAME", "name": "角标_xxx" }          ← 索引 3, 最顶层 (装饰最后)
  ]
```

### NONE 父容器内的关闭 / 信息按钮 — 必须放 children **最后**

否则被后续 children 遮挡, 用户点不到。

```json
✅ 正确:
{ "type": "FRAME", "name": "浮层_设置", "layoutMode": "NONE", "children": [
    { "type": "RECTANGLE", "name": "遮罩_浮层背景", ... },   // 0
    { "type": "RECTANGLE", "name": "底板_弹窗", ... },        // 1
    { "type": "TEXT", "name": "文本_标题", ... },             // 2
    { "type": "FRAME", "name": "组_设置项", ... },            // 3
    { "type": "FRAME", "name": "按钮_关闭", ... }             // 4 (最后, 不被遮挡)
]}
```

### 进度条相关排序 (来自 7c #5 进度条建模)

`进度条_XXX` index **必须 > `底板_XXX` index** (进度条在底板之上)。

## 5. 卡片 / 弹窗外壳铁律 🔴 (来自 旧 04 规则 5 + 旧 06)

**卡片 / 弹窗 / 大区域外壳必须是 `底板_xxx` RECTANGLE, 不能是 FRAME**。

⛔ **禁止**: 把卡片/弹窗外壳命名为 FRAME (这是 v19 老命名)

| 场景 | 节点类型 | 命名 |
|---|---|---|
| **真按钮触控层** | `FRAME` | `按钮_xxx` |
| **按钮内层底板** (父是按钮 FRAME) | `RECTANGLE` | `底板_xxx` |
| **外层容器底板** (卡片 / 弹窗 / 大区域, 父非按钮) | `RECTANGLE` | `底板_xxx` |
| **装按钮的容器** (纯分组) | `FRAME` | `组_xxx` / `容器_xxx` / `弹窗_xxx` |

### 正确示例: 卡片结构

```json
✅ 正确:
{ "type": "FRAME", "name": "容器_EasterPass卡",      // 容器 = FRAME (不是底板)
  "w": 1042, "h": 544, "layoutMode": "NONE",
  "children": [
    { "type": "RECTANGLE", "name": "底板_EasterPass卡",   // ← 底板 = RECT (不是 FRAME)
      "x": 0, "y": 0, "w": 1042, "h": 544,
      "corner_radius": 30,
      "constraints": { "horizontal": "SCALE", "vertical": "SCALE" } },
    { "type": "TEXT", "name": "文本_EasterPass标题", ... },
    { "type": "FRAME", "name": "按钮_Activate", ... }     // 卡内按钮
  ]
}
```

⛔ 装按钮的容器**禁止用 `底板_` 前缀** — 引擎按 `底板_` 当作 RECT 底板处理。

## 6. 无"一层底"铁律 (来自 旧 06 第四层)

**FRAME 不能同时有 `fill` 和 `children`** — 这是 v19 老命名残留, v20 已禁止。

```json
❌ 错误 ("一层底"):
{ "type": "FRAME", "name": "组_xxx",
  "fill": "#xxxxxx",                  // ← FRAME 有 fill
  "children": [ ... ] }               // ← 同时有 children

✅ 正确: 拆成两层
{ "type": "FRAME", "name": "组_xxx",
  "children": [
    { "type": "RECTANGLE", "name": "底板_xxx", ... },   // RECT 承担 fill
    ...
  ]
}
```

(注: 手搓节点 fill 一律省略, 由插件按命名自动上灰, 见 #3。)

## 7. 额外字段约束清单 (来自 旧 06 自检综合)

### TEXT 节点字段约束
- ❌ **不写 `w` 字段** (除非有固定宽度约束) — 让 TEXT 跟随内容
- ✅ 居中文本必须 `textAlignHorizontal: CENTER` + `textAlignVertical: CENTER`

### 禁用属性
- ❌ **不写 `stroke` / `strokeColor` / `strokeWidth`** — 描边由插件按命名上色

### 同组控件尺寸一致
- ✅ **对称布局两个按钮 w 必须相同**
- ✅ 同类按钮 FRAME 尺寸统一便于 AL 对齐
- 量测精度容差 **±5%**, 超出说明量测有误应重测

### 同屏 name 唯一性
- ✅ **同一屏幕内没有重名节点**
- 否则 `flow.from_node` 引用混乱, 引擎找不到目标

### 老命名禁止清单
- ❌ `切图_底板_` 前缀 (v18 老命名, 已废弃)
- ❌ `底板_xxx 形状` 后缀 (v19 老命名, 已废弃)
- ❌ `底板_xxx FRAME` 当按钮用 (v19 老命名, v20 改为 `按钮_xxx`)

### 滚动不写进 flow
- ❌ 滚动是**内容滚**, 不是屏幕跳转, **不写 flow 数组** (S9 处理)
- 滚动行为靠 `clip_content` + `overflow` + `layoutSizingVertical: HUG` 实现 (见 7e #3)
