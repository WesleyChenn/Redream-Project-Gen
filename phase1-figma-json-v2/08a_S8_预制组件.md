## 这一步做什么

把设计稿里**唯一一种带旋转指针动画的钟表 UI**, 通过**给 Figma frame 命名 `钟表_指针动画`**, 让引擎直接复用 `red_tool/prefabs/钟表_指针动画.red` 这份已沉淀的 .red 文件 (跳过常规生成 + 跳过 component_ref 解析)。

跟 S8 component_ref 的本质区别:

| 维度 | `component_ref` (S8) | 预制 (S8a) |
|---|---|---|
| 内容来源 | 组件库 JSON (Figma 端维护) | `red_tool/prefabs/` 三件套 (引擎工程内沉淀) |
| Figma 端做法 | INSTANCE 实例化组件 + 写 `component_ref: "<key>"` | **普通 frame, name 写 `钟表_指针动画`** |
| scene.json 字段 | `component_ref` (独立 key) | `name` (复用普通 frame 的 name 字段) |
| 引擎处理 | 子 CCB 生成 → REDFile 引用 | **直接拷预制 .red, 跳过生成** |
| 适用场景 | 视觉随实例变化 (按钮文字 / 角标) | 钟表带旋转指针动画 (唯一特例) |
| 命名 | 沿用 30 个白名单前缀 | **沿用旧命名 `钟表_指针动画`**(白名单未独立列, 唯一特例) |

## 二、识别 → 命名规则

### S6 pattern 命中后, S7 时怎么写 scene.json

S6 表 H 命中以下视觉特征 → S7 直接写**普通 FRAME + name = 钟表_指针动画**:

- **钟面 + 旋转指针动画 (能看到指针在转) + Scale9 底板 + 时间文本**

如果是**静态钟表 icon + 时间文本**(指针不转), 走 `component_ref: "底标_倒计时"`(S8), 不走预制。

### scene.json 输出示例

```json
{
  "name": "钟表_指针动画",
  "type": "FRAME",
  "x": 435, "y": 650, "w": 300, "h": 70,
  "constraints": {"horizontal": "CENTER", "vertical": "TOP"}
}
```

**不需要**:
- `component_ref` 字段
- `components[]` 数组声明
- `children` (写了也会被引擎忽略)

### 精确字符串匹配

| Figma frame 命名 | 是否触发预制 |
|---|---|
| `钟表_指针动画` | ✅ |
| `钟表_指针动画 2` (Figma 复制粘贴自动加 " 2") | ❌ 必须手动改回 |
| `钟表指针动画` (少了下划线) | ❌ |
| `预制_钟表指针动画` (老 C 方案命名, 已废弃) | ❌ |

## 三、跟其他铁律的边界

### 边界 1: `钟表_指针动画` 跟 `component_ref: 底标_倒计时` 的区分

- `钟表_指针动画`(预制): **带旋转指针动画**的钟表
- `底标_倒计时`(component_ref): **静态钟表 icon + 文本框** 的倒计时

视觉判断: 指针在转 → 预制; 静态 → component_ref。

### 边界 2: 跟"按钮装饰必须是按钮 child"铁律 (07b) 的关系

预制 self-contained, 内部 children 由 `.red` 决定, Figma 端画的 children 全部被忽略。装饰要做进预制 → 改预制本身, 不能从外面挂。

### 边界 3: `钟表_指针动画` 不走 scale 公式

scene.json 的 `w/h` 直接是 **Figma 量出来的原始尺寸**, 引擎用这个 w/h 决定 REDFile 节点的位置框, **不影响预制内部视觉大小** (由 `.red` 内部决定)。

## 四、引擎侧机制 (引用, 不必深读)

完整规范: [引擎 SKILL · 03_component.md §8.13](/Users/red/Desktop/引擎最新skill/03_component.md)

简要流程:
1. 引擎收到 scene.json → `_collect_prefab_refs(scene)` 递归扫所有 layer 的 `name` / `component_ref` / `component_name` 字段
2. 命中 `PREFAB_NAMES` (= `{钟表_指针动画}`) → 自动注册到 `_COMPONENT_VARIANT_SEQID` (避开 INSTANCE 兜底)
3. **独立预制循环**: 拷 `prefabs/钟表_指针动画.red` 到 `<output>/ccb/<module>/`, 同步 `.plist + .webp` 到 `<output>/_img_plist/<module>/`, 自动改 .red 里 `displayFrame`/`spriteFrame` 路径加 `<module>/` 前缀
4. 主屏 build 时, 该 layer 走 `make_redfile_single` 单层 REDFile (跟生产 res_juice_pro 对齐), 用百分比 position 引用预制 .red

## 五、加新预制的流程 (给开发用, 设计师跳过)

新增稳定不变的 UI 模块要做预制, 5 步:

1. **从生产 res_juice_pro 找一份合格 .red 作源** (或者用户手搓)
2. **决定预制名** — 沿用原项目命名规范 (白名单前缀 `底板_` `组_` `按钮_` 等), 不再用 `预制_` 前缀
3. **跑沉淀脚本** (参考 2026-05-15 `钟表_指针动画` 沉淀 v3):
   - 调 `app.pack_atlas(png_entries, prefabs/<pname>.plist, prefabs/<pname>.webp)` 打独立小图集, frame 名通用化为 `<pname>_<layer>.png`
   - 用 `plistlib` 改 .red: `displayFrame` (CCSprite) 和 `spriteFrame` (CCScale9Sprite) 字段值都改成新 frame 名; plist 路径改成**裸名** `<pname>.plist`
4. **`app.py` 把新预制名加进 `PREFAB_NAMES`**
5. **回本文件第一节表格加一行**

不需要重启 Flask (预制是运行时读 `prefabs/`)。
