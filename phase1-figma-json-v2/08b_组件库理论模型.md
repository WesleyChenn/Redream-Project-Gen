## 一、3 条引用路径(决策优先级)

```
PREFAB_NAMES 命中 (name 字段) → 走预制特例 (08a)
    ↓ 不命中
"组件库" page 已有同名 Component → 走 component_ref 引用 (08)
    ↓ 不命中
满足 ccb 3 标准 → 抽子 ccb 进 components[] (06a)
    ↓ 不满足
inline 保留
```

3 条路径选谁, 优先级从上到下。

---

## 二、何时**才**需要"组件库" page

满足全部条件:
1. ✅ 视觉零件**跨整个项目复用** (50+ 界面都用同一个按钮)
2. ✅ 设计师明确要 Figma Master/Instance 同步关系
3. ✅ scene.json 用 `component_ref` 字段引用

例: `圆形按钮_关闭` 适合做组件库 Component;`列表项` (只在 Royal Pass) 直接进 components[] 即可。

---

## 三、3 类引用方式对比

| 类型 | Figma 端 | scene.json 字段 | 引擎处理 |
|---|---|---|---|
| **预制** | 普通 frame, 起精确名 `钟表_指针动画` | `name` 命中 PREFAB_NAMES | 拷 `prefabs/` 三件套 |
| **组件库 component_ref** | "组件库" page Master + INSTANCE 引用 | `component_ref` | 走 REDFile + 等比缩放 |
| **普通子 ccb** | 普通 frame, 起白名单前缀 | `components[]` 数组声明 | `generate_red_component` 现场生成 |

---

## 四、最简 mental model

**极小项目** (1-2 界面): 完全可以**没有"组件库" page**, 只用普通 frame + components[]。

**跨项目稳定零件多** (按钮 / 通用 icon 标准化): 才开"组件库" page, 命名沿用白名单前缀 (`圆形按钮_` / `椭圆按钮_` / `矩形按钮_` / `底标_` / `角标_`)。

不做 (排除):
- 跨 Figma 文件共享 (team library) — 暂不支持
- 组件库 JSON 自动 export — 暂时靠对话上下文
- 自动检测 Master/Instance 不同步 — 靠设计师手动 `Push to main`
