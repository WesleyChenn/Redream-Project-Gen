# S2 · 滚动菜单识别【录屏专用】

> 开始前先读取 `00_core_rules.md`，基于 S1 的屏幕清单执行

---

## 目标

产出**可复用的通用滚动结构**，而不是按某一帧静态拼图。

## 步骤

### 1. 识别滚动区（谁在动，谁不动）

逐帧比对同一屏幕连续帧，标注三类区域：

- **固定区（不动）**：顶部标题/HUD、底部导航、全局浮层按钮
- **滚动区（在动）**：列表卡片区、网格区、排行榜条目区
- **Viewport**：滚动内容可见窗口的上/下边界

强制规则：
- 固定区必须单独成组，禁止并入滚动容器
- 滚动区是独立父容器，明确 `x/y/w/h`
- 仅中间内容变化、上下栏稳定 → 单屏 + 滚动，不是多屏

### 2. 识别滚动方向与单元

- 纵向位移 → `VERTICAL`
- 横向位移 → `HORIZONTAL`

滚动单元模板：
- **列表型**：行高基本一致，按行重复
- **网格型**：固定列数，单元等宽，按行推进
- **混合型**：先按区块拆分，每个区块内再判定

### 3. 锚点帧记录

每个滚动区至少记录三组：
- `anchor_start`：滚动前首帧（顶部可见项）
- `anchor_mid`：滚动中段帧（验证模板是否成立）
- `anchor_end`：滚动后稳定帧（底部新项）

### 4. 新屏幕回写 S1 清单（强制）

S2 执行过程中，若发现**之前 S1 未收录的独立屏幕**（例如通过滚动末尾、Tab 切换或过渡帧识别到的新页面），必须：

1. **立即暂停 S2 输出**，先补充说明：「发现 S1 遗漏屏幕：界面_xxx」
2. **回写 S1 屏幕清单**：在 S2 输出开头列出修订后的完整屏幕清单（含原有 + 新增）
3. **补充对应的交互连线**：说明该屏幕的触发来源（触摸点位置或推断来源）
4. 继续执行 S2 剩余步骤

**S1 清单是唯一权威来源**，S4 的 flow 只能基于 S2 确认后的最终清单生成，不得使用 S1 原始版本。

**常见遗漏场景：**
- 触摸点落在场景背景/建筑物（非标准按钮）触发的全屏跳转
- 从滚动列表某项点击进入的详情页
- 帧差分恰好在 40% 边界导致误判为同一屏幕

## 输出格式

对每个屏幕的每个滚动区输出：

```
【S1 最终屏幕清单（含 S2 补充）】
1. 界面_主地图
2. 浮层_xxx
3. 界面_yyy  ← S2 新增，来源：触摸点@(x,y) 推断为背景_地图场景

【屏幕名】滚动区识别

固定区：
- 组_顶部标题 [y=0, h=250]
- 组_底部导航 [y=2181, h=219]

滚动区：
- 容器_列表滚动区 [y=250, w=1080, h=1931] (scroll: VERTICAL)
  └── 内容项：列表型，约8项
      - 消息项 h≈190（5项）
      - 请求项 h≈280（3项）← 异构行高
  └── anchor_start: 帧X（Dennis, Eva...）
  └── anchor_end: 帧Y（Teresa, Choy, Lokwan）
```

## 生成后强制验证

滚动结构生成进 Figma 后,**必须手动滚一下验证**,不能直接交给用户：

1. 在 Figma 里打开生成的文件,手动拖拽或滚轮滚动滚动区
2. **正确表现**：顶部/底部的固定区保持不动,只有滚动区内容在移动
3. **错误表现（必修）**：
   - 整屏跟着滚,顶部固定区和滚动区一起上移 → 99% 是 `clip_content` 字段写成了 `clipsContent`（驼峰）
   - 滚动区能滚到负数位置(列表顶还能继续上滑,露出空白) → 子容器 `layoutSizingVertical` 没设 `HUG`
   - 滚动区一直不动 → 父容器 `overflow` 写成 `"NONE"` 或缺失

若出现错误表现,返回 S5 修 JSON 字段,不要交付。

详见 `05_json_generate.md` → "字段命名铁律"。
