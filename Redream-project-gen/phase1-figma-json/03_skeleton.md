# S3 · 骨架分析【强制，生成前必须完成】

> 开始前先读取 `00_core_rules.md`，基于 S1+S2 结果执行

---

## 目标

为每个屏幕输出精确的骨架表格，验证 h 加总 = 2400。

## 执行流程（四步）

### 第一步：量测元素边界

- 用 Python 像素分析辅助量测，**不能纯目测估算**
- 获取帧尺寸 → 计算 scale_x / scale_y
- 录屏帧 H 必须排除播放器 UI

**异构列表行高：强制分别量测**
- 两种行外观明显不同 → 单独量测 h
- 禁止套用统一行高

### 第二步：物理分组

- 包含判定：文字/图标边界在色块内 → 色块为底板，建大包装
- 对齐判定：Y中心对齐 → HORIZONTAL；X中心对齐 → VERTICAL
- 地图区：`layoutMode: NONE`，保留绝对 x/y

### 第三步：y 坐标计算（强制顺序）

```
① 贴顶区域：从 y=0 往下叠加
② 贴底区域：从 y=2400 往上叠加
③ 中间内容区：h = 贴底起始y - 贴顶结束y
```

**禁止：** 从上往下一路叠加，导致底部重叠。

### 第四步：标注组件库匹配与角标归属（强制）

对每个元素标注：component_ref（组件名+缩放尺寸）或 手搓。

**识别顺序：**

**一、看区域类型**
- 贴底全宽 + 均分3~5个图标/文字 → 导航栏（走导航组件）
- 贴底全宽 + 2个横排切换按钮 → 状态切换导航

**导航栏元素数量强制核查（识别到导航栏后必须执行）**

⛔ **禁止用「屏幕宽度 ÷ 估算item宽度」推断导航项数量。** 这会导致少算或多算 item。

必须通过以下方式逐个确认：

1. **逐帧视觉数清楚**：在最清晰的帧上，逐个数出导航栏里有几块可见的图标/文字区域，记录每一个
2. **像素扫描验证**：对导航栏行像素扫描，找出各个高亮/激活色块的 x 范围，数出独立色块数量
3. **两种方式结果一致**才写入 `导航_项N` 的 N

常见陷阱：
- 激活态 Tab（通常更大更亮）容易被视觉合并为「背景+图标」两个元素，实际只是一个 Tab
- 反之，某些 Tab 图标相邻紧密，容易两个被数成一个
- **数完后在骨架表备注：「导航共 N 项，逐个确认：项1=xxx, 项2=xxx, ...项N=xxx」**

**二、看整体形状**
- 椭圆头像区 + 底部时间条 → `椭圆按钮_活动`
- 正圆底板 + 单图标 → `圆形按钮_xxx`
- 圆角方形 + 消息气泡 → `方形按钮_消息_激活/禁用`

**三、看内部结构**
- 只有文字 → `矩形按钮_纯文本`
- 胶囊条 + 进度数字（短）→ `进度条_短`
- 胶囊条 + 进度数字（宽）→ `进度条_宽`
- 圆角矩形 + 时间（无时钟图标）→ `底标_时间`
- 圆角矩形 + 时间（有时钟图标）→ `底标_倒计时`

**四、看叠加附件**
- 右上角小圆 + "!" 或数字 → `角标_感叹号`
- 右上角矩形 + "×2" 类倍率 → `角标_倍数`（仅用于 ×N 格式，普通数字角标手搓）
- 好友头像框 → `头像_朋友`

**五、component_ref 缩放有效性前置检查（强制）**

识别到组件库匹配后，**必须**确认该组件库条目内部子元素的 constraints，再决定是否使用 component_ref：

| 内部子元素 constraints | 缩放行为 | 处理方式 |
|---|---|---|
| `SCALE/SCALE` | ✅ 随 frame 等比拉伸 | 正常使用 `component_ref` |
| `LEFT/TOP` | ❌ 内容锚定左上角，frame 放大但内容不跟随 | 修改组件库后使用；或改为手搓 |
| `CENTER/CENTER` | ❌ 内容居中但尺寸不变 | 修改组件库后使用；或改为手搓 |

**推荐做法**：统一将组件库内所有子元素 constraints 改为 `SCALE/SCALE`，确保所有 component_ref 都能正确等比缩放。用户已确认组件库可缩放后，方可在 S3 表格中标注为 component_ref。

**六、角标归属（强制，识别到角标后必须执行）**

禁止将角标直接记录为独立元素，必须先完成以下两步再记入表格：

1. **找父本**：角标视觉上贴在哪个元素上，那个元素就是父本。在 S5 生成时，角标与父本必须在同一个 NONE 容器内，不允许与父本同级平铺在 AL 容器中。

2. **确认位置关系**：量测角标相对父本的位置，记入表格。判断方法：同时量测父本宽度、角标宽度，计算居中期望值与实际值比较，误差 <10px 判定为居中。

| 常见场景 | x（相对父本左上角）| y | constraints |
|---|---|---|---|
| 右上角溢出顶部 | 父本w - 角标w + 少量偏移 | -(角标h × 0.5) | RIGHT / TOP |
| 右上角压在边缘内 | 父本w - 角标w - 偏移 | 偏移 | RIGHT / TOP |
| 底部贴边居中 | (父本w - 角标w) / 2 | 父本h - 角标h/2 | CENTER / BOTTOM |
| 主体下方居中溢出 | (父本w - 角标w) / 2 | 父本h - 3（轻微压入底边） | CENTER / TOP |

**S3 输出表格新增两列：**

```
元素名称            | 截图量测  | 输出尺寸  | 匹配结论                    | 父本      | 位置关系
-------------------|---------|---------|---------------------------|----------|----------
角标_数字2          | 28×28   | 34×35   | 手搓                        | 组_Area8 | 右上角，x=父本w-34+10, y=-17
底标_4d22h         | 152×38  | 185×48  | component_ref 底标_倒计时   | 组_Tab_Weekly | 底部居中，x=(219-185)/2=17, y=91
```

**兜底：无法确认 → 默认手搓，不猜测引用不存在的组件名。**

### 第五步：AL 容器对齐意图确认（强制，S4 生成前必须完成）

组件匹配表输出完毕后，紧接着对所有 AL 容器输出布局意图确认表。

**先查以下默认值表得出结论，无法确定的标注「待确认」：**

| 场景 | 典型容器 | primaryAxisAlignItems | 是否可用弹性缝隙 |
|---|---|---|---|
| 屏幕顶层 HUD / 标题栏 | 组_顶部HUD、组_标题栏 | MIN | 标题需居中时可用×2 |
| 屏幕底层导航 / 操作栏 | 组_底部导航、组_底部操作栏 | SPACE_BETWEEN | 否 |
| 外侧大组内容区（非 HUD）| 组_底部按钮区、弹窗主内容 | **CENTER** | 否 |
| 响应式中间区内各行 | 滚动区内列表行、网格行 | MIN 或 SPACE_BETWEEN | 靠右单元素时可用 |
| 列表行内部 | 列表项_xxx | MIN + 内容区FILL | 靠右单元素时可用 |
| 卡片底部行（名称+按钮）| 组_底部行 | MIN | 是，名称靠左按钮靠右 |
| 网格行 | 网格行_第N行 | SPACE_BETWEEN | 否 |
| 弹窗内容 VERTICAL | 内容区_弹窗 | MIN | 否 |

**小游戏专项规则（高优先级，覆盖上表）：**
- 顶部 HUD（生命值/金币栏）以外的**所有外侧大组**，默认 `CENTER`
- 响应式中间弹性区以外的固定高度容器，优先 `CENTER`
- 底部双按钮区：两个按钮作为整体居中，用 `CENTER`，不用弹性缝隙

**弹性缝隙使用三条强制规则（在此步骤确认，S4 执行）：**

1. **只能放在两个实体元素之间**，禁止放在 children 列表首位或末位
   ```
   ❌ [按钮_皮肤, 按钮_Level3, 弹性缝隙]   ← 缝隙在末位
   ✅ [按钮_返回, 弹性缝隙, 按钮_关闭]     ← 缝隙在中间
   ```

2. **使用前必须在本表中说明意图**：写明缝隙左侧是什么元素，右侧是什么元素，实现什么视觉效果。未在本表确认，S4 不得写入弹性缝隙。

3. **以下场景禁止用弹性缝隙，改用对应方案：**

   | 场景 | ❌ 禁止 | ✅ 正确方案 |
   |---|---|---|
   | 多个元素整体居中 | 缝隙放首位或末位 | `primaryAxisAlignItems: CENTER` |
   | 均匀分布 | 缝隙放元素之间 | `primaryAxisAlignItems: SPACE_BETWEEN` |
   | 靠右单个元素 | — | 弹性缝隙放在该元素左侧（此情况允许） |
   | 标题居中+两端按钮 | — | 弹性缝隙×2，分别放标题两侧 |

## 验证（三项全过才能继续）

1. **算术闭环**：所有大区 h 加总 = 2400，无重叠无空隙

3. **AL 容器自检**：同组控件一致、对齐方式合规、空档处理正确
