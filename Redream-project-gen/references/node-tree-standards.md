来源：6 个标准工程样例 + 工程搭建规范 + 文件命名规范（综合整理）

## 一、CCB 文件命名规范

### 1.1 命名格式

```
项目名_类型_具体名称
```

| 类型 | 命名格式 | 根节点类型 | 示例 |
|------|---------|-----------|------|
| 弹窗 | 项目名_弹窗_弹窗名 | CCLayer | FP_订单模块_弹窗_订单超时 |
| 界面 | 项目名_界面_界面名 | CCLayer | CM_主游戏模块_界面_游戏界面 |
| 浮层 | 项目名_浮层_浮层名 | CCLayer | M8P_体力模块_浮层_体力不足 |
| 全屏反馈 | 项目名_全屏反馈_反馈描述 | CCLayer | FP_全屏反馈_关卡完成 |
| 教程界面 | 项目名_教程界面_教程描述 | CCLayer | FP_教程界面_首次引导 |
| 活动界面 | 项目名_活动界面 | CCLayer | FP_活动界面 |
| 游戏界面 | 项目名_游戏界面 | CCLayer | CM_游戏界面 |
| 活动入口 | 项目名_活动入口 | CCNode | FP_活动入口 |
| 特效 | 项目名_特效_特效描述 | CCNode | FP_特效_金币飞行 |
| 音效接口 | 项目名_音效接口_音效描述 | CCNode | FP_音效接口_背景音乐 |
| 资源栏 | 项目名_资源栏 | CCNode | FP_资源栏 |
| 通用子级 | 项目名_子ccb描述 | CCNode | FP_奖励物展示 |
| 非通用子级 | 项目名_子级ccb描述 | CCNode | FP_子级订单卡片 |
| 微级 | 项目名_子级ccb名_微级描述 | CCNode | FP_子级订单卡片_微级星标 |

### 1.2 命名禁忌

- 不要重复描述：正确 `弹珠活动_弹窗_活动开始`，错误 `弹珠活动_弹窗_活动开始弹窗`
- 禁止使用：括号 `()`、空格、`#`、`*`、`=`、拼音
- rebolt 文件命名自动生成，与对应 ccb 一致

## 二、节点命名规范

### 2.1 按节点类型的标准命名

| 节点类型 | 标准命名 | 说明 |
|---------|---------|------|
| CCNode（容器） | 背景组、安全区域、总组、按钮组、信息栏、标题栏、弹窗总组、内容区域、顶部UI栏、底部按钮组、光效组、弹窗底板组 | 分组容器，只调位置不设大小（总组除外） |
| REDNodeButton | 全屏点击屏蔽、全屏防穿透按钮、全屏退出按钮、关闭按钮、按钮_确认、按钮_取消 | 可点击按钮 |
| CCLayerColor | 黑色遮罩 | 纯黑半透明遮罩层 |
| RedSafeAreaLayer | 安全区域 | 适配安全区域 |
| CCScale9Sprite | 弹窗底板、气泡框、底板 | 九宫格拉伸图片 |
| CCSprite | 背景图、插图、图标、标题底板 | 普通图片节点 |
| CCRedLabel / CCLabelPlus | 标题文本、提醒文本、描述文本、标题文本_描边 | 文本节点 |
| REDFile | 按钮组、金币栏、生命栏 | 引用外部 .red 文件 |

### 2.2 定位点命名

空 CCNode 作为程序挂载锚点，命名格式：`xxx定位点`

| 定位点示例 | 用途 |
|-----------|------|
| banner定位点 | 广告位挂载 |
| 弹窗层定位点 | 弹窗挂载 |
| 角色定位点_单人_任意 | 角色挂载 |
| 节点收集定位点 | 收集物挂载 |

### 2.3 程序相关节点标记（颜色标记）

| 颜色 | 用途 | 限制 |
|------|------|------|
| 红色 | 程序调用 | 节点不能 K 时间线帧 |
| 黄色 | 程序显隐 | 节点不能 K 可见帧 |
| 蓝色 | 程序赋值 | 文本节点不能 K 文本内容帧 |

### 2.4 图片节点规范

- 图片节点命名需与图片文件名有对应关系
- 禁止出现「的副本」字段
- 图片禁止被当作容器节点使用（不能在图片下嵌套子节点）

## 三、层级结构标准模式

### 3.1 界面（CCLayer）标准结构

```
CCLayer (根节点, 100%x100%)
├─ 背景组 (CCNode)                         ← 不在安全区域内
│   ├─ 全屏点击屏蔽 (REDNodeButton, 50%/50%, 100%x100%)
│   └─ 背景图 (CCSprite / CCLayerColor)
├─ 安全区域 (RedSafeAreaLayer)
│   └─ 总组 (CCNode, 50%/50%, 100%/100%)
│       ├─ 顶部UI栏 (CCNode)
│       │   ├─ 资源栏 (REDFile 引用)
│       │   └─ 按钮组 (CCNode)
│       └─ 内容区域 (CCNode)
├─ banner定位点 (CCNode)                    ← 广告位
└─ 弹窗层定位点 (CCNode)                    ← 弹窗挂载
```

### 3.2 弹窗标准结构

```
CCLayer (根节点)
├─ 总组 (CCNode, visible=false)              ← 初始隐藏，由动画控制显示
│   ├─ 全屏防穿透按钮 (REDNodeButton, 50%/50%, 100%x100%)
│   ├─ 黑色遮罩 (CCLayerColor, 50%/50%, 100%x100%, opacity=170~204)
│   └─ 安全区域 (RedSafeAreaLayer)
│       └─ 弹窗总组 (CCNode)
│           ├─ 弹窗底板 (CCScale9Sprite)
│           ├─ 标题栏 (CCNode)
│           │   ├─ 标题底板 (CCSprite)
│           │   ├─ 标题文本_描边 (CCRedLabel)     ← 底层描边/阴影
│           │   ├─ 标题文本 (CCRedLabel)           ← 上层主文本
│           │   └─ 关闭按钮 (REDNodeButton)
│           ├─ 内容区域 (CCNode)
│           └─ 按钮组 (CCNode)
│               ├─ 按钮_确认 (REDNodeButton)
│               └─ 按钮_取消 (REDNodeButton)
└─ 浮层定位层 (CCNode)
```

### 3.3 浮层标准结构

```
CCLayer (根节点)
├─ 背景组 (CCNode)
│   ├─ 全屏点击层 (REDNodeButton)
│   └─ 背景图 (CCSprite)                     ← 全屏背景图（非半透明遮罩）
├─ 总组 (CCNode)
│   └─ 信息组 / 结算组
└─ 底部按钮组 (CCNode)
```

**弹窗 vs 浮层区别：** 弹窗用半透明黑色遮罩 + 弹框，浮层用完整背景图覆盖全屏、无弹框。

## 四、总组规范

- 所有 ccb 文件搭建前必须建立总组
- 总组位置：`(50%, 50%)`，尺寸：`(100%, 100%)`
- 弹窗/界面总组尺寸根据实际情况调整：
  - 控件不需跟随分辨率变化 → 尺寸用绝对值（设计分辨率 1080x2400）
  - 控件需跟随分辨率变化 → 尺寸用百分比
- 除总组外其他 CCNode 节点：只调整位置、不设大小

---

## 五、背景组规范

- 背景组不包含在安全区域节点内（独立存在）
- 组内标准结构：
  - 黑色遮罩层：位置 `(50%,50%)` 尺寸 `(100%,100%)` 纯黑 透明度 80%（opacity=204）
  - 全屏防穿透按钮：位置 `(50%,50%)` 尺寸 `(100%,100%)`

## 六、防穿透按钮规范

| 场景 | 位置/尺寸设置 |
|------|-------------|
| 背景组的全屏防穿透按钮 | 位置 `(50%,50%)` 尺寸 `(100%,100%)` |
| 弹窗底板防穿透按钮 | 底板 node 尺寸为 `(0,0)`，按钮尺寸用绝对值 |

## 七、视觉技巧

### 7.1 文本描边双层法

两个 CCRedLabel 垂直偏移 2px 叠加：

```
标题文本_描边 (CCRedLabel, 描边字体, 偏下2px)   ← 底层描边/阴影
标题文本 (CCRedLabel, 纯白字体)                  ← 上层主文本
```

### 7.2 左右镜像拼合

底板和装饰元素只出一半贴图，通过 `scaleX=-1` 镜像拼合，节省 50% 贴图空间：

```
弹窗底板_左 (CCSprite)                  ← 原图
弹窗底板_右 (CCSprite, scaleX=-1)       ← 镜像
```

### 7.3 黑色遮罩透明度

| 场景 | opacity 值 | 百分比 |
|------|-----------|--------|
| 弹窗标准 | 170~204 | 67%~80% |
| 体力弹窗 | 180 | 70% |
| 订单超时弹窗 | 204 | 80% |

### 7.4 按钮音效标准配置

- 关闭按钮：`wiseOnTouchUpInside` = `"UI_popup_close"` (res_common.bnk)
- 普通按钮：`wiseOnTouchUpInside` = `"UI_btn"` (res_common.bnk)
- 按下缩放：`scaleRatio = 0.9`（默认开启）

## 八、时间线命名规范

### 8.1 命名格式

| 命名格式 | 含义 | 时长范围 |
|---------|------|---------|
| 常态 | 默认显示状态 | 0.03s（瞬时） |
| 常态_xxx | 条件性默认状态 | 0.03s |
| 动画_进入 / 进入动画 | 弹窗/界面进入 | 0.33s ~ 2.0s |
| 动画_退出 / 退出动画 | 弹窗/界面退出 | 0.03s ~ 0.33s |
| 动画_步骤N_xxx | 分步引导动画 | 1.0s ~ 2.5s |
| 动画_xxx反馈 | 反馈动画 | 0.3s ~ 1.0s |
| 循环动画_xxx | 循环播放的动画 | 视具体需求 |

### 8.2 命名禁忌

禁止使用：括号 `()`、空格、`#`、`*`、`=`、拼音

### 8.3 弹窗进入动画标准模式

```
t=0:         总组 visible=true
t=0~0.133s:  黑色遮罩 opacity 0→204（线性淡入）
t=0~0.5s:    弹窗总组 scale 0.6→1.0 + opacity 0→255（ElasticOut 弹性）
t=0~0.7s:    子内容延迟出现（scale 0→1）
```

### 8.4 退出动画标准模式

- 时长极短（0.03s~0.07s）
- 直接将 opacity 和 scale 清零（瞬间消失）

### 8.5 chain 规则

- `chain: -1` = 不自动链式播放（默认）
- `chain: N` = 播完后自动播第 N 条时间线（用于循环动画，指向自身）

### 8.6 注意事项

- 换图后需切换时间线检查所有分辨率的适配效果
- 循环动画时间线：第一帧和最后一帧的大小位置必须相同

## 十、多工程分层架构

核心原则：game = "壳"（UI/流程），board = "核"（核心玩法）

| 工程类型 | 前缀 | 职责 | 示例 |
|---------|------|------|------|
| common | res_模板公用 | 跨项目复用的通用组件（C1~C5系列）、字体、图集 | res_flower_common |
| proj | M8P_ | 项目特有的主页、商店、设置等 UI 模块 | res_flower_proj |
| game | OSG_ | 游戏上层 UI、订单系统、弹窗、角色表现 | res_foodpuzzle_game |
| board | M8G_ | 棋盘核心玩法、元素节点、道具特效 | res_foodpuzzle_board |
| engine | 项目缩写 | 游戏引擎逻辑（较小型项目） | resmathgameengine |
