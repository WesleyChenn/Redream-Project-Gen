## 1. 进度条生成 (S6 5.2 包装类型 = 进度条 时)

进度条必须**手搓双层 RECT + 三层结构**, **不用 component_ref** (FRAME 包装与引擎不兼容)。

### 三层结构

```text
组_xxx (FRAME, 不可点) 或 按钮_xxx (FRAME, 可点, 来自 S6 5.2 用户答可点)   ← 外层容器
├── 组_进度_XXX (FRAME)              ← 包装层 (含"进度"二字)
│   ├── 底板_XXX (RECTANGLE)         ← Z 序低, XXX 不带"进度"
│   └── 进度条_XXX (RECTANGLE)       ← Z 序高, XXX 不带"进度"
├── (可选) 文本_xxx (TEXT)            ← 外层容器的兄弟, 不放进 组_进度_ 内
└── (可选) 图标_xxx 或 component_ref  ← 外层容器的兄弟
```

### 命名规范 — "进度"二字只在外层包装

**三层的 XXX 必须完全一致**, "进度"二字**只出现在外层包装 FRAME `组_进度_XXX`**, 内部 `底板_XXX` 和 `进度条_XXX` 的 XXX 保持简洁不带"进度":

- ✅ `组_进度_经验` + `底板_经验` + `进度条_经验`
- ✅ `组_进度_活动` + `底板_活动` + `进度条_活动`
- ❌ `组_进度_经验` + `底板_经验进度` + `进度条_经验进度` (内部冗余)
- ❌ `组_进度_经验` + `底板_活动` (三层 XXX 不一致)

**XXX 同屏唯一规则**: 同一父 FRAME 内 XXX 唯一; 不同父 FRAME 内 XXX 可同名 (引擎按路径识别)。
- 例: 同屏 `按钮_活动` 内的 `底板_活动` 跟 `组_进度_活动` 内的 `底板_活动` — OK (父不同)

### 方向后缀 (99% 横向 lr 默认不加)

| 后缀 | 方向 |
|---|---|
| (无) | `horizontal_lr` 水平左→右 (默认) |
| `_rl` | `horizontal_rl` 水平右→左 |
| `_bt` | `vertical_bt` 垂直下→上 |
| `_tb` | `vertical_tb` 垂直上→下 |

含方向后缀时**三层都要带**, 不允许只一层带后缀: `组_进度_xxx_tb` + `底板_xxx_tb` + `进度条_xxx_tb`。

环形进度条**暂不支持** (引擎未实现)。

### Z 序铁律

`children` 数组里 `进度条_XXX` 的 index **必须 > `底板_XXX` 的 index** (进度条覆盖在底板之上)。

### 尺寸规范 — 内缩 + 中心对齐

`进度条_XXX` RECT **必须小于** `底板_XXX` RECT, 内缩中心对齐 (进度条表达"100% 满时填充内容的视觉区域", 不含底板边框):

| 底板尺寸范围 | 横向内缩 (每边) | 纵向内缩 (每边) |
|---|---|---|
| 大 (w≥200, h≥80) | 10px | 10px |
| 中 (100≤w<200, 50≤h<80) | 8px | 5px |
| 小 (w<100, h<50) | 5px | 3-5px |

**中心对齐铁律**:
```
进度条 中心 = 底板 中心
进度条 x + 进度条 w/2 = 底板 x + 底板 w/2  (横向)
进度条 y + 进度条 h/2 = 底板 y + 底板 h/2  (纵向)
```

包装 FRAME 尺寸: `组_进度_XXX` 的 w/h = `底板_XXX` 的 w/h (包装层视觉上和底板一样大, 只是分组用)。

⛔ **禁止**: 进度条 = 底板 同尺寸同位置 (看不到底板边框, 失去视觉区分)
⛔ **禁止**: 进度条偏离底板中心 (左对齐 / 右对齐 / 顶对齐)

### 进度条本体永远画 100% 满模板

视觉上画满, 引擎运行时按 percentage 切割 (CCProgressTimer)。**不写 `percentage` 字段或 `_p<数字>` 后缀**, 百分比完全由引擎运行时根据玩家数据决定。

### 🔴 进度条本体永远是**一整根**, 不分段 (即使条上有节点 / icon)

不管进度条上是否压有节点 icon / 里程碑节点 / 中段图标, Figma 侧的 `进度条_XXX` RECT **永远只画一整根 100% 满**, **不要按节点位置拆成多段 RECT**。引擎运行时按 percentage 切割整根, 节点 icon 在视觉上自然显示为"已过/未过"。

| ❌ 错 | ✅ 对 |
|---|---|
| 4 节点的进度条画 3 段 `进度条_段1 / 段2 / 段3` RECT | 1 根 `进度条_XXX` RECT (100% 满), 节点 icon 叠在条上方 |
| 给每段进度条分别设 `visible` 切换"已过/未过" | 引擎运行时切割整根, 视觉上 icon 自然分"已过/未过" |
| 节点之间的"短进度段" 抽 Component 多 Variants | 短进度段也是进度条本体一部分, 不抽; 节点 icon 才抽 Component |

原因:
- 多节点进度条的"节点状态"由节点 icon 自身的 Component Variants 表达 (已完成/未完成/当前)
- 进度条本体的"填充量"由引擎运行时的 percentage 决定, 跟节点位置无关 — 引擎切到哪个 x 位置就是当前进度
- 拆成多段 = 设计阶段就把"进度状态" 硬编码, 引擎无法在运行时按数据动态调整

例: RoyalPass 类型条 (4 个节点)
```
Figma: [ 整根 进度条_RoyalPass RECT (100% 满) ] + [节点1 INSTANCE / 节点2 / 节点3 / 节点4]
引擎运行时: progress=0.6 → 切割整根到 60% 处 → 节点1/2 视觉上"已过", 节点3/4 "未过"
```

## 2. 角标包装规则做法 B (基于 S6 5.3 标记)

S6 5.3 已识别角标父本类型, S7 执行:

### 父本是手搓按钮

角标作为按钮 FRAME 的 children:
```json
{ "type": "FRAME", "name": "按钮_活动紫罐", "children": [
    { "type": "RECTANGLE", "name": "底板_活动紫罐", ... },
    { "type": "RECTANGLE", "name": "图片_紫罐", ... },
    { "type": "FRAME", "name": "角标_感叹号", ... }   // 装饰 children
]}
```

### 父本是 `component_ref` (做法 B)

**外层包一个 `按钮_xxx` FRAME**, 把 component_ref + 角标都作为该 FRAME 的 children:

```json
{ "type": "FRAME", "name": "按钮_活动紫罐", "children": [
    { "component_ref": "椭圆按钮_活动", "name": "活动_紫罐", ... },   // 主体, S8 处理细节
    { "type": "FRAME", "name": "角标_感叹号", ... }                   // 装饰
]}
```

外层按钮 FRAME 不需要独立 `底板_xxx` RECT (视觉依赖 component_ref 提供)。

### 父本是非按钮 (纯展示)

角标作为父组件 FRAME 的 children, 跟主元素同级。

## 3. `component_ref` 节点写法 (S7 占位, S8 处理细节)

S7 阶段命中旧组件库的组团, 用 `component_ref` 占位写法:

```json
{ "component_ref": "椭圆按钮_活动",
  "name": "活动_紫罐",
  "x": 100, "y": 200, "w": 163, "h": 213 }
```

| 字段规则 | 说明 |
|---|---|
| `component_ref` | **独立 key**, 不是 `"type": "component_ref"` |
| 不写 `layoutSizingHorizontal` / `layoutSizingVertical` | 由组件库自维护 |
| **必须等比缩放** | 输出 w/h = 截图量测 × scale, **不使用组件库原始尺寸** |
| 缩放比计算 | `scale = 目标h / 原始h`, 非正方形以高度为基准等比推算宽度 |
| 组件库内部结构 | 由 Figma 维护, Claude 不检查也不重写库内节点 |
| fill 规则 | 不受手搓节点 fill 省略规则约束 (组件库内部 fill 由 Figma 维护) |

具体处理 (尺寸缩放对齐 / S8 预检 / Push to main component 同步) 留给 **S8 少量组件库引用**。S7 阶段只是占位写法。
