## 这一步做什么

基于 S2 列出的页面元素清单, 识别元素之间的**布局关系**:
1. 谁包含谁 (父子关系)
2. **组团化** — 把"看起来是一组"的元素包到一个空 FRAME 里
3. 同级元素之间是 NONE / HORIZONTAL AL / VERTICAL AL
4. AL 容器的对齐意图 (MIN / CENTER / SPACE_BETWEEN)
5. 屏幕顶层大区的 y 坐标分布 (贴顶 / 贴底 / 中间弹性)
6. 元素相对父容器的 constraints (缩放约束)

**这一步只识别"怎么排"**, 不关心:
- 这是不是按钮 (S6 pattern 命中)
- 是否匹配已知 component (S6)
- 元素之间的交互 (S4)
- 写 JSON (S7-S9)

## 该步做的事

### 1. 包含关系判定 (父子)

- **包含判定**: 文字/图标边界**完全落在**色块边界内 → 该色块作为父容器
- **不在内**: 两个元素只是相邻不重叠, 不构成父子关系
- 父子关系是后续 S7 把装饰挂进按钮 children 的依据 (S3 只识别, S7 才挂)

注: 包含判定是"父已存在的色块/底板, 识别谁是它的子"。如果父不存在 (多个元素是一组但没有共同的色块底板包住它们) → 走下一步**组团化**。

### 2. 组团化 (空 FRAME 包装) 🔴 关键步骤

在判 layout type 之前必须先**识别组团** — 把"看起来是一组"的元素**包装到一个空 FRAME** (无 fill, 透明) 里。原因:

- **S6 基于组团识别 pattern 命中** — 组团是 pattern 匹配的最小单位
- **S7 基于组团抽 Component** — 组团 → Component 是直接映射
- **视觉一致性** — 一组元素一起缩放/移动/动画, 不会散开
- **连接 S2 #6 相似元素数量双重核查** — S2 数对的"那组 N 项", 在 S3 必须被组团化, 否则 S6/S7 无法用

#### 组团判定的三个标准 (满足任一即组团)

| 标准 | 判定方法 | 例子 |
|---|---|---|
| **结构相似** | 几个元素的子结构高度重复 (子节点类型/数量/层次一致) | 列表里 8 行 (每行都是头像 + 名字 + 分数) → 8 行一组 |
| **成排 / 成列** | 同 Y 中心对齐 (成排) 或 同 X 中心对齐 (成列) | 顶部 HUD 的 生命栏 / 金币栏 / 钻石栏 同 Y → 一组 |
| **语义化功能成组** | 视觉位置相邻 + 语义是一个功能单元 | 标题栏 (返回 + 标题 + 设置) → 一组 |

#### 组团必须放在空 FRAME 里 (无 fill, 透明)

```text
未组团化 (错):                  组团化后 (对):
顶部 6 个元素散在屏幕顶层        顶部 HUD (空 FRAME, 父, 透明无 fill)
- 生命栏                         ├─ 生命栏
- 金币栏                         ├─ 金币栏
- 钻石栏                         ├─ 钻石栏
- 弹性                           ├─ 弹性
- 设置按钮                       └─ 设置按钮
```

空 FRAME 的特征:
- `type: FRAME`
- **无 fill** (透明, 不渲染本身)
- 作为父容器, 承载布局 (layoutMode + AL 对齐)
- 子节点通过它统一缩放/移动

#### 组团嵌套与并列

组团**跨层级嵌套**, 但**同层级并列不嵌套**:

```text
跨层级 (嵌套, 允许):
列表 (大组团, 空 FRAME)
└─ 列表行 ×8 (子组团, 每行一个空 FRAME)
    └─ 头像 + 名字 + 分数 (行内子组团, 也是空 FRAME)

同层级 (并列, 不嵌套):
顶部 HUD (空 FRAME) ┃ 进度条区 (空 FRAME) ┃ 中间地图 ┃ 底部导航 (空 FRAME)
   ↑ 4 个组团同层并列, 禁止"把进度条区塞进顶部 HUD 里"
```

S3 识别出的嵌套结构, S7 抽 Component 时直接对应嵌套 Component 关系 (对应 S0 第 13 节嵌套 CCB 三层模型)。

#### 组团化递归到最小粒度 🔴

组团化**不止"大→子两层"**, 而是**一直递归到最小粒度** — 直到一个空 FRAME 里只剩"主元素 + 依附装饰":

| 层级 | 内容 | 例子 |
|---|---|---|
| 大组团 | 跨多功能的区域 | 顶部 HUD / 列表 / 标题栏 |
| 子组团 | 单一功能单元 | 生命栏 / 列表行 / 导航项 |
| **最小组团 (组件级)** | **主元素 (底板/icon/文字 1-N 个) + 依附装饰 (角标/徽章/底标 0-N 个)** | 生命栏 = icon_心 + 数字_5 + 角标_! |

完整嵌套示例:

```text
顶部 HUD (大组团 FRAME, 空)
├── 生命栏 (子组团 FRAME, 空)   ← 内部是"主元素+装饰"
│   ├── icon_心 (主元素)
│   ├── 数字_5 (主元素)
│   └── 角标_! (依附装饰)
├── 金币栏 (子组团 FRAME, 空)
│   ├── icon_金币 (主元素)
│   └── 数字_860 (主元素)
└── 设置按钮 (单独组件 FRAME, 空)
    ├── icon_设置 (主元素)
    └── 角标_红点 (依附装饰)
```

**为什么要递归到组件级**:
- **S6 识别 pattern 命中**: 按"最小组团"匹配 (例: "icon + 数字 + 角标" 命中 memory 里 "横排徽章" pattern)
- **S7 抽 Component**: 每个最小组团 → 一个 Component (一对一映射)
- **角标依附正确**: 装饰角标在组件 FRAME 内, 跟主元素同级, 一起移动/缩放/动画

⛔ **禁止**: 把主元素和角标平铺在大组团下, 跳过组件级 FRAME 包装 — 会导致角标和主元素不绑定, S6 pattern 匹配失败, S7 抽 Component 错配

#### 角标父本识别 (允许视觉溢出) 🔴

角标 / 徽章 / 底标这类装饰元素, 必须识别它**依附于哪个主元素 (或主元素组)**, **即使坐标视觉溢出**父本边界 (负坐标 / 超出 w/h, 见 S0 第 14 节触控范围铁律):

| 视觉特征 | 判定 |
|---|---|
| 角标 y=-15 (顶部溢出 15px), 视觉上贴在某主元素顶部 | 父本 = 该主元素 |
| 角标 x = 父本w + 5 (右侧溢出 5px), 视觉上贴在某主元素右上 | 父本 = 该主元素 |
| 角标坐标完全在父本内 | 父本 = 该主元素 (普通包含, 走 #1) |

**核心判定规则**: 看角标**视觉贴附**在哪个主元素 (而**不是**用"坐标完全包含" 判断) — 那个主元素就是角标的父本。

识别后, 角标在 S3 表 C 里**作为该父本所在的组件 FRAME 的子元素**, 跟主元素同级:

```text
某组件 FRAME (空)
├── 主元素 1 (底板)
├── 主元素 2 (icon)
├── 主元素 3 (文字)
└── 角标 (依附装饰, 视觉可溢出组件 FRAME 边界)
```

> S7 (生成阶段) 才决定这个"组件 FRAME"最终是变成 `按钮_xxx` FRAME (REDNodeButton 触控层, 角标走"做法 B"包装) 还是 `组_xxx` FRAME (纯展示)。S3 阶段只识别"角标依附哪个主元素", 不下"是不是按钮"的结论。

#### 组团化的禁止

⛔ **禁止**: 把组团里的元素**直接平铺**在屏幕顶层 (扁平结构), 必须先组团化 + 空 FRAME 包装
⛔ **禁止**: 用有 fill 的 FRAME 当组团容器 — 组团容器必须**无 fill 透明**, 否则 S6/S7 会把它当作"视觉色块" 错算
⛔ **禁止**: 跳过 S2 数过的相似组团不组团化 — S2 #6 双重核查数过的"N 项", S3 必须组团化进同一个空 FRAME

### 3. 同级元素的 layout type 判定

组团化后, **组团内**的同级元素 + **组团之间**, 都要判 layout type:

- **NONE** (绝对定位): 元素位置不规律, 各有各的 x/y (典型: **地图区** / 自由布局)
- **HORIZONTAL** (水平 AL): 同级元素 **Y 中心对齐** → 横排
- **VERTICAL** (垂直 AL): 同级元素 **X 中心对齐** → 竖排

判定方法: 量测所有同级元素的中心点, 看 Y 是否一致 / X 是否一致。

### 3.1 组团内 layout 单一化铁律 🔴 (来自 2026-05-14 用户教学)

#### 这一步在 S3 中的位置

```text
S3 整体流程:
  #1 包含关系判定 (父子)
  #2 组团化 (空 FRAME 包装) ──┐
                              │
  #3 layout type 判定 (单一组团内的 NONE/HORIZONTAL/VERTICAL) ──┐
                              │                                  │
  #3.1 (本节) layout 单一化铁律 ←──────────────────────────────┘
       └── 对每个 FRAME 跑识别+聚类算法
       └── 发现混合 → 触发 #2 再次拆 wrapper FRAME (反馈循环)
       └── 直到每个 FRAME 内部只剩一种 layout
                              │
  #4 y 坐标计算
  #5 AL 容器对齐意图 ←──── 此时每个 FRAME 已单一 layout, 才能填表 B
  #6 弹性缝隙
  #7 constraints
  #8 异构内容 layout 分别判定
```

**关键定位**: #3.1 是 **#2 组团化 + #3 layout 判定的反馈闭环** — 不只是 #3 的补充。 #3 给出每个 FRAME 的初步 layout, #3.1 检查这个 layout 是否单一, 不单一就回到 #2 拆 wrapper FRAME, 再重新 #3 判 layout, 反复直到收敛。 收敛后才能进 #5 填表 B 的 AL 对齐意图。

#### 核心铁律

一个 FRAME 内部, 子节点必须能用**单一一种 layout 描述** (NONE / HORIZONTAL / VERTICAL 三选一)。**禁止**在同一个 FRAME 内混合 HORIZONTAL + VERTICAL 关系。

#### 触发时机

#3 layout 判定给出"这个 FRAME 应该用 HORIZONTAL/VERTICAL/NONE" 之后, **每个 FRAME 都跑一次 #3.1 全流程验证**。 实际执行时序:
1. #2 组团化先把视频元素包成初始 FRAME
2. #3 给每个 FRAME 判初步 layout
3. **#3.1 验证 + 修正** (本节)
4. 全部 FRAME 都通过验证, 才进 #5 填表 B

#### 完整流程 (6 Step)

##### Step 1: 量测子节点

对当前 FRAME 的每个直接子节点, 拿到:
- 坐标 `x / y / w / h`
- 中心点 `cx = x + w/2, cy = y + h/2`

##### Step 2: 两两位置关系判定

对子节点任意两个 A、B, 判它们的关系。 容差按**父 FRAME 短边尺寸**分档查:

| 父 FRAME 短边 (min(w,h)) | 中心点容差 ε | 紧密距离判定 |
|---|---|---|
| `< 200 px` | ±3 | 距离 `< 同向元素尺寸 × 1.5` |
| `200 ~ 500 px` | ±5 | 同上 |
| `> 500 px` | ±10 | 同上 |

> "同向元素尺寸": 竖排看元素自身 `height`, 横排看 `width` (跟距离测量方向一致)

判定规则:

| 判定条件 | 关系标记 |
|---|---|
| `|cx_A - cx_B| < ε` 且 `cy_A ≠ cy_B` | **竖排** (同列, 上下) |
| `|cy_A - cy_B| < ε` 且 `cx_A ≠ cx_B` | **横排** (同行, 左右) |
| 都不同 | **无对齐** (NONE 候选) |

输出: 一张 N×N 关系矩阵 (N 是子节点数)

##### Step 3: 强关系聚类 — 聚成"原子组"

把"必须聚在一起"的子节点聚成原子组, 每个原子组内部 layout 单一。

**聚类有 2 个并列依据, 任一命中即强制聚类**:

###### 依据 A: 位置强关系

- 距离 < 同向尺寸 1.5 倍 (紧密) + 中心坐标完全一致 (容差 ±10) → 加入同一个原子组
- 一个原子组只允许**一种位置关系** (竖排原子组 / 横排原子组)
- **传递性**: 若 A-B 强关系 + B-C 强关系, 则 A-B-C 同一原子组

> 例 (RoyalPass 节点行): 心 (cx=200, cy=100) + "30m" (cx=200, cy=300) → cx 一致, 距离 200 < 心高度 1.5× → **聚成"左奖励原子组" (竖排)**

###### 依据 B: 语义共存 (5 条视觉信号, 命中任一即聚类) 🔴

**不依赖主观判定**。 看 5 条可观察信号, 命中任一即"语义共存", 强制聚类:

| # | 信号 | 例子 |
|---|---|---|
| ① | **视觉镜像** | 左花纹 ↔ 右花纹镜像 / 左箭头 ↔ 右箭头 |
| ② | **视觉对称** | 进度条左 icon ↔ 右 icon / 左端节点 ↔ 右端节点 |
| ③ | **边框性质** (多元素组成闭合框) | 上线 + 下线 / 左线 + 右线 / 四角装饰 ×4 |
| ④ | **跨多实例同步现身** | 视频里 N 个元素永远一起出现 (S2 数过同步现身次数) |
| ⑤ | **装饰依附** (无独立交互/语义) | 角标依附按钮 / 徽章依附 icon / 底标依附按钮 |

- 任一信号命中 → 强制聚类成原子组, **即使两元素之间没有位置强关系** (距离远 / 中心不对齐)
- 任一信号命中 → **先聚语义共存对**, 即使两元素分别跟其他元素有位置关系
- 不命中任一信号 = 不算语义共存, 走依据 A 处理

> 例 (RoyalPass 节点行 黄色边框): 上下 2 根黄线 → 信号 ③ (边框性质) 命中 → 强制聚成 **黄框原子组**, 不参与外部横排。

###### 两类依据冲突时

- 依据 A vs 依据 B 冲突 → **依据 B 优先**
- 原因: 语义共存是设计意图 (语义/作用一致), 位置关系只是视觉摆放服务于语义

###### Step 3 输出

聚出 K 个原子组:
- 每个原子组对应一个潜在 wrapper FRAME
- 原子组内部位置关系单一 (竖排 / 横排 / NONE)
- wrapper 整体当作一个节点参与下一步判定

##### Step 4: 原子组之间关系判定

把每个原子组**当作一个整体** (用 bounding box 中心点), 两两判定:

| 全部原子组之间是 | 父 FRAME layout |
|---|---|
| 都是**横排关系** | 外层 **HORIZONTAL** AL |
| 都是**竖排关系** | 外层 **VERTICAL** AL |
| 关系**不统一** (既有横排又有竖排) | 外层 **NONE** (不打 AL) |
| 全部独立 (无对齐) | 外层 **NONE** |

##### Step 5: 覆盖度判定 + 处理方式选择

**覆盖度公式**: `覆盖度 = union(bbox_i) / parent_area` (union, 不重复计重叠区)

根据覆盖度查表:

| 覆盖度 | 类别 | 处理 |
|---|---|---|
| **≥ 80%** | **A. 主流混合** | 每个原子组**包成独立 wrapper FRAME**, 父 FRAME 按 Step 4 结果定 layout |
| **30% ~ 80%** | **灰区** | **主动问用户**: "这几个原子组是否要包成独立 wrapper FRAME?" 拿到回答再继续 |
| **< 30%** | **B. 局部混合** | **只把局部混合包成 1 个 wrapper FRAME**, 其余保持平铺, 父 FRAME 打全局 layout |
| **(独立)** | **C. 全单一** — 全部子节点已是同一原子组 / 全部子节点关系单一 | 不需要拆, 父 FRAME 直接打对应 AL (Step 4 给出) |

##### Step 6: 递归

对每个新包出来的 wrapper FRAME, **从 Step 1 重新跑**, 直到每个 FRAME 内部都通过 #3.1 验证 (Step 5 进 C 类)。

##### 通用兜底规则 ⛔

任何 Step 1-5 进不下去 (无法判定关系 / 聚类失败 / 不收敛), **父 FRAME 强制 NONE, 所有子节点平铺** (绝对坐标定位)。

具体触发场景:

| 场景 | 兜底处理 |
|---|---|
| FRAME 子节点 ≤ 1 | 直接 NONE, 跳过 Step 1-6 |
| FRAME 子节点完全重叠 (cx + cy 都相同) | 父 NONE, 子节点绝对定位 |
| 递归跑 3 轮还混合 | 当前层强制 NONE, 不再拆 |
| 一个元素同时满足依据 A + 依据 B 跟不同元素 | **依据 B 优先** (语义共存优先), 进 B 组 |
| Step 4 原子组关系完全无规则 (既非全横排也非全竖排) | 父 NONE, 各原子组独立 wrapper |

---

#### 流程图

```text
当前 FRAME (N 个子节点)
    │
    ▼
Step 1: 量测每个子节点 cx/cy
    │
    ▼
Step 2: 两两关系矩阵 (竖排/横排/无对齐)
    │
    ▼
Step 3: 聚类成 K 个原子组
   ┌── 依据 A (位置强关系)
   └── 依据 B (语义共存) ← B 优先
    │
    ▼
Step 4: 原子组之间关系 → 决定父 layout 候选
    │
    ▼
Step 5: 覆盖度判定 → 选 A/B/C 处理
   ┌── A: 全部原子组包独立 wrapper FRAME
   ├── B: 局部原子组包 1 个 wrapper FRAME, 其余平铺
   └── C: 不拆, 父 FRAME 直接定 layout (跳过 Step 6)
    │
    ▼
Step 6: 对每个新 wrapper FRAME, 回 Step 1 递归
    │
    ▼
收敛: 每个 FRAME 内部只剩一种 layout ✓
```

#### 实操判定快表

| 子节点构成 | 父 FRAME layout | 子 FRAME 怎么包 |
|---|---|---|
| 全部同 Y 横排, 各自宽度不同 | HORIZONTAL | 不需要拆 (C 类) |
| 全部同 X 竖排 | VERTICAL | 不需要拆 (C 类) |
| N 个"竖排原子组" 之间横排 (例: RoyalPass 行) | NONE 或 HORIZONTAL | 每个竖排原子组独立 wrapper FRAME (A 类) |
| 2 个"横排原子组" 之间竖排 (例: 卡片含上行标题+下行按钮) | VERTICAL | 每行原子组独立 wrapper FRAME (A 类) |
| 局部 2 个元素竖排, 其余横排 | HORIZONTAL (外层) | 局部 2 个竖排包 wrapper, 其余平铺 (B 类) |
| **N 个元素语义共存, 单独无意义** (黄框 / 进度条端点对) | 看 wrapper 跟其他子组的关系定 | **强制**包成 wrapper FRAME, 内部按位置定 layout |
| 完全无规则 (地图区) | NONE | 不需要拆 (C 类) |

#### 跟 S3 其他步骤的衔接

- **跟 #2 组团化**: #3.1 触发的 wrapper FRAME 也是 S3 表 C "组团结构"的一部分 — 即 #2 的产物会被 #3.1 进一步细分。最终表 C 是 #2 + #3.1 共同产出。
- **跟 #5 AL 对齐意图**: #3.1 收敛后, 每个 FRAME 已单一 layout, #5 才能为每个 AL 容器填 `primaryAxisAlignItems` 等对齐意图到表 B。 #3.1 没收敛就填表 B = 错误。
- **跟 #7 constraints**: #3.1 拆出的 wrapper FRAME 如果是 NONE 父容器, 内部子节点写 constraints; 如果是 AL 父容器, 不写 constraints (per #7)。
- **跟 S6 语义共存 + 角标识别**: #3.1 依据 B 的"语义共存" 跟 #2 "角标父本识别" 衔接 — 角标依附主元素也是一种语义共存 (角标单独无意义, 必须依附主元素)。 二者结合用。

#### 完整例: RoyalPass 节点行

> 用户原话: "内部 FRAME 有多种布局方式的外侧 FRAME 不再布局, 更外侧才可以布局"

一行包含: 左奖励气泡 (心 icon + "30m" 文本竖排) + 中间黄色框 (2 根上下线竖排) + 右奖励气泡 (大炮 icon + "x2" 文本竖排) + 整行三个组件之间是横向关系。

**Step 1-2** (量测 + 关系矩阵): 心-30m 同 cx 竖排, 黄线1-黄线2 同 cx 竖排, 大炮-x2 同 cx 竖排; 跨子组之间是横排关系。

**Step 3** (聚类): 3 个原子组
- 心+30m (位置强关系 + 语义都是"奖励数量信息")
- 上线+下线 (语义共存: 黄色边框装饰, 单根无意义)
- 大炮+x2 (位置强关系 + 语义都是"奖励数量信息")

**Step 4** (原子组之间): 3 组中心 cy 接近 → 横排关系

**Step 5** (覆盖度): A 类 — 3 个原子组覆盖父 FRAME 80%+ → 各包独立 wrapper FRAME

**Step 6** (递归): 每个 wrapper 内部已单一 (竖排 2 元素 → VERTICAL AL), 不再拆

❌ **错** (跨混合关系强行打 AL):
```text
组_行 (HORIZONTAL AL)  ← 错: 整行打 AL, 把气泡里的竖排关系一刀切
├── 心 icon
├── "30m" 文本
├── 黄线1
├── 黄线2
├── 大炮 icon
└── "x2" 文本
```

✅ **对** (拆到 wrapper FRAME 各自统一 layout):
```text
组_行 (HORIZONTAL AL 或 NONE)  ← 外层关系单一 (3 个子 wrapper 横排) → 可以 AL
├── 组_左奖励气泡 (VERTICAL AL)  ← 心 + 30m 竖排
│   ├── 图标_心
│   └── 文本_30m
├── 角标_黄框 (VERTICAL AL)  ← 2 根线竖排, 语义共存强制聚类
│   ├── 线_上
│   └── 线_下
└── 组_右奖励气泡 (VERTICAL AL)  ← 大炮 + x2 竖排
    ├── 图标_大炮
    └── 文本_x2
```

每个 FRAME 内部都是单一 layout, 收敛 ✓

#### ⛔ 禁止

- ❌ 看见 N 个元素同 Y 就一刀切 HORIZONTAL — 必须先跑 Step 1-3 看子组关系是否统一
- ❌ 父 FRAME 打 AL 但子 FRAME 之间关系混合 → 视觉错位
- ❌ 用嵌套 AL 表达混合 (HORIZONTAL 父 + VERTICAL 子 + HORIZONTAL 孙) 当 AL 关系不通时 → 仍然要拆出 NONE 层 wrapper
- ❌ 跳过 Step 3 依据 B (语义共存) — 即使位置上 2 个元素分散, 语义共存仍强制聚类

### 4. y 坐标计算 (屏幕顶层大区, 强制顺序)

```
① 贴顶区域: 从 y=0 往下叠加
② 贴底区域: 从 y=2400 往上叠加
③ 中间内容区: h = 贴底起始y - 贴顶结束y
```

⛔ **禁止**: 从上往下一路叠加, 导致底部重叠

**验证**: 所有大区 h 加总 = 2400, 无重叠无空隙

### 5. AL 容器对齐意图 (查默认值表)

| 场景 | 典型容器 | primaryAxisAlignItems | 是否可用弹性缝隙 |
|---|---|---|---|
| 屏幕顶层 HUD / 标题栏 | 顶部 HUD / 标题栏 | MIN | 标题需居中时可用 ×2 |
| 屏幕底层导航 / 操作栏 | 底部导航 / 底部操作栏 | SPACE_BETWEEN | 否 |
| 外侧大组内容区 (非 HUD) | 底部按钮区 / 弹窗主内容 | **CENTER** | 否 |
| 响应式中间区内各行 | 滚动区内列表行 / 网格行 | MIN 或 SPACE_BETWEEN | 靠右单元素时可用 |
| 列表行内部 | 列表项_xxx | MIN + 内容区 FILL | 靠右单元素时可用 |
| 卡片底部行 (名称 + 按钮) | 底部行 | MIN | 是, 名称靠左按钮靠右 |
| 网格行 | 网格行_第N行 | SPACE_BETWEEN | 否 |
| 弹窗内容 VERTICAL | 内容区_弹窗 | MIN | 否 |

#### 小游戏专项规则 (高优先级, 覆盖上表)

- 顶部 HUD (生命值/金币栏) 以外的**所有外侧大组**, 默认 `CENTER`
- 响应式中间弹性区以外的固定高度容器, 优先 `CENTER`
- 底部双按钮区: 两个按钮作为整体居中, 用 `CENTER`, **不用弹性缝隙**

### 6. 弹性缝隙使用 (三条强制规则, S3 确认 / S7 执行)

#### 规则 1: 只能放在两个实体元素之间

```
❌ [按钮_皮肤, 按钮_Level3, 弹性缝隙]   ← 缝隙在末位, 禁止
✅ [按钮_返回, 弹性缝隙, 按钮_关闭]     ← 缝隙在中间
```

#### 规则 2: 使用前必须在表 B 说明意图

写明缝隙**左侧**是什么元素, **右侧**是什么元素, 实现什么视觉效果。
**未在表 B 确认, S7 不得写入弹性缝隙。**

#### 规则 3: 禁用场景与正确方案对照

| 场景 | ❌ 禁止 | ✅ 正确方案 |
|---|---|---|
| 多个元素整体居中 | 缝隙放首位或末位 | `primaryAxisAlignItems: CENTER` |
| 均匀分布 | 缝隙放元素之间 | `primaryAxisAlignItems: SPACE_BETWEEN` |
| 靠右单个元素 | — | 弹性缝隙放在该元素左侧 (此情况允许) |
| 标题居中 + 两端按钮 | — | 弹性缝隙 ×2, 分别放标题两侧 |

### 7. constraints 判定

constraints 描述子节点相对父容器的对齐/缩放关系。

| 场景 | constraints |
|---|---|
| 屏幕 `layers` 直接子节点 | ✅ **必须写** |
| `NONE` 父容器的子节点 | ✅ **必须写** |
| `HORIZONTAL` / `VERTICAL` 父容器的子节点 | ❌ **不写** (由 AL 接管) |

constraints 取值: `LEFT` / `RIGHT` / `CENTER` / `SCALE` (横向) + `TOP` / `BOTTOM` / `CENTER` / `SCALE` (纵向)

### 8. 异构内容 layout 分别判定

异构组 (如消息项 + 请求项混排) → **每种类型分别判 layout type**, 禁止套用统一 layout。

### 9. S3 执行顺序 checklist 🔴 (跟 #2 / #3.1 / #5 衔接)

S3 跑视频时按以下顺序执行, 后面步骤跳过前面已聚类的元素 (避免 #2 / #3.1 概念重叠重复跑):

```
□ Step 1: #2 标准 1+2 聚类 (结构相似 / 成排成列)         — 粗粒度组团化
□ Step 2: #2 标准 3 聚类 (语义化功能成组)                — 中粒度组团化
□ Step 3: #2 角标父本识别                                — 装饰挂主元素
□ Step 4: #3 给每个组团 layout 初判 (NONE / HORIZONTAL / VERTICAL)
□ Step 5: 对每个组团跑 #3.1 入口判定
    ├── 子节点 ≤ 1                       → 跳过, 强制 NONE (兜底)
    ├── 前 Step 1-3 已聚类的元素         → 跳过依据 B (避免重复)
    └── 否则                             → 进入 Step 6
□ Step 6: 跑 #3.1 Step 1-6 (量测 → 关系 → 聚类 → 父 layout → 覆盖度 → 递归)
□ Step 7: #4 y 坐标计算 + 算术闭环验证 (h 加总 = 2400)
□ Step 8: #5 填表 B (AL 对齐意图)        — 此时每个 FRAME 已单一 layout, 才能填
□ Step 9: #6 弹性缝隙 + #7 constraints + #8 异构 layout
```

⚠️ **关键: Step 5 避免概念重叠**:
- #2 标准 3 已聚类的元素 (语义化功能成组) → #3.1 依据 B 不重复跑
- #2 角标父本已挂的装饰 → #3.1 依据 B 信号 ⑤ (装饰依附) 不重复跑
- 只对**未聚类的零散子节点**跑 #3.1 全套依据
