# S1 · 抽帧 【录屏专用】

> **阶段**: 识别阶段, 第 1 步 (S1-S6 全是"看", 不写 JSON)
> **前置**: S0 上下文已读
>
> **适用条件**: 仅当输入是录屏视频 (`.mp4` / `.mov`) 时启用 S1。
> 如果输入是单张截图 / 多张已抽好的截图, **跳过 S1**, 直接进入 S2 (识别页面内容)。

---

## 这一步做什么

从用户提供的录屏视频中**机械抽帧**, 产出"原始帧序列", 给后续 S2-S5 消费。

**这一步只抽, 不识别内容、不识别交互、不分析转场、不写任何 JSON。**

---

## 输入

用户提供的 `.mp4` / `.mov` 录屏文件。

---

## 输出 (这一步的中间产物)

一份"帧序列清单":

| 字段 | 说明 |
|---|---|
| 帧序号 | 0, 1, 2, ... |
| 时间戳 | 0ms, 333ms, 666ms, ... |
| 帧图像 | (本地缓存路径) |

输出格式示例:

```text
共抽出 N 帧 (视频 X 秒, 3 fps):
  frame_0   @ 0ms
  frame_1   @ 333ms
  frame_2   @ 666ms
  ...
  frame_(N-1) @ ((N-1) × 333)ms
```

---

## 该步做的事

1. **抽帧技术参数**: PyObjC + AVFoundation 提取 **3 fps** (每 333ms 一帧)
2. **不得跳帧** — 视频每 333ms 的帧都要抽出, 不能"中间几帧看着差不多就跳过"
3. **抽完整段** — 一直抽到视频末尾, 不能提前停

---

## 该步绝对不做的事 (越界 = 抢跑)

| ❌ 越界行为 | 这是哪一步的事 |
|---|---|
| 描述每帧里有什么节点 / 文字 / 图标 / 按钮 | S2 (识别页面内容) |
| 量测元素的 x/y/w/h | S2 |
| 对比相邻帧, 识别滚动区 / 按钮缩放 / 位移 | S4 (识别交互) |
| 像素扫描找触摸点(半透明白色圆形) | S4 |
| 计算帧差分 (>40% 判定新屏幕) | S5 (提取 flow) |
| 判断哪些帧属于同一屏幕、哪些是不同屏幕 | S5 |
| 识别转场动画类型 (dissolve / slide / OVERLAY) | S5 |
| 判断屏幕类型 (`界面_` vs `浮层_`) | S5 |
| 写入任何 JSON 字段 | S7-S9 (生成阶段) |

---

## 违规信号 (自检触发)

| 出现的行为 | 说明 |
|---|---|
| 抽帧时已经开始描述"这帧是主菜单, 那帧是关卡列表" | 抢跑到 S5 (屏幕判定), 立即回到 S1 |
| 主动跳过"看起来重复"的帧 | 违反"不得跳帧"原则;是不是重复留给 S5 帧差分 |
| 边抽帧边记录"这帧按钮被点了" | 抢跑到 S4 (识别交互);触摸点识别和按钮缩放对比是 S4 的事 |
| 边抽帧边量测"这个按钮 w=200" | 抢跑到 S2 (识别页面内容) |

---

## 录屏 H 注意

视频源帧的高度 H **必须排除视频播放器自身 UI** (顶部状态栏 / 底部控制条)。

如果用户的录屏带了播放器 UI 边框, 在 S1 阶段就要先**裁切**, 只保留游戏画面区域, 这样后续 S2/S3 量测的 H 才是有效的游戏屏幕高度。
