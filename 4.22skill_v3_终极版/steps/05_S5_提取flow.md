# S5 · 提取 flow

> **阶段**: 识别阶段, 第 5 步 (识别阶段的倒数第二步)
> **前置**: S0 上下文已读, S1-S4 已完成
> - S4 给出"哪一帧发生了什么交互" (触摸点 / 按钮缩放推点击)
> - S5 把"交互事件"串成"屏幕跳转关系"

---

## 这一步做什么

基于 S1 帧序列 + S4 交互事件清单, 提取**屏幕跳转关系 (flow)**:

1. **汇总屏幕清单** — 帧差分 >40% → 独立屏幕
2. **屏幕类型判断** — `界面_` (全屏替换) / `浮层_` (覆盖)
3. **翻页类型识别 + 转场动画** — dissolve / slide / OVERLAY / CLOSE
4. **转场回溯** — 每次转场前 3 帧找触摸点 → 确认触发元素
5. **触摸点不可见时仍记录连线** — 不省略
6. **新屏幕回写 S1 清单** — 发现 S1 漏的屏幕, 补充进清单

**这一步只识别"谁点击 → 切到哪个屏"**, 不关心:
- 元素布局 (S3)
- 单帧元素视觉反馈 (S4 已记录)
- 写 JSON (S7-S9)

- S4 表 E 触摸点 / 点击事件清单 (含视觉反馈)

## 该步做的事

### 1. 汇总屏幕清单 (帧差分判定)

逐帧比对相邻帧的画面差异:

| 帧差分 | 判定 |
|---|---|
| > 40% | **独立屏幕** (画面发生重大变化) |
| < 40%, 且只是部分变化 | 同一屏幕 (内容更新 / 滚动) |
| 仅遮罩变暗 | 同一屏幕**之上叠浮层** (不算新独立屏幕, 但要记 OVERLAY 转场) |

帧差分**恰好在 40% 边界**容易误判 — 重新核对画面结构是否真的变了 (重看主元素 / 顶部 / 底部), 边界 case 倾向于判为"独立屏幕"。

### 2. 屏幕类型判断

| 视觉特征 | 类型 | 前缀 | 转场动画 |
|---|---|---|---|
| 全屏替换, 原画面完全消失 | 界面 | `界面_` | dissolve 300ms |
| 弹窗覆盖, 原画面变暗仍可见 | 浮层 | `浮层_` | OVERLAY |
| 活动页面占满全屏 (即使叫"活动") | **界面**, 不是浮层 | `界面_` | dissolve 300ms |

(背景见 S0 第 10 节 "什么是界面 vs 浮层")

### 3. 翻页类型识别 (动画判定)

| 识别特征 | 切换类型 | 动画 |
|---|---|---|
| 过渡帧两屏同时可见, 内容横向位移, 导航栏不动 | Tab 导航切换 | `slide 300ms` |
| 触摸点在内容区按钮, 切换后结构完全不同 | 全屏页面跳转 | `dissolve 300ms` |
| 原屏幕变暗仍可见, 新内容浮在上方 | 弹窗/浮层打开 | `dissolve 300ms (OVERLAY)` |
| 触摸点在浮层关闭按钮, 回到原屏幕 | 浮层关闭 | `CLOSE` |
| 底部 Nav 高亮 Tab 变化 | 推断为 Tab 切换 | `slide 300ms` |
| 触摸点落在场景背景/建筑物, 切换后结构完全不同 | 全屏页面跳转 | `dissolve 300ms` |

### 4. 转场回溯 (强制, 每次帧差分 >40% 后立即执行)

发现转场时, **必须回溯前 3 帧** (查 S4 表 E):

1. 找到该帧 / 前 1 帧 / 前 2 帧 / 前 3 帧 的触摸点坐标
2. 映射到**源屏** UI 元素 → 确认触发元素
3. 记入 flow 连线表
4. 找不到触摸点 → 标"**来源未确认**", 仍然记录该转场, **不得省略**

⛔ **禁止**: 仅记录新屏幕而不追溯是谁触发了跳转 — 没有触发元素的连线 = flow 断链

### 5. 触摸点不可见时仍记录连线 (从 S4 #6 继承)

如果 S4 已经走了 #6 候选推断, S5 把 S4 给的"候选 (按契合度降序)" 直接抄进 flow 连线表的"触发元素"列:

```text
连线 #N: 源屏 → 目标屏
  触发: 来源未确认
  候选 (S4 已推断, 按契合度降序):
    1. 按钮_活动放大镜 [极高] 放大镜=侦探标志
    2. 按钮_活动紫罐   [中]   卷轴可能=任务线索
  动画: dissolve 300ms (默认)
```

⛔ **禁止**: 因触摸点不可见就**省略整条交互连线** — 必须记录, 只是标"来源未确认"

候选连线占比 > 30% → 大概率用户没开 Show taps, 在 S5 输出时提示用户 (参考 S4 #6 实操建议)。

### 6. 新屏幕回写 S1 清单 (强制)

S5 执行过程中, 若发现 **S1 漏收录的屏幕** (例如通过滚动末尾 / Tab 切换 / 过渡帧识别到的新页面), 必须:

1. **立即暂停 S5 输出**, 补充说明: "发现 S1 遗漏屏幕: 界面_xxx"
2. **回写表 F**: 列出修订后的**完整屏幕清单** (含原有 + 新增)
3. **补充对应的 flow 连线**: 说明该屏幕的触发来源 (触摸点 或 推断来源)
4. 继续执行 S5 剩余步骤

**表 F (屏幕清单) 是 flow 的唯一权威来源**, S5 的 flow 连线只能基于表 F 最终版生成, 不得使用 S1 原始版本。

**常见遗漏场景**:
- 触摸点落在**场景背景/建筑物** (非标准按钮) 触发的全屏跳转
- 从滚动列表某项点击进入的详情页
- 帧差分**恰好在 40% 边界**导致误判为同一屏幕

## 该步绝对不做的事 (越界 = 抢跑)

| ❌ 越界行为 | 这是哪一步的事 |
|---|---|
| 识别新元素 / 重新量测 x/y/w/h | S2 |
| 识别新的布局关系 / 组团 | S3 |
| 重新扫触摸点像素 (S4 已做) | S4 |
| 识别 pattern (这个按钮命中哪个 ui_pattern) | S6 |
| 给触发元素起 `按钮_xxx` 命名 | S7 |
| 把 flow 连线写成 JSON `flow: [{ trigger, from, to }]` | S9 (字段补全阶段) |

## 违规信号 (自检触发)

| 出现的行为 | 说明 |
|---|---|
| 发现新屏幕但没回写表 F | 违反 #6, 表 F 必须修订 |
| 发现转场但没追溯触发元素 | 违反 #4 强制回溯 |
| 触摸点不可见就省略连线 | 违反 #5, 必须记录"来源未确认" |
| flow 连线里写了 `按钮_xxx` 这种白名单命名 | 抢跑到 S7;S5 用 S4 给的描述性标签 |
| 把 flow 写成 JSON 字段格式 | 抢跑到 S9 |
| 帧差分 40% 边界 case 凭"感觉"判 | 必须重新核对结构, 不能拍脑袋 |

---

## 验证 (S5 输出前必过)

1. **屏幕清单完整性**: 表 F 包含 S1 初识 + S5 发现的所有屏幕, 没有遗漏
2. **flow 连线覆盖**: 表 F 里**每个非起始屏幕**都有至少一条 flow 连线指向它 (否则用户怎么进来的?)
3. **每条转场都追溯了触发元素**: 表 G 没有"触发元素为空"的行 — 即使是"来源未确认"也要列候选
4. **候选连线占比检查**: 候选连线 > 30% → 在输出末尾**主动提醒用户**开 Show taps
