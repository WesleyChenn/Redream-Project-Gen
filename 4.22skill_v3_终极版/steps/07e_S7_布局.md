## 1. constraints 写法 — 外侧大组团语义表

> 取值: `LEFT`/`RIGHT`/`CENTER`/`SCALE` (横) + `TOP`/`BOTTOM`/`CENTER`/`SCALE` (纵)。
> **判断逻辑**: §1.0 元规则 → §1.1 外侧大组团典型表 → §1.2 完整控件单元 → §1.3 附加溢出硬夹断

### 1.0 元规则 (4 条) 🔴

1. **约束只放在外侧大组团** (屏幕 `layers[]` 直接子节点)
2. **大组团内部排版用 AutoLayout** (HORIZONTAL/VERTICAL + alignment + paddings + itemSpacing)
3. **AL 容器的子节点不写 constraints** (AL 接管)
4. **整体不可 SCALE** —— 唯一 SCALE 例外仅 1 个: 全屏遮罩

### 1.1 外侧大组团 → constraints 典型表 🔴🔴

按位置/语义**直接查表**, 不靠抽象推理:

| # | 大组团位置/语义 | 命名特征 | constraints |
|---|---|---|---|
| 1 | **全屏遮罩** | `遮罩_浮层背景` | `SCALE/SCALE` ⚠️ **唯一 SCALE 例外** |
| 2 | **屏幕背景图** (美术做超大图, 屏幕变大显示更多原图) | `背景_主` / `背景_xxx` (整屏) | `CENTER/CENTER` |
| 3 | **顶部 HUD wrapper** | `组_顶部HUD` | `CENTER/TOP` |
| 4 | **顶部 HUD 下方进度条** | `组_主进度` / `组_顶部进度` | `CENTER/TOP` |
| 5 | **左活动入口** | `组_活动_左xxx` | `LEFT/TOP` |
| 6 | **右活动入口** | `组_活动_右xxx` | `RIGHT/TOP` |
| 7 | **底部 HUD 上方按钮** (独立大按钮, 例如"开始游戏") | `按钮_xxx` | `CENTER/BOTTOM` |
| 8 | **底部 HUD 整体** | `组_底部HUD` / `导航_xxx` | `CENTER/BOTTOM` |
| 9 | **滚动列表区** | `容器_xxx滚动区` / `容器_xxx滚动` | `CENTER/TOP` ⚠️ **2026-05-22 update**: 永远中上, 不写 BOTTOM, 不写 vertical SCALE (滚动区固定高度从顶部往下排, clip_content + overflow:VERTICAL 接管滚动行为) |

| 12 | **fallback 默认** | 其余一切外侧大组团 (标题栏 / 装饰 / 倒计时 / Tab / 自我条 / ...) | `CENTER/TOP` |

**使用方法**:
1. 拿外侧大组团的**命名 + 位置语义**跟表里匹配
2. 命中第 1-11 行 → 用对应 constraints 值
3. 都不匹配 → 第 12 行 `CENTER/TOP` 兜底

**表外元素的处理**:
- 出新元素 → 落入第 12 行 fallback (中上)
- 同类反复出现 → 反馈给用户加新行 (保持表的实例锚定)

**顶部 HUD 子组特殊说明** (#3 行的内部结构):

```
组_顶部HUD (外侧约束: CENTER/TOP)
├── (内部) layoutMode: HORIZONTAL
├── (内部) primaryAxisAlignItems: SPACE_BETWEEN  ← 自动把两子组推到左右两端
├── children:
│   ├── 组_顶部HUD_左 (不写 constraints, AL 接管, 内部可再 HORIZONTAL AL 排按钮)
│   └── 组_顶部HUD_右 (不写 constraints, AL 接管, 内部可再 HORIZONTAL AL 排按钮)
```

**没有"左/右活动入口"时的默认形态**:
- 除底部 HUD 和底部 HUD 上方按钮 (第 7/8 行用 `CENTER/BOTTOM`) 之外
- 全部用第 12 行 fallback `CENTER/TOP`

### 1.2 完整控件单元 (按钮 / 角标 / 进度条节点 / 列表项 / INSTANCE) 🔴

**核心约束**: 这些"逻辑完整的复用/控件单元"**整体绝不 SCALE** (拉伸即破, 不分父类型)。

**识别**:
- 进度条 widget、角标、节点、奖励物、奖励格、按钮、钟表、行、任何 INSTANCE/子ccb 引用 → 都是完整控件单元

**约束写法**:
- 在 AL 容器里 → **不写 constraints** (AL 接管)
- 不在 AL 容器里 (例: 直接挂屏当外侧大组团) → 按 §1.1 表查
- **内部 layer 一律不写 `constraints` 字段** (由外侧统一管)

**是约束放置规则, 不触发重抽 ccb** (ccb/多态用已确认决议表, 不动)

### 1.3 🔴 附加溢出元素 — 硬夹断 (引擎 bug 绕过, 理解式遵守, 不走推断)

**WHY (理解了再守, 不是盲套)**: Figma 的 `RIGHT`/`CENTER` 约束在某些父子布局下**会覆盖子节点的 x 值, 把元素弹飞出屏**。这是 Figma 引擎缺陷, **不是设计逻辑, §1.1 的语义推断推不出来** —— 所以对"挂在主体边缘的附加/溢出小件(角标、溢出装饰)"必须无条件夹断:

- ✅ 附加元素 constraints **一律 `LEFT/TOP`** (哪怕语义上它在右上角)
- ✅ x/y **一律正数**, **禁止负坐标**
- ✅ 让**主体用 x/y 偏移让位**给溢出的附加元素 (不用负坐标顶上去)
- ⛔ 附加元素**禁用** `RIGHT`/`CENTER` 约束 / 负坐标

#### 四种常见叠加场景算法

| 视觉场景 | 包装层 w/h | 主体 x/y | 附加元素 x/y | 附加 constraints |
|---|---|---|---|---|
| **右上角角标溢出顶部** | w=主体w, h=主体h | x=0, y=角标h/2 (主体下移让位) | x=主体w-角标w/2, y=0 | `LEFT/TOP` |
| **角标正上方居中** | w=主体w, h=主体h | x=0, y=溢出量 | x=(主体w-角标w)/2, y=0 | `LEFT/TOP` |
| **底标/倒计时下方居中** | w=主体w, h=主体h | x=0, y=0 | x=(主体w-附加w)/2, y=主体h+间距 | `LEFT/TOP` |
| **右上角内侧(不溢出)** | w=主体w, h=主体h | x=0, y=0 | x=主体w-角标w-偏移, y=偏移 | `LEFT/TOP` |

> **关键**: 包装层 h **不含**附加元素溢出高度 (= 主体 h), 这样同行多个按钮的 h 对齐才一致。附加元素的"溢出"通过视觉绝对定位实现, **不撑大包装层**。

#### 居中验证方法 (防止误判居中 / 左对齐)

```
同时量测父本宽度 W_parent + 附加元素宽度 W_child
居中期望值 x = (W_parent - W_child) / 2
实际量测 x_actual (相对父本左边缘)
|x_actual - x| < 10px → 居中, x 用计算值
偏差 > 10px → 左/右对齐, x 用量测值
(无论哪种情况, constraints 都写 LEFT/TOP)
```

#### 🔴🔴 角标在 AL 容器内必 ABSOLUTE (2026-05-22 加, 跟铁律 14 角标处理对齐)

**所有 `角标_xxx` 节点都不参与 AL 排版**:
- 父容器是 NONE → 角标走绝对定位 (`x/y` 写值, 上面规则照旧)
- 父容器是 HORIZONTAL / VERTICAL AL → **角标必带 `layoutPositioning: ABSOLUTE`**, 脱离 AL 流, 不影响 AL 子元素排列

理由: 角标本质是"溢出/装饰小件", 它不该跟主体一起被 AL 算位置 (AL 会算成"主体旁边", 但角标视觉应该"主体边缘附着")。AL 接管 = 角标错位。

```json
// ✅ 正确: 角标在 AL 容器内, 用 ABSOLUTE 脱离布局流
{ "type": "FRAME", "name": "列表项_xxx",
  "layoutMode": "HORIZONTAL",
  "children": [
    { "type": "INSTANCE", "name": "组_主体", ... },                       // AL 流
    { "type": "INSTANCE", "name": "角标_状态",                            // ❗ ABSOLUTE
      "x": 273, "y": 115, "w": 80, "h": 80,
      "layoutPositioning": "ABSOLUTE" }
  ]
}

// ❌ 错误: 角标也参与 AL → AL 会把它当"下一项"排到主体旁边, 而不是叠在边缘
{ "type": "FRAME", "name": "列表项_xxx",
  "layoutMode": "HORIZONTAL",
  "children": [
    { "type": "INSTANCE", "name": "组_主体", ... },
    { "type": "INSTANCE", "name": "角标_状态", ... }  // ❌ 没 ABSOLUTE → AL 把它放主体右侧
  ]
}
```

**通用规则**: 凡是 `角标_xxx` 命名节点, **都要忽略 AutoLayout** (无论父是 NONE 还是 AL):
- NONE 父 → 绝对定位 `x/y` (本身就脱离 AL)
- AL 父 → 必写 `layoutPositioning: ABSOLUTE`

## 2. AL 容器完整字段 + 弹性缝隙 (基于 S3 表 B)

S3 表 B 已识别 AL 容器的对齐意图 (MIN / CENTER / SPACE_BETWEEN), S7 写**完整 JSON 字段**让 Figma 插件能正确渲染:

### AL 容器 / 子节点字段完整清单 🔴 (来自 旧 04 规则 6 + 旧 05 Auto Layout 规则)

| 字段 | 取值 | 写在哪 |
|---|---|---|
| `layoutMode` | `NONE` / `HORIZONTAL` / `VERTICAL` | AL 父容器 (来自 S3 #2) |
| `primaryAxisSizingMode` | **`FIXED` / `AUTO`** (只有 2 个值, 不是 HUG/FILL) | AL 父容器 |
| `counterAxisSizingMode` | **`FIXED` / `AUTO`** (只有 2 个值) | AL 父容器 |
| `primaryAxisAlignItems` | `MIN` / `CENTER` / `MAX` / `SPACE_BETWEEN` | AL 父容器 (来自 S3 表 B) |
| `counterAxisAlignItems` | `MIN` / `CENTER` / `MAX` / `BASELINE` | AL 父容器 |
| `itemSpacing` | 数字 (px) | AL 父容器 (子元素间距) |
| `paddingLeft` / `paddingRight` / `paddingTop` / `paddingBottom` | 数字 (px) | AL 父容器 (内边距) |
| `layoutSizingHorizontal` | `FIXED` / `HUG` / `FILL` (这里才是 3 个值) | **AL 父容器内的子节点** |
| `layoutSizingVertical` | `FIXED` / `HUG` / `FILL` | **AL 父容器内的子节点** |
| `layoutPositioning` | `ABSOLUTE` | **AL 父容器内子节点**, 用于底板"脱离布局流"绝对定位 |

⚠️ **关键区分**:
- **`primaryAxisSizingMode` / `counterAxisSizingMode`** 只有 **`FIXED` / `AUTO`** 两个值 — **容器自身**的尺寸模式
- **`layoutSizingHorizontal` / `layoutSizingVertical`** 才有 **`FIXED` / `HUG` / `FILL`** 三个值 — **容器内子节点**的尺寸模式
- 这两个**不要混用**

⛔ **AL 禁用值**: **不允许** `SPACE_AROUND` / `STRETCH` / `primaryAxisSizingMode: FILL` / `primaryAxisSizingMode: HUG`

### 子节点 `layoutSizing` 取值规则 (在 AL 父容器内)

- **`FIXED`** (默认): 用 `w`/`h` 固定尺寸
- **`HUG`**: 跟随内容 (例: 滚动区子容器内容多就高 / TEXT 不写 w 跟随文本)
- **`FILL`**: 填满父容器剩余空间 (例: 列表行内"内容区"填满中间宽)

#### 响应式行为补充表 (来自 旧 04 规则 2)

| 子节点语义 | layoutSizingHorizontal | 说明 |
|---|---|---|
| 列表行 (排行榜行/消息行) | `FILL` | 撑满父容器宽度 |
| 列表行内名字 / 内容区 | `FILL` | 占满剩余宽度 |
| 列表行内固定元素 (头像/序号) | 不写 (`FIXED`) | 保持量测宽度 |
| AL 容器内均分按钮 | `FILL` | 均分容器宽度 |
| AL 容器内固定宽按钮 | 不写 (`FIXED`) | 保持量测宽度 |
| 网格项 | `FILL` | 均分行宽度 |
| **VERTICAL 容器内任意子 FRAME** | **`FILL`** (必填!) | **防止文字竖排** |

### 弹性缝隙节点写法 🔴 (来自 旧 04 规则 8 + 旧 05)

S3 #6 已在表 B 确认的弹性缝隙 (位置 + 意图), S7 用**空 FRAME + layoutSizingHorizontal: FILL + w:0/h:0** 实现 (**不是** `layoutGrow: 1`):

```json
{ "type": "FRAME", "name": "弹性缝隙",
  "w": 0, "h": 0,
  "layoutMode": "NONE",
  "layoutSizingHorizontal": "FILL" }
```

⚠️ **VERTICAL 容器内的弹性缝隙**: 需同时写 `"layoutSizingVertical": "FILL"`, 去掉 `layoutSizingHorizontal`。

⚠️ 有弹性缝隙时, 父容器 `primaryAxisAlignItems` 必须用 **`MIN`** (不是 SPACE_BETWEEN — 那个是均分场景)。

### ⛔ AL 父容器内的 ABSOLUTE 底板 — 已废弃 (z 序 bug, 2026-05-22)

> **实证 bug (JO 列表项_journey 渲染全空白)**: Figma 渲染 AL 容器时, **`layoutPositioning: ABSOLUTE` 的子节点会被拉到 z 最顶层**(无视 children[] 位置)。
>
> 后果: 底板放 AL 容器内 + ABSOLUTE → **底板覆盖 AL flow 内容**, Claim / Win 25 Levels / 数字 / 锁等全部看不见。手动把底板拖出来才能看到下面被遮的内容。
>
> **修法**: 改用 **NONE 外层 + 内层 AL 容器** 模式, 见下面 §"复用类 component 内部布局 — NONE 外层 + AL 内层"。

**旧 ABSOLUTE 写法 ⛔ 不要再用**:

```json
{ "type": "FRAME", "name": "容器_xxx",
  "layoutMode": "VERTICAL",                          // ❌ AL 容器
  "children": [
    { "type": "RECTANGLE", "name": "底板_背景",
      "layoutPositioning": "ABSOLUTE" },             // ❌ ABSOLUTE → 拉到顶层覆盖内容
    { "type": "TEXT", "name": "文本_标题", ... },
    ...
  ]
}
```

**保留: layoutPositioning: ABSOLUTE 字段** 在 v20.6 schema 里仍合法(其他场景可能需要), 但**不再用于底板**。底板一律走 NONE 外层 + AL 内层。

### 🔴🔴 复用类 component 内部布局 — NONE 外层 + AL 内层 (2026-05-22 更新)

> **本节是 SKILL.md 铁律 15 + `03_S3 §"layoutMode 合约 → S7"` 在复用类 component 上的具体写法样例**。
>
> **核心元规则 (已在 03_S3 / 铁律 15 定义)**: S3 标的 layoutMode 是 S7 合约, 不论层级。本节给出标准写法。
>
> 列表项 / 网格项 / 卡片类 component (有底板 + 多个 INSTANCE 子单元 + 可能有角标溢出) → **必用 NONE 外层 + AL 内层 模式**, 让 z 序按 children[] 自然排列。
>
> 实证 (2 个 bug 都靠这个模式根治):
> - **出框 bug**: TT 列表项 收集物数量 出底板 20px / JO 列表项 角标 出 75px → 内层 AL 自动算位置, 不会超界
> - **z 序 bug** (2026-05-22 新发现): JO 列表项 渲染全空白, 因为底板 ABSOLUTE 在 AL 容器内被 Figma 拉到顶层覆盖内容 → NONE 外层让底板按 children[0] 自然底层

#### 🔴 核心规则: 底板永不进入 AL 容器 (铁律 18)

`底板_xxx` RECT **永远在外层 NONE 容器内**作为 `children[0]`, **永不作为 HORIZONTAL/VERTICAL AL 容器的 children**。3 个理由:

1. **视觉语义**: 底板在内容"外侧" (z 序底层包围内容), AL 容器子节点参与 AL 流, 跟"外侧"语义冲突
2. **z 序 bug** (2026-05-22 JO 实证): 底板进 AL 内必用 ABSOLUTE 脱离布局流, Figma 渲染会把 ABSOLUTE 拉 z 顶层 → 覆盖 AL 内容看不见 (`lessons/lesson_AL内ABSOLUTE底板z序bug.md`)
3. **AL 算位置干扰**: AL 容器把底板算进 itemSpacing/padding/FILL → 底板尺寸被错算

→ 必用下面的标准结构 (NONE 外层让底板天然底层, 内层 AL FRAME 接管内容排版)。

#### 标准结构 (NONE 外层 + AL 内层, 3 层 z 序)

```json
{
  "name": "列表项_xxx",
  "w": <宽>, "h": <高>,
  "variants": [{
    "name": "常态",
    "layers": [
      // ─── children[0]: 底板 (底层, 自然 z=0) ───
      { "type": "RECTANGLE", "name": "底板_行",
        "x": 0, "y": 0, "w": <宽>, "h": <高>,
        "corner_radius": 25 },
        // ⛔ 不写 layoutPositioning: ABSOLUTE
        // NONE 外层容器内, children[0] 自然在底层, 不会被 Figma 拉到顶层

      // ─── children[1]: 内容容器 (中层, AL 接管排版) ───
      { "type": "FRAME", "name": "组_内容容器",
        "x": 0, "y": 0, "w": <宽>, "h": <高>,
        "layoutMode": "HORIZONTAL",            // ← AL 在内层 wrapper 内
        "primaryAxisSizingMode": "FIXED",
        "counterAxisSizingMode": "FIXED",
        "primaryAxisAlignItems": "MIN",
        "counterAxisAlignItems": "CENTER",
        "itemSpacing": 15,
        "paddingLeft": 25, "paddingRight": 25,
        "children": [
          // 全部 AL 流子节点 - 不写 x/y/constraints, AL 接管
          { "type": "INSTANCE", "name": "组_排名", "component_name": "排名",
            "variant": "金", "w": 80, "h": 120 },
          { "type": "INSTANCE", "name": "组_头像", "component_name": "头像",
            "variant": "带装饰", "w": 145, "h": 145 },
          { "type": "FRAME", "name": "组_名字",
            "layoutMode": "VERTICAL", "w": 290, "h": 130,
            "children": [
              { "type": "TEXT", "name": "文本_玩家名", "content": "Name", ... },
              { "type": "TEXT", "name": "文本_副标", "content": "Knight", ... }
            ]},
          // 弹性缝隙撑开"靠左组" vs "靠右组"
          { "type": "FRAME", "name": "弹性缝隙",
            "w": 0, "h": 0, "layoutMode": "NONE",
            "layoutSizingHorizontal": "FILL" },
          { "type": "INSTANCE", "name": "组_道具", "component_name": "道具",
            "variant": "常态", "w": 160, "h": 90 },
          { "type": "INSTANCE", "name": "组_收集物数量", "component_name": "收集物数量",
            "variant": "常态", "w": 215, "h": 100 }
        ]
      },

      // ─── children[-1]: 附加溢出元素 (顶层, 自然 z=top) ───
      // 例如角标(右上锁/对勾/状态)、装饰物溢出等
      { "type": "INSTANCE", "name": "角标_行", "component_name": "角标_状态",
        "variant": "锁",
        "x": <靠右上角的 x>, "y": <靠右上角的 y>,
        "w": 75, "h": 75 }
        // ⛔ 不写 layoutPositioning: ABSOLUTE (NONE 容器内本来就是绝对定位)
        // children[-1] 自然在顶层
    ]
  }]
  // ⚠️ component 顶层不再写 layoutMode/primaryAxis... — 外层是 NONE
}
```

**3 层 z 序 (按 children[] 顺序自然形成)**:
| children 位置 | 内容 | z 序 |
|---|---|---|
| `children[0]` | 底板 RECT | 底层 (z=0) |
| `children[1]`(单个) 或 `children[1..n-1]`(多个) | 内容容器 (内层 AL 排版) | 中层 |
| `children[-1]` | 附加溢出 (角标 / 装饰) | 顶层 |

**关键点**:
- **外层 NONE 容器** → 各 children 按 x/y 绝对定位 + **z 序按 children[] 顺序**, 不会被 Figma 拉到顶层
- **底板** RECT 直接挂 NONE 外层 children[0], **不再用 `layoutPositioning: ABSOLUTE`** (2026-05-22 z 序 bug 修法)
- **内容容器** 单独一层 FRAME, HORIZONTAL / VERTICAL AL 接管排版, 内部子节点不写 x/y
- **角标 / 附加溢出** 直接挂 NONE 外层 children[-1], 用 x/y 定位 (top-right 等), **不再用 layoutPositioning**
- AL 算位置 → 永远不会超界 (出框 bug 治本); NONE 外层 → 底板天然底层 (z 序 bug 治本)

#### ⛔ 反例: NONE + 绝对坐标的失败模式

```json
// 错误写法 — 用 NONE + 手算 x/y
{
  "name": "列表项_xxx",
  "w": 890,
  "layoutMode": "NONE",  // ❌
  "variants": [{
    "layers": [
      { "type": "INSTANCE", "name": "组_收集物", "x": 855, "w": 215 },  // ❌ ends at 1070, 出界 180px
      { "type": "INSTANCE", "name": "组_角标",   "x": 905, "w": 60  }   // ❌ ends at 965,  出界 75px
    ]
  }]
}
```

→ 手算坐标永远会有人算错; AL 让位置由结构自动推导, 不可能算错。

## 3. 滚动区字段生成 (基于 S4 表 D) 🔴

> 🔴 **滚动区识别标准 — 看 S4 表 D, 不看几何关系**
>
> "这块是不是滚动区"的判断**完全基于 S4 表 D** (视频里实际有滚动行为 → 标记为滚动区)。
>
> **不要**用"子容器 h > 父容器 h"作为判断标准 — 那是 HUG 内容多了**自然产生的结果**, 不是判断条件。S7 只需按 S4 表 D 写字段, 内容多少由设计师在 Figma 端调整, 运行时 HUG 自动让 h 跟随内容。
>
> ⚠️ **CENTER/TOP 跟"内部能滚"不矛盾** (2026-05-22 加注): 外侧 constraints `CENTER/TOP` 管滚动区父 FRAME 在屏幕里的定位 (横向居中固定宽, 纵向贴顶固定高度, 不拉伸); 内部 `clip_content + overflow:VERTICAL + 子容器 layoutSizingVertical:HUG` 管子容器内容多了能滚动。**两件事不同字段, 不冲突** — 不要因为"vertical:TOP"就觉得"不能滚动"。

### 滚动区父容器 + 子内容容器 完整结构

```json
{ "type": "FRAME", "name": "容器_列表滚动区",
  "x": 0, "y": 250, "w": 1080, "h": 1931,
  "layoutMode": "VERTICAL",
  "primaryAxisSizingMode": "FIXED",
  "counterAxisSizingMode": "FIXED",
  "clip_content": true,                  // ← 滚动区必须: 裁剪溢出
  "overflow": "VERTICAL",                // ← 滚动方向: VERTICAL / HORIZONTAL
  "constraints": { "horizontal": "CENTER", "vertical": "TOP" },  // ← 2026-05-22 update: CENTER/TOP (永远中上, 不写 vertical SCALE/BOTTOM; 滚动行为靠 clip_content+overflow 接管)
  "children": [
    { "type": "FRAME", "name": "组_滚动内容",
      "layoutMode": "VERTICAL",
      "primaryAxisSizingMode": "AUTO",   // ← 子容器主轴 AUTO (自适应内容, 非 FIXED!)
      "counterAxisSizingMode": "FIXED",
      "layoutSizingHorizontal": "FIXED",  // ← w 必须显式指定
      "layoutSizingVertical": "HUG",     // ← 子容器必须 HUG (内容多就长)
      "itemSpacing": 12,
      "children": [
        // 列表行 / 网格行 ...
      ]
    }
  ]
}
```

### 三个关键字段

| 字段 | 必须取值 | 写在哪 | 作用 |
|---|---|---|---|
| `clip_content` | `true` | **滚动区父容器** | 裁剪溢出 (注意命名 — 是 `clip_content` 下划线, **不是** `clipsContent` 驼峰!) |
| `overflow` | `VERTICAL` / `HORIZONTAL` (按 S4 表 D 方向) | **滚动区父容器** | 滚动方向 |
| `layoutSizingVertical` (横向滚则是 Horizontal) | `HUG` | **子内容容器** | 内容多才能滚 |

### 常见错误 (旧 02 末提到, S10 自检要检查)

| 现象 | 原因 | 修法 |
|---|---|---|
| 整屏跟着滚, 顶部固定区也上移 | `clip_content` 写成 `clipsContent` (驼峰错误) | 改成 `clip_content` |
| 滚动区滚到负数位置 (露出空白) | 子容器 `layoutSizingVertical` 没设 `HUG` | 子容器加 `"layoutSizingVertical": "HUG"` |
| 滚动区一直不动 | 父容器 `overflow` 写成 `"NONE"` 或缺失 | 加 `"overflow": "VERTICAL"` |

### 固定区 / 滚动区分组 (来自 S4 #1 强制规则)

S4 #1: **固定区必须单独成组, 不并入滚动容器**:

```text
界面_主菜单 (FRAME, 顶层)
├── 容器_顶部标题栏 (固定区 FRAME, 不可滚, 无 clip_content)
├── 容器_列表滚动区 (滚动区 FRAME, clip_content: true, overflow: VERTICAL)
│   └── 组_滚动内容 (子容器 FRAME, layoutSizingVertical: HUG)
│       ├── 列表项_排名1
│       ├── 列表项_排名2
│       └── ...
└── 容器_底部导航 (固定区 FRAME, 不可滚, 无 clip_content)
```
