### 为什么换主路径

之前的设计是 "S7 扁平 FRAME → S11 跑 extract_components.py → 后处理删大组团/中间组团"。 实践证明这条路径**对奖励物这种"枚举+占位混合 Variant"** 不工作:

## 🔴 Variant 命名铁律 (v20.6+ 与 Figma combineAsVariants 行为对齐)

### Variant 名字禁止包含下划线 `_`

**原因**: Figma `combineAsVariants` 在解析 `<ComponentName>/<VariantValue>` 命名时, 如果 VariantValue 含下划线, 会误把一组"对称下划线"的 Variant **互相归并/吞掉**。

具体表现: 5 个 tile 在 Component Set 里都画出来了, 但右侧"状态"下拉只显示 3 个, 设计师**没法在 INSTANCE 上完整切换状态**。

### ❌ 错误命名

- `有头衔_无道具` / `无头衔_有道具` / `有头衔_有道具` (对称下划线 → 互相吞)
- `状态_选中` / `状态_未选中` (任何含下划线的都不行)

### ✅ 正确命名

- `有头衔无道具` / `无头衔有道具` / `有头衔有道具` (拼接, 无下划线)
- `选中` / `未选中` (单词)
- `已完成` / `可领取` / `进行中` / `当前用户` (短语)
- `变体2` / `变体3` (占位名, 不带下划线)

### 应用范围

阶段二脚本输出的 `components[].variants[].name` 和 `screens.layers[].variant` 引用, **两边都不能含下划线**。

## 中间组团后处理删除 🔴 (S6 #4 三层区分铁律的 S11 落实)

### 为什么需要后处理删除

`extract_components.py` 脚本**默认抽取所有跨多实例同结构 FRAME**, 包括:
- ✅ **最小单元** (S6 标记应抽 — 底板 / 角标 / 短进度 / 节点六边形 等)
- ❌ **中间组团** (S6 标记不抽 — 组_左奖励 / 组_右奖励 / 组_节点列 等 FRAME 包装层)
- ❌ **大组团** (S6 标记不抽 — 节点行 / 列表项 等)

按旧 skill `00d` 原则 2 "大组团不抽 Component, 只是 FRAME 结构" + S6 #4 三层区分铁律, 跑完脚本后必须**手动删除中间组团 + 大组团 Component**, 把它们的 INSTANCE 还原为扁平 FRAME。

### 何时需要删

对照 S6 表 H, 凡是标记**不抽 Component**的 FRAME, 如果脚本抽出来了, 就要删:

| 标记 | 脚本抽出来? | 后处理 |
|---|---|---|
| 大组团 (节点行 / 列表项) | 默认会抽 | **删 Component, 还原 INSTANCE → FRAME** |
| 中间组团 (组_左奖励 / 组_节点列) | 默认会抽 | **删 Component, 还原 INSTANCE → FRAME** |
| 最小单元 (角标 / 底板 / 短进度) | 应该抽 | **保留** |
| 占位 RECT (奖励物图片) | 不会抽 (脚本只抽 FRAME) | 保留 RECT |

### 删除步骤 (脚本)

```python
import json
from copy import deepcopy

with open('final_scene.json', 'r') as f:
    d = json.load(f)

# 1. 列出要删的中间组团 + 大组团 Component 名 (来自 S6 表 H)
TO_DELETE = ['组_节点行', '组', '组_节点列']  # 例: RoyalPass 视频

for target in TO_DELETE:
    comp = next((c for c in d['components'] if c['name'] == target), None)
    if not comp:
        continue
    # 默认 Variant 的 layers 作为还原模板
    template = comp['variants'][0]['layers']

    # 遍历所有 INSTANCE 引用, 还原为 FRAME (保留 wrapper 字段 + 应用 overrides)
    def restore(node):
        if not isinstance(node, dict): return
        kids = node.get('children') or node.get('layers') or []
        new_kids = []
        for c in kids:
            if c.get('type') == 'INSTANCE' and c.get('component_name') == target:
                frame = {
                    'type': 'FRAME', 'name': c.get('name'),
                    'x': c.get('x', 0), 'y': c.get('y', 0),
                    'w': c.get('w'), 'h': c.get('h'),
                    'layoutMode': 'NONE',
                    'children': deepcopy(template)
                }
                # 应用 INSTANCE.overrides → 子节点 TEXT.content
                ovrs = c.get('overrides', {})
                def apply(n):
                    if isinstance(n, dict):
                        if n.get('type') == 'TEXT' and n.get('name') in ovrs:
                            n['content'] = ovrs[n['name']]
                        for k in ('children', 'layers'):
                            if k in n:
                                for cc in n[k]: apply(cc)
                for ch in frame['children']: apply(ch)
                new_kids.append(frame)
            else:
                restore(c)
                new_kids.append(c)
        if 'children' in node: node['children'] = new_kids
        elif 'layers' in node: node['layers'] = new_kids

    for s in d['screens']: restore(s)
    d['components'] = [c for c in d['components'] if c['name'] != target]

with open('final_scene.json', 'w') as f:
    json.dump(d, f, ensure_ascii=False, indent=2)
```

### 跟漏网 FRAME 修复的对比 (两个反向操作)

| 后处理类型 | 触发场景 | 操作 |
|---|---|---|
| **中间组团删除** (本节) | 脚本**多抽了** Component (大组团/中间组团) | 删 Component + INSTANCE 转 FRAME |
| **漏网 FRAME 修复** (下一节) | 脚本**漏抽了** Variant (边缘形态) | 加 Variant + FRAME 转 INSTANCE |

### 删除前必查 (避免误删)

❌ **禁止**: 把"最小单元 Component" 当中间组团删了 (例: 误删 `角标_状态` Component)
✅ **必查**: 对照 S6 表 H, 只删表里标"大 CCB / 中间组团" 的 Component

### 删除后验证

- ✅ 还原的 FRAME 在主屏 layers 内 (类型 = FRAME, name 跟原 INSTANCE 一致)
- ✅ FRAME 的 children 跟之前 INSTANCE 引用的 Variant.layers 内容一致
- ✅ INSTANCE.overrides 已应用到 children TEXT
- ✅ 该 Component name 不再在 `components[]` 数组里
- ✅ 主屏没有引用该 Component 的 INSTANCE 残留

### 🔴 删除后核心铁律: 主屏 FRAME → INSTANCE 转换 (游戏界面可调多态)

**核心要求**: 主屏内每个最小单元位置必须是 ◇ INSTANCE 节点, 设计师在 Figma 端能**直接选中并切换 Variant**。

#### 为什么需要这步

`extract_components.py` 对 **embedded Component** (`cross_cutting=1`) **不做嵌套 INSTANCE 替换** — 中间组团 Component 的 `Variant.layers` 内部, 最小单元仍是 FRAME 而非 INSTANCE。

所以删除中间组团时, 如果**只是简单还原** (拷贝 Variant.layers 作 children), 还原 FRAME 内部的最小单元也是 FRAME, **设计师在主屏看不到 INSTANCE icon, 无法切换 Variant**。

这跟"游戏页面的内容必须是可调节状态的 Component" 这一核心铁律直接冲突 — **必须修复**。

#### 转换路径

删除中间组团 + 还原 FRAME 后, 递归 walk 还原 FRAME 内的所有子节点:
1. 如果子节点是 `type: FRAME` 且 `name` 对应**保留的最小单元 Component** (在 `components[]` 数组内)
2. → 把它转成 `type: INSTANCE`, `component_name = name`, `variant` 字段按子节点内容启发式确定

#### Variant 字段的启发式确定

不依赖任何 extract 信息, 直接看 FRAME 自身内容:

| 最小单元 Component | 启发式 |
|---|---|
| `角标_状态` | wrapper visible:false → '空'; 内含 `图标_对勾` visible:true → '对勾'; 内含 `图标_锁` visible:true → '锁' |
| `组_奖励卡底板` | 内含 `底板_奖励卡` corner_radius=31 → '待激活'; corner_radius=30 → '常态' |
| `组_节点六边形` | 内含 `底板_节点六边形` corner_radius=15 → '已完成'; corner_radius=14 → '未完成' |
| 通用 | 看子节点哪个 visible:true 唯一存在, 对应 Variant 名 |

#### 转换脚本 (跟前面"中间组团删除脚本"接在一起)

```python
# 保留的最小单元 Component (来自 components[] 数组)
KEEP_COMPS = {c['name'] for c in d['components']}

def determine_variant(frame_node):
    """看 FRAME 内部内容启发式定 variant"""
    cn = frame_node.get('name')
    children = frame_node.get('children', [])
    if cn == '角标_状态':
        if frame_node.get('visible') is False: return '空'
        if any('图标_对勾' in (c.get('name') or '') and c.get('visible') is not False for c in children): return '对勾'
        if any('图标_锁' in (c.get('name') or '') and c.get('visible') is not False for c in children): return '锁'
        return '空'
    # 其他 Component 类似 (看 corner_radius / fill / visible 等)
    ...
    return None

def transform_to_instance(node):
    """递归 walk, FRAME→INSTANCE"""
    if not isinstance(node, dict): return
    kids = node.get('children') or node.get('layers') or []
    new_kids = []
    for c in kids:
        if c.get('type') == 'FRAME' and c.get('name') in KEEP_COMPS:
            variant = determine_variant(c)
            inst = {
                'type': 'INSTANCE',
                'name': c.get('name'),
                'component_name': c.get('name'),
                'variant': variant,
                'x': c.get('x', 0), 'y': c.get('y', 0),
                'w': c.get('w'), 'h': c.get('h'),
            }
            if c.get('visible') is False: inst['visible'] = False
            # TEXT.content 差异 → INSTANCE.overrides
            for cc in children:
                if cc.get('type') == 'TEXT' and cc.get('content'):
                    inst.setdefault('overrides', {})[cc.get('name')] = cc['content']
            new_kids.append(inst)
        else:
            transform_to_instance(c)
            new_kids.append(c)
    if 'children' in node: node['children'] = new_kids
    elif 'layers' in node: node['layers'] = new_kids

# 应用到所有 screens (不只是删除的那些)
for s in d['screens']:
    transform_to_instance(s)
```

#### ⚠️ 关键: 不要从中间组团 Variant.layers 还原 — 从 flat_scene.json 还原

中间组团 Component 通常只有 1 个 Variant (或少数几个), 即使删除后用它的 Variant.layers 作模板还原, **8 行实例的差异 (锁/对勾/空 等) 都会丢失** — 因为 Variant.layers 是统一模板。

**正确路径**: 从 `flat_scene.json` (S7 阶段一扁平 FRAME, 每个实例 children 各异) 取实例间差异, 然后对该实例的 children 跑 `transform_to_instance` 转 INSTANCE。

```python

with open('final_scene.json') as f: final = json.load(f)
# final 用 flat 的 screens (含实例间差异)
```

## 漏网 FRAME 检测 + 修复 🔴 (v20.7.x+, RoyalPass 教训)

### 为什么需要后处理

`extract_components.py` 算法只识别**主流**显隐组合 (常态 / 宝箱型 等), **边缘组合会留作 FRAME**。

例如 RoyalPass 行 19/20:
- 行 19: 左对勾 + 右对勾 (双侧对勾)
- 行 20: 左对勾 + 右锁 (对勾锁混合)

不在算法 2 种主流形态里 → 留作扁平 FRAME 在主屏 → 设计师粘到 Figma 看到"前 2 行扁平 + 后 6 行引用"混合形态。

### 漏网 FRAME 检测脚本

```bash
python3 -c "
import json
d = json.load(open('final_scene.json'))

def find_lists(n, results=[]):
    if isinstance(n, dict):
        # 启发式: VERTICAL 容器 + ≥4 children + 子里既有 INSTANCE 又有 FRAME → 可能是漏网混合
        if n.get('layoutMode')=='VERTICAL' and len(n.get('children',[]))>=4:
            ts = [c.get('type') for c in n['children']]
            if 'INSTANCE' in ts and 'FRAME' in ts:
                results.append((n.get('name','?'), ts))
        for k in ('children','layers'):
            if k in n: find_lists(n[k], results)
    elif isinstance(n, list):
        for x in n: find_lists(x, results)
    return results

mixed = find_lists(d['screens'])
if mixed:
    print('⚠️ 发现漏网混合容器:')
    for name, ts in mixed:
        print(f'  {name}: {ts}')
    print('→ 需要把 FRAME 类型项抽成新 Variant 转 INSTANCE')
else:
    print('✅ 所有列表/网格容器内全部 INSTANCE, 无漏网平铺')
"
```

### 修复路径 (铁律)

对每个漏网 FRAME:

1. 抽出 FRAME 的内部 children 作为新 Variant 模板 (过滤 visible=false)
2. 添加到对应 Component 的 variants 数组里 (语义命名, 如 `对勾型` / `对勾锁型`, **无下划线**)
3. 把主屏的 FRAME 替换为 INSTANCE 引用新 Variant
4. 验证: 对应 Component variants ≥ 2 + 视觉签名唯一 (过【阶段二第 4 层】自检)

### ⛔ 严禁

- ❌ 删除 Component 让 FRAME "合规" (违反用户原始设计意图, 引发连锁失败)
- ❌ 不抽 Variant, 直接保留 FRAME (设计师粘到 Figma 看到混合形态)

## 算法能力 (v20.7+)

### ✅ 支持 — 二层嵌套抽取 (Multi-pass)

```text
Pass 1: 收集所有 FRAME 候选 + 评分 + 分类
        cross_cutting ≥ 2 → promoted (内层提级, 跨多个外层共享)
        cross_cutting = 1 → embedded (外层 Component 自身)

Pass 2: 抽 promoted 内层 Component 先, 在 mutable_scene 里替换为 INSTANCE

Pass 3: 抽 embedded 外层 Component 后 (模板从 mutable_scene 取, 含已替换的 INSTANCE 引用 ✓)

Pass 4: 输出 components 数组按 promoted → embedded 排序
        (内层在前, 满足 Figma 插件依赖序: 外层引用内层时, 内层已注册)
```

### ✅ 支持 — 视觉差异生成 Variant

阶段二自动按视觉签名 (`visible` / `fill` / `corner_radius` / `opacity`) 分 Variant。`TEXT.content` **不算视觉差异** (归数据驱动)。

### ⚠️ 局限

- **Variant 名只给占位** — `常态` / `变体2` / `变体3`, 必须人工重命名为语义名
- **数据驱动判断颗粒度** — 同 Component 实例的图片 url 差异如果是"语义状态", 脚本会误判为同 Variant。解决: S7 阶段显式标 `visible` 或 `fill` 表达状态多态
- **暂不支持三层及以上嵌套** — promoted 候选自身内部还有可抽 FRAME 时, 当前脚本不递归。游戏 UI 通常不超过两层, 够用

```bash
d = json.load(open('final_scene.json'))
```

```bash
def variant_signature(layers):
    parts = []
    def collect(L):
        for n in L or []:
            if isinstance(n, dict):
                parts.append(f'{n.get(\"type\")}|{n.get(\"name\")}|{n.get(\"fill\",\"\")}|{n.get(\"visible\",True)}')
                if n.get('type')=='INSTANCE':

                    if k in n: collect(n[k])

    return hashlib.md5(''.join(parts).encode()).hexdigest()[:8]

        issues.append(f'{c[\"name\"]} 只有 {len(c[\"variants\"])} Variant — combineAsVariants 会失败')

    walk_inst = []
    def collect_refs(layers):
        for n in layers or []:
            if isinstance(n, dict):
                if n.get('type')=='INSTANCE':
                    walk_inst.append(n.get('component_name'))
                for k in ('children','layers'):
                    if k in n: collect_refs(n[k])
    for v in c['variants']: collect_refs(v.get('layers'))
    for ref in walk_inst:
        if ref not in seen and ref in all_comp_names:
            issues.append(f'components[] 顺序错: {c[\"name\"]} 引用了还未注册的 {ref}')
    seen.add(c['name'])

print('✅ 第4层全部合规' if not issues else f'❌ {len(issues)} 项问题:')
for i in issues[:20]: print(f'  {i}')
"
```

## Component 修复铁律 (combineAsVariants 失败时)

| 失败项 | ❌ 错误修复 | ✅ 正确修复 |
|---|---|---|
| 漏网平铺 FRAME | 删 Component 让 FRAME 合规 | **加 Variant 转 INSTANCE 引用** |
| Variant 数量 < 2 | 删 Component | **加 dummy 第 2 Variant** (fill 不同) |
| Variant 视觉签名相同 | 合并/删 Variant | "显隐"用 INSTANCE.visible=false / 其他加 fill 或 icon 差异 |
| INSTANCE 引用不存在 component | 删 INSTANCE | 把缺失 Component 加回 components[] |
| components[] 顺序错 | (不会自动错) | 按依赖关系重排: 子 → 外层 |

### 🔴 元铁律: 删 Component 必须先和用户确认

Component 列表是用户的**设计决策**, 不是工具限制下我可以决定的。

**任何 Component 删除操作前必须先问用户, 不擅自删**。

#### 历史教训 (RoyalPass)

| 错误时机 | 错误操作 | 正确做法 | 后果 |
|---|---|---|---|
| 看到 1 Variant Component | 删 Component 内嵌 FRAME | 加 dummy 第 2 Variant fill 不同 | 用户反馈"你怎么把进度条删了" |
| 看到 Variant 视觉签名相同 | 删其中一个 Variant | "显隐"改 INSTANCE.visible=false | 后续连锁失败, 组件库 / 预览多次"消失" |
| 看到漏网 FRAME 混合形态 | 删整个 Component | 加 Variant 转 INSTANCE | 用户原始设计被擅自改变 |
