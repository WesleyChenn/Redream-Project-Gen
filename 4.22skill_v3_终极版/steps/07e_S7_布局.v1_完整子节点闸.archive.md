## 1. constraints 写法 (基于 S3 表 A/B/C)

> 取值: `LEFT`/`RIGHT`/`CENTER`/`SCALE` (横) + `TOP`/`BOTTOM`/`CENTER`/`SCALE` (纵)。
> **判断顺序: §1.0 完整子节点闸 → §1.1 位置+语义出值 → §1.2 SCALE 窄例外 → §1.3 附加元素硬夹断。**

### 1.0 🔴🔴 最前置:完整子节点闸 (决定"谁写约束、谁绝不 SCALE")

**完整子节点** = 逻辑完整的复用/控件单元:进度条 widget、角标、节点、奖励物、奖励格、按钮、钟表、行、任何 INSTANCE/子ccb 引用、任何"一个整体控件"。

| 节点类别 | 写约束? | 能 SCALE? |
|---|---|---|
| **完整子节点(外侧落点)** | ✅ 只在它**外侧写一个** | ⛔ **绝不**(整体不可拉伸) |
| **完整子节点的内部 layer** | ⛔ **完全不输出 `constraints` 字段** | — |
| **非完整子节点 = 布局骨架**:全屏背景 / 全屏遮罩 / 手搓布局容器 FRAME / 纯填充面底板 | ✅ 写 | ✅ 可(见 §1.2) |
| AL (HORIZONTAL/VERTICAL) 容器的子节点 | ⛔ 不写(AL 接管) | — |

铁律:
- **约束一定写在完整子节点的外侧**(它在父里的那个落点 = INSTANCE 本身 / 该控件外层 FRAME)。**内部一律不写**(不是写 LEFT/TOP,是干脆不输出该字段)。
- **完整子节点整体不可拉伸**:外侧只能钉边/居中,**永不 SCALE**;图素/进度条/角标拉伸即破。
- 进度条、角标都算完整子节点 → 外侧一个约束、内部零约束、整体不拉。这是**约束放置规则**,**不触发重抽 ccb**(ccb/多态用已确认决议表,不动)。

### 1.1 完整子节点的约束 = 位置 + 语义 (具体判, 不查死表)

定了它是完整子节点(不可拉伸)后, 外侧那一个约束这样出值:

- **纵向**:**默认 `TOP`(贴顶)**。**唯一 `BOTTOM` 例外 = 底部 HUD/导航/操作栏**。其余内容(含滚动区/中部块)**一律不贴底, 贴顶**。基本不用纵向 `CENTER`(除非语义确为父内垂直居中的主体)。
- **横向**:看它在父里的**位置 + 语义**具体判 —— 居屏/父中线 → `CENTER`;贴左侧/左起 → `LEFT`;贴右侧/右动作位 → `RIGHT`。**一例一判, 不套表**。
- 能用一句话说清"它在父的什么位置、所以这俩值"才算判清;说不清回 §1.0。

### 1.2 SCALE 的窄例外 + 旧表(降为学习样例, 非查表)

`SCALE` 经插件映射成 Figma `STRETCH`(两边钉住拉伸,非等比)。**只有这几类**(均**非**完整子节点)可 SCALE:

| 可 SCALE 的(且仅) | 典型轴 |
|---|---|
| 真·全屏背景 (`背景_xxx` 全屏) | `SCALE/SCALE` |
| 全屏遮罩 (`遮罩_浮层背景`) | `SCALE/SCALE` |
| 手搓布局容器 FRAME(顶部固定区/滚动区壳, 需跟宽) | `SCALE/TOP`(跟宽+贴顶) |
| 纯填充面底板(填满父布局壳、无美术细节会被拉坏) | `SCALE/TOP` |

> 旧角色表(全屏背景/按钮内底板/进度条跟宽/顶底固定区… → 各值)**仅作学习样例帮你识别类别**;**与本框架冲突时以本框架为准**(例:旧表"进度条 SCALE/TOP"已废 —— 进度条是完整子节点, 不可拉伸)。表外元素按 §1.0+§1.1 判。

### 1.3 🔴 附加溢出元素 — 硬夹断 (引擎 bug 绕过, 理解式遵守, 不走推断)

**WHY (理解了再守, 不是盲套)**: Figma 的 `RIGHT`/`CENTER` 约束在某些父子布局下**会覆盖子节点的 x 值, 把元素弹飞出屏**。这是 Figma 引擎缺陷, **不是设计逻辑, §1.1 的语义推断推不出来**——所以对"挂在主体边缘的附加/溢出小件(角标、溢出装饰)"必须无条件夹断:

- ✅ 附加元素 constraints **一律 `LEFT/TOP`**(哪怕语义上它在右上角)
- ✅ x/y **一律正数**, **禁止负坐标**
- ✅ 让**主体用 x/y 偏移让位**给溢出的附加元素(不用负坐标顶上去)
- ⛔ 附加元素**禁用** `RIGHT`/`CENTER` 约束 / 负坐标

#### 四种常见叠加场景算法

| 视觉场景 | 包装层 w/h | 主体 x/y | 附加元素 x/y | 附加 constraints |
|---|---|---|---|---|
| **右上角角标溢出顶部** | w=主体w, h=主体h | x=0, y=角标h/2 (主体下移让位) | x=主体w-角标w/2, y=0 | `LEFT/TOP` |
| **角标正上方居中** | w=主体w, h=主体h | x=0, y=溢出量 | x=(主体w-角标w)/2, y=0 | `LEFT/TOP` |
| **底标/倒计时下方居中** | w=主体w, h=主体h | x=0, y=0 | x=(主体w-附加w)/2, y=主体h+间距 | `LEFT/TOP` |
| **右上角内侧(不溢出)** | w=主体w, h=主体h | x=0, y=0 | x=主体w-角标w-偏移, y=偏移 | `LEFT/TOP` |

> **关键**: 包装层 h **不含**附加元素溢出高度 (= 主体 h), 这样同行多个按钮的 h 对齐才一致。附加元素的"溢出"通过视觉绝对定位实现, **不撑大包装层**。

#### 居中验证方法 (防止误判居中 / 左对齐)

```
同时量测父本宽度 W_parent + 附加元素宽度 W_child
居中期望值 x = (W_parent - W_child) / 2
实际量测 x_actual (相对父本左边缘)
|x_actual - x| < 10px → 居中, x 用计算值
偏差 > 10px → 左/右对齐, x 用量测值
(无论哪种情况, constraints 都写 LEFT/TOP)
```

## 2. AL 容器完整字段 + 弹性缝隙 (基于 S3 表 B)

S3 表 B 已识别 AL 容器的对齐意图 (MIN / CENTER / SPACE_BETWEEN), S7 写**完整 JSON 字段**让 Figma 插件能正确渲染:

### AL 容器 / 子节点字段完整清单 🔴 (来自 旧 04 规则 6 + 旧 05 Auto Layout 规则)

| 字段 | 取值 | 写在哪 |
|---|---|---|
| `layoutMode` | `NONE` / `HORIZONTAL` / `VERTICAL` | AL 父容器 (来自 S3 #2) |
| `primaryAxisSizingMode` | **`FIXED` / `AUTO`** (只有 2 个值, 不是 HUG/FILL) | AL 父容器 |
| `counterAxisSizingMode` | **`FIXED` / `AUTO`** (只有 2 个值) | AL 父容器 |
| `primaryAxisAlignItems` | `MIN` / `CENTER` / `MAX` / `SPACE_BETWEEN` | AL 父容器 (来自 S3 表 B) |
| `counterAxisAlignItems` | `MIN` / `CENTER` / `MAX` / `BASELINE` | AL 父容器 |
| `itemSpacing` | 数字 (px) | AL 父容器 (子元素间距) |
| `paddingLeft` / `paddingRight` / `paddingTop` / `paddingBottom` | 数字 (px) | AL 父容器 (内边距) |
| `layoutSizingHorizontal` | `FIXED` / `HUG` / `FILL` (这里才是 3 个值) | **AL 父容器内的子节点** |
| `layoutSizingVertical` | `FIXED` / `HUG` / `FILL` | **AL 父容器内的子节点** |
| `layoutPositioning` | `ABSOLUTE` | **AL 父容器内子节点**, 用于底板"脱离布局流"绝对定位 |

⚠️ **关键区分**:
- **`primaryAxisSizingMode` / `counterAxisSizingMode`** 只有 **`FIXED` / `AUTO`** 两个值 — **容器自身**的尺寸模式
- **`layoutSizingHorizontal` / `layoutSizingVertical`** 才有 **`FIXED` / `HUG` / `FILL`** 三个值 — **容器内子节点**的尺寸模式
- 这两个**不要混用**

⛔ **AL 禁用值**: **不允许** `SPACE_AROUND` / `STRETCH` / `primaryAxisSizingMode: FILL` / `primaryAxisSizingMode: HUG`

### 子节点 `layoutSizing` 取值规则 (在 AL 父容器内)

- **`FIXED`** (默认): 用 `w`/`h` 固定尺寸
- **`HUG`**: 跟随内容 (例: 滚动区子容器内容多就高 / TEXT 不写 w 跟随文本)
- **`FILL`**: 填满父容器剩余空间 (例: 列表行内"内容区"填满中间宽)

#### 响应式行为补充表 (来自 旧 04 规则 2)

| 子节点语义 | layoutSizingHorizontal | 说明 |
|---|---|---|
| 列表行 (排行榜行/消息行) | `FILL` | 撑满父容器宽度 |
| 列表行内名字 / 内容区 | `FILL` | 占满剩余宽度 |
| 列表行内固定元素 (头像/序号) | 不写 (`FIXED`) | 保持量测宽度 |
| AL 容器内均分按钮 | `FILL` | 均分容器宽度 |
| AL 容器内固定宽按钮 | 不写 (`FIXED`) | 保持量测宽度 |
| 网格项 | `FILL` | 均分行宽度 |
| **VERTICAL 容器内任意子 FRAME** | **`FILL`** (必填!) | **防止文字竖排** |

### 弹性缝隙节点写法 🔴 (来自 旧 04 规则 8 + 旧 05)

S3 #6 已在表 B 确认的弹性缝隙 (位置 + 意图), S7 用**空 FRAME + layoutSizingHorizontal: FILL + w:0/h:0** 实现 (**不是** `layoutGrow: 1`):

```json
{ "type": "FRAME", "name": "弹性缝隙",
  "w": 0, "h": 0,
  "layoutMode": "NONE",
  "layoutSizingHorizontal": "FILL" }
```

⚠️ **VERTICAL 容器内的弹性缝隙**: 需同时写 `"layoutSizingVertical": "FILL"`, 去掉 `layoutSizingHorizontal`。

⚠️ 有弹性缝隙时, 父容器 `primaryAxisAlignItems` 必须用 **`MIN`** (不是 SPACE_BETWEEN — 那个是均分场景)。

### AL 父容器内的 ABSOLUTE 底板 🔴 (来自 旧 04 规则 5.5 + 旧 05)

AL 父容器内, 要放铺满容器但**不占布局流空间**的底板 (例: VERTICAL 容器内整块背景底板, 上面叠加 AL 子元素), 用 `layoutPositioning: ABSOLUTE`:

```json
{ "type": "FRAME", "name": "容器_xxx",
  "layoutMode": "VERTICAL",
  "primaryAxisSizingMode": "FIXED",
  "counterAxisSizingMode": "FIXED",
  "primaryAxisAlignItems": "CENTER",
  "children": [
    { "type": "RECTANGLE", "name": "底板_背景",
      "x": 0, "y": 0, "w": 1000, "h": 80,
      "corner_radius": 12,
      "layoutPositioning": "ABSOLUTE" },     // ← 脱离 AL 流, 绝对定位
    { "type": "TEXT", "name": "文本_标题", ... },   // 正常 AL 流
    { "type": "FRAME", "name": "按钮_确认", ... }   // 正常 AL 流
  ]
}
```

⚠️ **关键限制**:
- `layoutPositioning: ABSOLUTE` **仅在 AL 父容器** (HORIZONTAL / VERTICAL) 内有效
- **NONE 父容器内不写** `layoutPositioning` (NONE 本身就是绝对定位)
- VERTICAL 容器内的背景底板 → 用 ABSOLUTE; 文字/按钮等内容元素 → 不用 ABSOLUTE (走 AL 流)

### 完整示例: 顶部 HUD 横排 (生命栏 / 金币栏 / 弹性缝隙 / 设置按钮)

```json
{ "type": "FRAME", "name": "组_顶部HUD",
  "x": 0, "y": 0, "w": 1080, "h": 88,
  "layoutMode": "HORIZONTAL",
  "primaryAxisAlignItems": "MIN",
  "counterAxisAlignItems": "CENTER",
  "primaryAxisSizingMode": "FIXED",
  "counterAxisSizingMode": "FIXED",
  "itemSpacing": 16,
  "paddingLeft": 20, "paddingRight": 20,
  "constraints": { "horizontal": "SCALE", "vertical": "TOP" },
  "children": [
    { "type": "FRAME", "name": "生命栏", "children": [...] },
    { "type": "FRAME", "name": "金币栏", "children": [...] },
    { "type": "FRAME", "name": "弹性缝隙", "w": 0, "h": 0, "layoutMode": "NONE", "layoutSizingHorizontal": "FILL" },
    { "type": "FRAME", "name": "按钮_设置", "children": [...] }
  ]
}
```

⛔ **弹性缝隙限制** (来自 S3 #6):
- 只能放在两实体元素**之间**, 禁止首/末位
- 必须在 S3 表 B 已说明意图 (左侧元素 / 右侧元素 / 视觉效果), 否则 S7 不得写入

## 3. 滚动区字段生成 (基于 S4 表 D) 🔴

> 🔴 **滚动区识别标准 — 看 S4 表 D, 不看几何关系**
>
> "这块是不是滚动区"的判断**完全基于 S4 表 D** (视频里实际有滚动行为 → 标记为滚动区)。
>
> **不要**用"子容器 h > 父容器 h"作为判断标准 — 那是 HUG 内容多了**自然产生的结果**, 不是判断条件。S7 只需按 S4 表 D 写字段, 内容多少由设计师在 Figma 端调整, 运行时 HUG 自动让 h 跟随内容。

### 滚动区父容器 + 子内容容器 完整结构

```json
{ "type": "FRAME", "name": "容器_列表滚动区",
  "x": 0, "y": 250, "w": 1080, "h": 1931,
  "layoutMode": "VERTICAL",
  "primaryAxisSizingMode": "FIXED",
  "counterAxisSizingMode": "FIXED",
  "clip_content": true,                  // ← 滚动区必须: 裁剪溢出
  "overflow": "VERTICAL",                // ← 滚动方向: VERTICAL / HORIZONTAL
  "constraints": { "horizontal": "SCALE", "vertical": "SCALE" },
  "children": [
    { "type": "FRAME", "name": "组_滚动内容",
      "layoutMode": "VERTICAL",
      "primaryAxisSizingMode": "AUTO",   // ← 子容器主轴 AUTO (自适应内容, 非 FIXED!)
      "counterAxisSizingMode": "FIXED",
      "layoutSizingHorizontal": "FIXED",  // ← w 必须显式指定
      "layoutSizingVertical": "HUG",     // ← 子容器必须 HUG (内容多就长)
      "itemSpacing": 12,
      "children": [
        // 列表行 / 网格行 ...
      ]
    }
  ]
}
```

### 三个关键字段

| 字段 | 必须取值 | 写在哪 | 作用 |
|---|---|---|---|
| `clip_content` | `true` | **滚动区父容器** | 裁剪溢出 (注意命名 — 是 `clip_content` 下划线, **不是** `clipsContent` 驼峰!) |
| `overflow` | `VERTICAL` / `HORIZONTAL` (按 S4 表 D 方向) | **滚动区父容器** | 滚动方向 |
| `layoutSizingVertical` (横向滚则是 Horizontal) | `HUG` | **子内容容器** | 内容多才能滚 |

### 常见错误 (旧 02 末提到, S10 自检要检查)

| 现象 | 原因 | 修法 |
|---|---|---|
| 整屏跟着滚, 顶部固定区也上移 | `clip_content` 写成 `clipsContent` (驼峰错误) | 改成 `clip_content` |
| 滚动区滚到负数位置 (露出空白) | 子容器 `layoutSizingVertical` 没设 `HUG` | 子容器加 `"layoutSizingVertical": "HUG"` |
| 滚动区一直不动 | 父容器 `overflow` 写成 `"NONE"` 或缺失 | 加 `"overflow": "VERTICAL"` |

### 固定区 / 滚动区分组 (来自 S4 #1 强制规则)

S4 #1: **固定区必须单独成组, 不并入滚动容器**:

```text
界面_主菜单 (FRAME, 顶层)
├── 容器_顶部标题栏 (固定区 FRAME, 不可滚, 无 clip_content)
├── 容器_列表滚动区 (滚动区 FRAME, clip_content: true, overflow: VERTICAL)
│   └── 组_滚动内容 (子容器 FRAME, layoutSizingVertical: HUG)
│       ├── 列表项_排名1
│       ├── 列表项_排名2
│       └── ...
└── 容器_底部导航 (固定区 FRAME, 不可滚, 无 clip_content)
```
