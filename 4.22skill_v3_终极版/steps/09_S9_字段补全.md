## 该步做的事

### 1. TEXT.content 字段填充 (基于 S2 识别)

对每个 TEXT 节点, 把 S2 识别的**实际文字内容**写入 `content` 字段:

```json
{ "type": "TEXT", "name": "文本_玩家名",
  "content": "walid",          // ← S9 填入 (来自 S2 识别)
  "font_size": 40,
  "font_weight": "Regular",
  "textAlignHorizontal": "LEFT" }
```

#### 实例间 TEXT.content 差异 — 每实例独立写实际内容 🔴

S7 阶段每个列表行是**独立完整 FRAME**, 每行的 `文本_玩家名` TEXT 都要写**该实例的实际名字** (不是占位 / 不是统一占位字符串):

```json
// row 1
{ "type": "FRAME", "name": "列表项_排名1", "children": [
    ...,
    { "type": "TEXT", "name": "文本_玩家名", "content": "Dennis", ... }
]}

// row 2
{ "type": "FRAME", "name": "列表项_排名2", "children": [
    ...,
    { "type": "TEXT", "name": "文本_玩家名", "content": "Eva", ... }
]}

// ... row 3-8 各自独立 content
```

⚠️ S11 抽取时, 会**自动**把 8 个实例的"文本_玩家名"差异提取到 `INSTANCE.overrides`。S9 阶段**不写** overrides, 只把每个实例的 content 直接写实际值。

### 2. TEXT 字体字段补全 (基于 S2 识别)

| 字段 | 取值 | 来源 |
|---|---|---|
| `font_size` | 数字 (px) | S2 量测字号 |
| `font_weight` | `Regular` / `Medium` / `Bold` / `Black` | S2 识别字重 |
| `textAlignHorizontal` | `LEFT` / `CENTER` / `RIGHT` | S2 识别对齐 |
| `textAlignVertical` (可选) | `TOP` / `CENTER` / `BOTTOM` | S2 识别 (一般 CENTER) |
| `color` (可选) | 颜色 hex | 一般用插件默认, 视频明显特殊色时写 |
| `lineHeight` (可选) | 数字 | 一般不写 |

如果 S7 已经写了, S9 校验; 没写的, S9 补。

### 3. 图片占位的 name 命名最终化

S7 阶段如果用临时描述性 name, S9 按命名白名单 + 数据语义最终命名:

```json
// S7 临时:
{ "type": "RECTANGLE", "name": "头像左1", "x": 50, "y": 30, "w": 120, "h": 120 }

// S9 最终化 (按命名白名单 `图片_` 前缀):
{ "type": "RECTANGLE", "name": "图片_头像", "x": 50, "y": 30, "w": 120, "h": 120 }
```

每个实例的图片占位**命名一致** (8 行的 `图片_头像` 都叫这个), 实际图片 url 由程序运行时 `setSpriteFrame` 填。

| 内容 | 命名前缀 |
|---|---|
| 头像 / 玩家图片 | `图片_xxx` |
| icon / 物品图标 | `图标_xxx` |
| 全屏背景图 | `背景_xxx` |
| 浮层遮罩 | `遮罩_xxx` |

### 4. flow 数组写入 🔴 (基于 S5 表 G)

S5 表 G 已识别 flow 连线 (源屏 → 目标屏 + 触发元素 + 动画), S9 写到**源屏幕**的 `flow` 数组:

```json
{
  "name": "界面_主菜单",
  "type": "FRAME",
  "w": 1080, "h": 2400,
  "layers": [...],
  "flow": [
    {
      "trigger": "ON_CLICK",
      "from": "界面_主菜单",
      "from_node": "按钮_开始",
      "to": "界面_关卡选择",
      "animation": "dissolve 300ms"
    },
    {
      "trigger": "ON_CLICK",
      "from": "界面_主菜单",
      "from_node": "按钮_设置",
      "to": "浮层_设置",
      "animation": "OVERLAY"
    }
  ]
}

// 浮层屏的 flow (CLOSE 到空字符串, 不是写源屏名)
{
  "name": "浮层_设置",
  ...
  "flow": [
    {
      "trigger": "ON_CLICK",
      "from": "浮层_设置",
      "from_node": "按钮_关闭",
      "to": "",
      "animation": "CLOSE"
    }
  ]
}
```

#### flow 字段格式 🔴 (来自 旧 04 规则 10)

| 字段 | 取值 | 说明 |
|---|---|---|
| `trigger` | `ON_CLICK` (默认) | 来自 旧 00a JSON 格式铁律 |
| **`from`** | **源屏的 `name`** (例: `"界面_主菜单"`) | **是源屏名**, **不是触发节点**; 必须在 screens[] 里能找到 |
| **`from_node`** | **触发节点的 `name`** (例: `"按钮_开始"`) | **必须在源屏 layers 里能找到** |
| `to` | 目标屏的 `name`; **浮层 CLOSE 时 `to: ""` (空字符串)** | 必须在 screens[] 里能找到 (CLOSE 除外) |
| `animation` | `dissolve 300ms` / `slide 300ms` / `OVERLAY` / `CLOSE` | 来自 S5 表 G |

⚠️ **常见错误**: 把 `from` 写成触发节点 (`"from": "按钮_开始"`) — ❌ 错!
- ✅ 正确: `"from": "界面_主菜单", "from_node": "按钮_开始"`

#### flow 写在哪个屏幕的 flow 数组里?

**写在源屏幕** — 因为是源屏的某按钮触发跳转。例:
- 主菜单按钮点击跳到关卡列表 → flow 写在 `界面_主菜单` 的 `flow` 数组
- 浮层关闭按钮回到主菜单 → flow 写在 `浮层_设置` 的 `flow` 数组

⛔ **禁止**: 把 flow 写到**目标屏幕**的 `flow` 数组 (方向反了)。

#### 🔴 flow.from 必须是可点击元素, 不能是装饰

S0 第 14 节: 装饰 (角标 / 徽章 / 底标) 作为按钮 children, **自己不是触控层**, 不可点击。flow.from 字段必须指向**可点击元素**:

| flow.from 取值 | 合规? |
|---|---|
| ✅ `按钮_xxx` FRAME (REDNodeButton 触控层) | 合法 |
| ✅ `component_ref` 按钮类 (圆形按钮_xxx / 椭圆按钮_xxx) | 合法 |
| ✅ 做法 B 的外层 `按钮_xxx` 包装 | 合法 |
| ✅ 背景区域 (`背景_xxx` 或 `地图区` 等隐式交互目标) | 合法 (S4 #5 已说) |
| ❌ **装饰** `角标_xxx` / `徽章_xxx` / `底标_xxx` | **违规** (装饰不是触控层) |
| ❌ 普通容器 `组_xxx` / `容器_xxx` (没设按钮属性) | 违规 |
| ❌ 普通 `图片_xxx` / `图标_xxx` / `文本_xxx` (按钮内的子元素) | 违规, 应归父按钮 |

(注: 这里说的 "flow.from_node" 字段, 不是 "flow.from" — `from` 是源屏名, `from_node` 才是触发节点。)

S4 阶段应已修正归属 (#5 触摸点落在装饰时归父按钮)。S9 如果 S5 表 G 抄过来发现 `from_node` 是装饰 → **回 S4/S5 重新映射父按钮**, 不要在 S9 强行写。

例:
- S5 表 G "连线 #3: from_node = 角标_红点" → ❌ 违规
- 修正后 "连线 #3: from_node = 按钮_设置 (含角标_红点 装饰)" → ✅ 合法

#### 触摸点不可见时的 flow (S5 #5 候选推断)

S5 表 G 里"来源未确认"的连线 (含候选列表), S9 阶段:

- ✅ **仍然写入 flow 数组**, `from` 字段取 **S5 候选列表第一个 (契合度最高)**
- 加 `"_note"` 字段标注候选, 供设计师在 Figma 端确认:

```json
{ "trigger": "ON_CLICK",
  "from": "界面_主地图",              // ← 源屏 name
  "from_node": "按钮_活动放大镜",     // ← 触发节点 = S5 候选第一个 (极高契合)
  "to": "界面_Mission_Pursuit",
  "animation": "dissolve 300ms",
  "_note": "来源未确认; 候选: 按钮_活动放大镜 [极高] / 按钮_活动紫罐 [中] / 按钮_活动花朵 [低]" }
```

⛔ **禁止**: 因触摸点不可见就**省略整条 flow 连线** (S5 已强调过, S9 不能绕过)。

#### 导航栏全量连线原则 🔴 (来自 旧 04 规则 10)

每个屏幕**底部导航栏**中, **所有非激活 Tab 项**必须写 flow 指向对应目标屏幕。

- N 个已识别屏幕 → **N×(N-1) 条 slide 连线** (每屏的每个非激活 Tab 都连一条)
- 只写视频中**实际出现的目标屏幕**, 未出现的不写
- 动画用 `slide 300ms` (Tab 切换专用)

例: 视频识别到 5 个屏幕 (主页 / 活动 / 商店 / 任务 / 我的), 每屏底部 5 项导航:
- 主页屏的 flow: 4 条 (活动/商店/任务/我的)
- 活动屏的 flow: 4 条 (主页/商店/任务/我的)
- ... 总共 5 × 4 = 20 条 slide 连线

⛔ **状态切换 Tab** (`导航栏_状态切换_*`) **不生成 flow** (屏内切换, 不跨屏)。

```json
"flow": [
  { "trigger": "ON_CLICK",
    "from": "界面_主页",
    "from_node": "导航_项2",        // 活动 Tab (未激活)
    "to": "界面_活动",
    "animation": "slide 300ms" },
  { "trigger": "ON_CLICK",
    "from": "界面_主页",
    "from_node": "导航_项3",        // 商店 Tab (未激活)
    "to": "界面_商店",
    "animation": "slide 300ms" },
  ...
]
```

### 5. 其它细节字段 (按需补)

| 字段 | 何时写 |
|---|---|
| `opacity` | 节点透明度 < 1.0 时 (例: 半透明浮层遮罩 0.7, 但插件自动处理 `遮罩_xxx` 前缀, 一般 S9 不写) |
| `corner_radius` | 圆角节点 (S7 示例已用; S9 校验所有圆角节点都有) |
| `visible` (顶层) | 默认 true 时不写; **false 时必须写** (子 CCB 显隐铁律: S7 #6 已写, S9 校验) |
| `stroke` / `strokeColor` / `strokeWidth` (可选) | 有描边的节点 (一般组件库 / 手搓很少用) |
