## 0. 🔴🔴 识别为按钮的语义信号 (S6→S7 命名合约, 不许在 S7 退化)

> **跟 SKILL.md 铁律 16 配套**: S6 判定"这是按钮" → S7 必命名 `按钮_<动作>` FRAME, 不能只写 TEXT, 不能用 `组_`/`容器_`/其他前缀。

### 强触发动作词 (任一命中即必识按钮)

视频中文本是以下任一**动作词**, **必识为按钮, S7 必写 `按钮_<动作>` FRAME**:

| 类别 | 动作词 (大小写都算) |
|---|---|
| 领取类 | `claim` / `Claim` / `CLAIM` / `领取` / `Redeem` |
| 启动类 | `Start` / `Play` / `GO` / `开始` |
| 解锁类 | `OPEN` / `Unlock` / `解锁` |
| 商业类 | `购买` / `Buy` / `Get` / `FREE` / `Purchase` |
| 请求类 | `Request` / `Send` / `Ask` |
| 操作类 | `Action` / `Continue` / `Next` / `Skip` |

→ S6 决议表 `pattern_hit` 或 `subclass_or_note` 应包含 "按钮", 包装类型 = 按钮。
→ S7 写时, 该组团**必须**包装成 `按钮_<动作>` FRAME:

```json
// ✅ 正确
{ "type": "FRAME", "name": "按钮_claim", "children": [
    { "type": "RECTANGLE", "name": "底板_claim", ... },
    { "type": "TEXT", "name": "文本_claim", "content": "claim", ... }
]}

// ❌ 错误 (5.21_视觉缩窄即AL 退化案例)
{ "type": "TEXT", "name": "文本_状态_claim", "content": "claim", ... }
// → 没 按钮_ 前缀 FRAME → 引擎不识别为触控层 → 不可点
```

### 为什么这条这么硬

**引擎合约**: Redream 引擎只对节点 name 以 `按钮_` 开头的 FRAME 生成 REDNodeButton 触控层。其他 name 前缀 (`组_` / `容器_` / TEXT 任意 name) 即使视觉看着像按钮, 引擎**不会让它可点**。

→ 设计意图 (这是个按钮) 在引擎层直接丢失, 用户点了没反应。

### 退化触发场景 (Claude 易犯)

在 component variant 切换时, Claude 倾向于把不同 variant 的内容统一成 TEXT layer + visible 切换, 而忘了"某个 variant 应该是按钮 FRAME"。例如:

```
状态 component:
  已完成 variant → 图标_对勾 RECT
  未完成 variant → 底板+文本数字  
  可领取 variant → 应是 按钮_claim FRAME ❌ Claude 退化成 文本_claim TEXT
```

→ 必须保留各 variant 的命名前缀差异: 按钮就是 `按钮_xxx` FRAME, 不能为了 children 结构整齐而退化。

## 1. 按钮外壳结构

```text
按钮_xxx (FRAME, 不带 fill)              ← 触控层, REDNodeButton
├── 底板_xxx (RECTANGLE, x=0, y=0, SCALE/SCALE)   ← 内层装饰底板 (父是 按钮_, 插件自动上最浅灰)
├── (可选) 图标_xxx / 图片_xxx
├── (可选) 文本_xxx (或包在 内容区_xxx 内)
└── (可选) 角标_xxx / 徽章_xxx / 底标_xxx          ← 装饰附件 (一起响应反馈, 见 #2 分组铁律)
```

⚠️ **按钮内部 layoutMode 也按 S3 判** (跟铁律 15 一致, 不是固定 NONE):
- S3 标 NONE (底板+图标+文本 叠加居中) → 按钮内部用 NONE + 绝对定位
- S3 标 HORIZONTAL (图标 + 文本 横排) → 按钮内部用 HORIZONTAL AL + itemSpacing + paddings
- S3 标 VERTICAL (图标 + 下方文本) → 按钮内部用 VERTICAL AL
- 上面 "按钮_xxx 树形结构" 是**视觉示意**, 不规定父容器必 NONE

## 2. 按钮分组铁律 — 装饰必须 children, 不可平级

✅ **正确**:
```json
{ "type": "FRAME", "name": "按钮_活动紫罐", "children": [
    { "type": "RECTANGLE", "name": "底板_活动紫罐", ... },
    { "type": "RECTANGLE", "name": "图片_紫罐", ... },
    { "type": "FRAME", "name": "角标_感叹号", ... }   // 装饰作为 children
]}
```

❌ **错误**:
```json
{ "type": "FRAME", "name": "组_活动_紫罐", "children": [
    { "type": "FRAME", "name": "按钮_活动紫罐", ... },
    { "type": "FRAME", "name": "角标_感叹号", ... }   // 装饰平级 → 点击不跟随按钮变换
]}
```

---

## 3. 按钮内容居中 — 多内容用 内容区_FRAME

按钮内多个子元素需要自动居中排列时, 用 `内容区_xxx` FRAME (HORIZONTAL / VERTICAL AL, CENTER / CENTER) 包装内容。

简单按钮 (单一文字或单一图标) 不需要内容区, 子元素直接作为按钮 children, 用绝对坐标或 AL 任选。

---

## 4. 按钮触控范围 — 装饰可视觉溢出但不可点

按钮 FRAME 尺寸 = 主体尺寸, **不为装饰溢出扩大** (来自 S0 第 14 节)。装饰允许视觉上溢出 (负坐标或 y+h 超出按钮 h), 接受"溢出部分不触发按钮反馈"的代价 — 优先保证按钮 FRAME 尺寸统一对齐。

---

## 5. 按钮内层底板语义后缀 (插件上色可选)

按钮 FRAME 后缀决定内层底板灰度:

| `按钮_` 后缀包含 | 场景 | 内层底板灰度 | 示例 |
|---|---|---|---|
| `弹窗` / `浮层` | 弹窗级按钮 | 最深 | `按钮_弹窗关闭` |
| `切换` / `卡片` | 切换 / 卡片按钮 | 中灰 | `按钮_切换音量` |
| `开关` | 开关控件 | 较浅 | `按钮_开关音量` |
| 其余 (动作名 / 功能名) | 普通按钮 | 最浅 | `按钮_开始` / `按钮_Claim` |

---

## 6. 嵌套按钮冲突 — 禁止 `按钮_` 嵌套

`按钮_xxx` FRAME 内部**禁止再嵌套** `按钮_` 前缀 FRAME (通过 component_ref 间接嵌套也不行)。

组件库已在 S6 #2 预检 3 检查过; 手搓时也要遵守。

## 7. 手搓按钮内容居中铁律 (来自 旧 00a)

所有手搓按钮 (非 component_ref) 内部必须按以下结构, **禁止用估算绝对坐标放置内容**:

```text
按钮_xxx FRAME (NONE, 固定 w/h)                        ← v20: "按钮_" 前缀 = 触控层 REDNodeButton
├── 底板_xxx RECTANGLE (x=0, y=0, SCALE/SCALE)         ← 内层装饰底板
├── (可选) 图标_xxx / 图片_xxx
├── (可选) 文本_xxx
└── (可选) 角标_xxx / 徽章_xxx / 底标_xxx
```

### 完整示例 (带内容区, 自动居中)

```json
{
  "type": "FRAME", "name": "按钮_开始",
  "w": 446, "h": 150, "layoutMode": "NONE", "corner_radius": 75,
  "children": [
    { "type": "RECTANGLE", "name": "底板_开始",
      "x": 0, "y": 0, "w": 446, "h": 150, "corner_radius": 75,
      "constraints": { "horizontal": "SCALE", "vertical": "SCALE" } },
    { "type": "FRAME", "name": "内容区_开始",
      "x": 0, "y": 0, "w": 446, "h": 150,
      "layoutMode": "HORIZONTAL",
      "primaryAxisAlignItems": "CENTER", "counterAxisAlignItems": "CENTER",
      "constraints": { "horizontal": "SCALE", "vertical": "SCALE" },
      "children": [
        { "type": "TEXT", "name": "文本_开始", "content": "開始遊戲",
          "font_size": 60, "font_weight": "Bold", "textAlignHorizontal": "CENTER" }
      ]
    }
  ]
}
```

⚠️ **内容区_ FRAME 的 w/h 必须与按钮底板完全一致**, 子元素不写 x/y, 由 CENTER 自动居中。
