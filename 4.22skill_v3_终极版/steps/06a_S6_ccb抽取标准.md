# S6a · 视觉缩窄机制 + ccb 抽取 3 标准 (v20.7.x+, 2026-05-15)

> 🔑 **一句话核心原则 (2026-05-17)**:
> **多态 (Variant) = 最小化** — 抽 Variant 让被复用组件**尽可能小** (差异下沉到最小变化单元)。
> **子 ccb = 最大化** — 抽子 ccb 让复用**尽可能多次发生** (能复用就抽, 被引用 N 次, 层数不限)。
> 方向相反但配合: **ccb 决定"抽什么出来反复用", Variant 决定"这个被反复用的东西内部差异压到多小"**。
>
> ⚠️ **别停留在"差异下沉"这个手段上**: "差异下沉" 是手段, 真正**目的是压小被复用组件本身的体积**。复杂结构必须先把**不变的大部分** inline / 抽别的 ccb, **Variant 组件只保留"真正会变的那一小块"** —— 不能只满足"Variant 切得细" 却抽出一个仍偏大的组件。
>
> 🔴 **ccb 维度 ≠ 多态维度 3 硬判据 (2026-05-18 Team Battle 复盘, 详见 4.22最新skill/00f 边界1.5)**:
> 1. 抽不抽 ccb 只看 3 标准(复用/动态/独立), 跟有没有多态无关 — 列表项复用 ≥3 **必抽 ccb**, 可以 0 多态(1 默认 Variant), 差异下沉子 ccb
> 2. **有多态 → 必然是 ccb**(Variant 只能挂 component, 裸 FRAME/RECT 无多态能力)。要离散多态先抽 ccb
> 3. 同一差异只在唯一最小单元 ccb 做一次多态, 外层不重复包(列表项 1 默认 Variant + 主屏 INSTANCE override 选子 ccb variant)
> **子 ccb 不一定有多态, 但有多态的一定是子 ccb** — 可当判据反用。

> **属于 S6 pattern 命中阶段的扩展铁律** — 跟 06 主文件配套读
> **范围**: ccb 嵌套决策方法论(决定主屏哪些块抽 ccb / 哪些 inline 保留)
> **跟 06 的关系**: 06 管"组件本身抽不抽 + Variant 怎么切粒度 (最小化)"; 06a 管"ccb 嵌套怎么决定 (最大化复用)"。**两个不是同一回事**, 不要混。

## 一、视觉缩窄机制 (识别阶段方法论)

S3 看视频/截图骨架 + S6 pattern 命中时, **递归下钻找重复结构**:

```
看视频帧 → 找大块重复 → 缩窄一层进入重复块内部 →
   继续找重复 → 再缩窄 → ... 直到没有重复 (原子单元)

每次缩窄到的"稳定重复结构" = 一个 ccb (如果满足 3 标准任一)
缩窄过程中"同一层多个兄弟节点的差异点" = 当前组件的多态 (Variant)
"平行的状态" (同一组件的多种显示状态) = 同一个 ccb 的多个 sequence (时间线), 不抽多个 ccb
```

### 样本对照: Royal Pass

样本路径: `/Users/red/Desktop/red_output5.15.17/ccb/界面_Royal_Pass/`

```
主屏 → 列表项 × 8 (列表项_19~_26 + 列表项_1/_2)             ← 第 1 层重复, 抽 列表项.red
列表项内部 → 组_左气泡 / 组_右气泡 / 组_中央段 / 黄色装饰带    ← 第 2 层重复, 抽各自 ccb
组_中央段 → 组_短进度 / 钻石节点 / ...                       ← 第 3 层, 钻石节点抽 组_钻石节点.red
组_右气泡 → 底板_气泡 / 奖励 / 角标                          ← 第 4 层, 各自抽 ccb
底板_气泡 → REDFile(组_气泡底板.red)                       ← 已是最深 ccb
```

每一层用 [ccb 3 标准](#二ccb-产生的-3-标准) 判断是否抽。

### 平行状态走时间线, 不抽多 ccb

`钟表_指针动画` 内部有 2 个 sequence: **进行中 / 已结束** — 同一组件两种平行状态, **不抽 2 个 ccb**, 而是同一个 .red 里 2 个 sequence 在 keyframe 上切换可见性/字符串。

## 二、ccb 产生的 3 标准

满足任意一条即抽 ccb:

| 标准 | 解释 | 样本例子 |
|---|---|---|
| **复用** | 同一节点结构在多处出现 — **≥3 次必抽,2 次需另满足 #2 动态 或 #3 独立** (2026-05-15 修订, 跟 app.py 护栏 min_repeat=3 对齐) | `列表项 / 组_气泡底板 / 组_奖励 / 组_钻石节点` |
| **动态** | 运行时动态创建数量/位置 | `列表项` (数量按数据决定);`组_奖励`(物品种类多) |
| **独立** | 有独立动画或行为 | `钟表_指针动画`(指针 360° 旋转, 4.27 秒)|

视觉缩窄中找到的**每个"稳定重复结构"**:
- 满足任意一条 → 抽 ccb
- 都不满足 → inline 保留

## 三、跟其他铁律的边界

### 边界 1: 跟 06 #3 "Variant 抽取 (5 大原则)" 的关系

| 主题 | 文件 | 管什么 |
|---|---|---|
| **ccb 嵌套** | 本文(06a)| 哪些块抽 ccb / 嵌套到第几层 — **不限层数, 该抽就抽** |
| **Variant 粒度** | 06 #3 | 某个组件内部怎么抽 Variant — 必须**差异下沉到最小变化单元** |

**两个不是同一回事**。误把"Variant 最小化"理解成"ccb 嵌套也最小化" → 大块漏抽 ccb。

### 边界 2: 跟 03_S3_识别布局 的关系

S3 5 步法 = 视觉缩窄机制的**具体执行步骤**(走 5 步 = 走一轮缩窄)。本文是**方法论 + 终止条件 + 抽取标准**, 5 步法是具体操作流程。

S3 完成第一轮缩窄后, 如果某子大组内部还有重复结构, **递归再走 5 步法**, 直到原子单元。

### 边界 3: 跟 07d "嵌套 CCB 写法" 的关系

07d 管**ccb 嵌套怎么写**(写法层 — INSTANCE 字段、嵌套 ccb 写法、尺寸同步);
本文(06a)管**ccb 嵌套怎么决定**(决策层 — 满足 3 标准就抽)。
两者配合: 06a 决定"要不要抽", 07d 决定"抽出来怎么写"。

### 边界 4: 跟 08a "预制单一钟表特例" 的关系

预制(`钟表_指针动画`)是 3 标准里**"独立" + "复用"** 的特殊情况 — 走独立预制路径(不进 components[] 数组, 引擎直接拷 .red)。其他满足 3 标准的 ccb 都走普通 components[] 路径。

## 四、对 Claude 的 S3-S7 阶段输出规则

1. **S3 先做视觉缩窄**: 从最外层往里递归找重复结构, 每一层用 3 标准判断
2. **S6 pattern 命中**: 缩窄出的稳定结构跟 pattern 库匹配, 命中即抽 ccb
3. **抽出 ccb 命名**: 沿用白名单前缀(`组_` `列表项_` `按钮_` 等)
4. **S7 scene.json 输出**: 在 `components[]` 数组里声明所有抽出的 ccb(`钟表_指针动画` 走预制特例不需要)
5. **Variant 抽法**: 走 06 #3 "差异下沉到最小单元"

### 反面案例(更全见 4.22最新skill/00f §七)

| ❌ 错误做法 | ✅ 正确做法 |
|---|---|
| 列表项 8 个全部 inline 平铺在主屏 layers 里 | 抽 `列表项.red`, 主屏只放 INSTANCE 引用 |
| 钟表 ccb 里"进行中"和"已结束"各做一份 sprite 拷贝 | 1 份 sprite + 2 个 sequence 切换 keyframe |
| 大组(网格行)整体做 4 Variant("通用/宝箱型/对勾型/对勾锁型")| 大组只是 FRAME 包装, 子结构每个最小单元各自 Variant |
| 单 CCSprite `图标_钥匙` 在多气泡共用, 抽 ccb | 叶子节点不抽, inline 保留 (硬规则) |
| 奖励物 7 Variant 列举所有道具 | 占位 RECT, 程序 setSpriteFrame |

### 完整决策流程图 + Royal Pass 端到端案例

见 [4.22最新skill/00f §六 + §七 + §八](/Users/red/Desktop/4.22最新skill/00f_视觉缩窄_ccb_3标准.md), 本文不复述。

## 五、引擎侧机制 (引用, 不必深读)

引擎 `app.py` 收到 scene.json 后:
- 按 `components[]` 数组里的 component 名生成对应 `<output>/ccb/<module>/<comp>.red`(`generate_red_component`)
- 主屏 INSTANCE 走 REDFile 引用 `<module>/<comp>.red`
- 预制(`PREFAB_NAMES = {钟表_指针动画}`)单独走拷贝路径, 不生成

引擎不主动识别"该不该抽 ccb" — 决策由 Claude 在 S3-S6 按本文做完, scene.json 写好。

**引擎护栏**(2026-05-15+): `app.py` 加 `_detect_repeated_inline_structures` warning, 扫主屏 inline 节点找"同结构 ≥ 3 次但没在 components[] 声明的"提示 Claude 漏抽。详见引擎 SKILL `03_component.md`。
