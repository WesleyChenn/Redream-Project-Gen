## #7 constraints 判定

按铁律 #14 (2026-05-21 新加): 约束**只在外侧大组团**(屏幕 `layers[]` 直接子节点)写, 大组团内部用 AutoLayout 或 NONE 内绝对定位。完整控件单元内部 layer **一律不输出** `constraints`。

横向 default = CENTER, 纵向 default = TOP, **整体绝不 SCALE**。

| 屏幕 layers 直接子节点 | 横向 | 纵向 |
|---|---|---|
| 顶部装饰区 | CENTER | TOP |
| Choisss 玩家行 | CENTER | TOP |
| 团队进度组团 (父 ccb) | CENTER | TOP |
| 列表区 | CENTER | SCALE | (滚动列表区允许 SCALE) |

(列表项内部 / 子 ccb 内部子节点: 一律不输出 constraints, 完整控件单元 INSTANCE 整体绝不 SCALE)

## #8 异构内容 layout 分别判定

**列表项是同构的** (排名前 3 用金银铜底, 但是 ccb 内部 variant 切换, 整体结构 children name 100% 一致, 规则 11.5 满足), 不需异构分别判定。

**列表项 vs Choisss 行**: 视觉相似 (都是玩家信息条 + 装饰 + 数字), 但**Choisss 行是单独大组团, 不在列表 ccb 内部** — 是另一个独立组团 (用户没把 Choisss 行声明为列表项的实例, 它是顶部固定的玩家身份条)。 不要因为视觉相似就把 Choisss 行抽进列表项 ccb。
