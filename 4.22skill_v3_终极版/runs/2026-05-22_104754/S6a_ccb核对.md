# S6a · ccb 3 标准 + 视觉缩窄机制核对

按 [06a_S6_ccb抽取标准.md](../../steps/06a_S6_ccb抽取标准.md) 的 3 标准 (复用/动态/独立) 逐 ccb 核对用户决议:

| ccb | 复用次数 | 复用 ✓? | 动态 ✓? | 独立 ✓? | 抽 ccb? | variant 数 |
|---|---|---|---|---|---|---|
| `列表项_offer` | 6 | ✓ (≥3) | — | — | ✅ | 1 (默认) |
| `奖励物` | 6 (每个列表项 1 处) | ✓ (≥3) | ✓ (运行时种类) | — | ✅ | 2 (单/多) |
| `按钮_offer` | 6 | ✓ (≥3) | — | — | ✅ | 1 (默认) |
| `角标_锁` | 6 (5 锁 + 1 空) | ✓ (≥3) | — | — | ✅ | 2 (锁/空) |
| `单个奖励物` | 9 (= 1+2+1+3+1+1) | ✓ (≥3) | ✓ | — | ✅ | 2 (金币/道具) |

## 跟 06a 一句话核心原则交叉验证

- **多态 = 最小化** ✓ — 差异下沉到最小变化单元
  - `列表项_offer` 1 default variant, 差异下沉到子 ccb (奖励物 / 按钮 / 锁) 各自的 variant + override
  - `按钮_offer` 1 default variant, 文案/颜色走 override (不强行抽 variant 因为颜色跟文本绑定且只 2 种,符合"最小")
  - `单个奖励物` 2 variant 切 "金币 vs 道具" — 因为视觉结构有差异 (金币堆无 "×" 数字, 道具有 "×N" 模板)
- **子 ccb = 最大化** ✓ — 能复用都抽出
  - 奖励物 / 按钮 / 锁 / 单个奖励物 都抽出, 不 inline 在列表项内
  - 嵌套层数: 列表项 → 奖励物 → 单个奖励物 (3 层) + 列表项 → 按钮/角标 (各 1 层)

## ccb 维度 ≠ 多态维度 自检

| 抽 ccb? | 有多态? | 案例 | OK? |
|---|---|---|---|
| ✅ | 1 默认 | `列表项_offer` (复用 6, 0 多态) | ✓ "复用必抽 ccb, 可 0 多态" |
| ✅ | 1 默认 | `按钮_offer` | ✓ 同上 |
| ✅ | 2 多态 | `奖励物` (单/多) | ✓ "有多态必是 ccb" |
| ✅ | 2 多态 | `角标_锁` (锁/空) | ✓ |
| ✅ | 2 多态 | `单个奖励物` (金币/道具) | ✓ |

**结论**: 用户决议 5 个 ccb 全部满足 ccb 3 标准, 多态下沉到最小单元符合 06a "Variant = 最小化"。✅ 可进 S7。

## 视觉缩窄链路

```
浮层 → 6 个列表块 (缩窄 1)
列表块 → 奖励物 + 按钮 + 锁 (缩窄 2)
奖励物 → 1 或 N 个 单个奖励物 (缩窄 3, variant 切单/多)
单个奖励物 → 终点 (variant 切金币/道具, layer 是 icon + 文本, 不再抽)
```

抽 ccb 终点: `单个奖励物`. 其 layer (RECT icon + TEXT) 是叶子, **不再抽 ccb** (06a 硬终止)。
