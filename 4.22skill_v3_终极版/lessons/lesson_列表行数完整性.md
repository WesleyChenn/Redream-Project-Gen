# Lesson · 列表行数完整性 (滚动视频必逐帧扫描全部行)

## 一句话
滚动列表识别必逐帧扫描全部行, 不能只识别首屏可见数 — 视频里能滚到几行就要识别几行, 漏识别会导致整个排行榜数据缺失。

## 触发条件 (Trigger)
- **S2 阶段**, 输入是**录屏视频** (S1 已抽帧)
- 视频里有"滚动"或"列表滑动"行为 (S4 表 D 会标记滚动区)
- 列表项 component 跨多帧出现, 行数 > 首屏可见数

## 失败模式 (What goes wrong)

### 反例: 只识别首屏

```
源视频 (TT, 5.20 14:31): 排行榜 13 行 (maila/onon/Choy/.../789)
- 首屏可见 6 行 (mailo ~ Csl)
- 滚动后再见 7 行 (Arthur ~ 789)

Claude 输出 (失败): 只识别 6 行, 整个排行榜数据缺一半
```

实证 (5.21 跑出来):
```json
"列表项_排行_6 (最后一行) overrides": { "文本_玩家名": "Csl" }
// 应该有 7-13 行也都识别出来
```

## 正确做法

### S2 扫帧策略

```text
1. 看 S1 帧序列, 标出"滚动开始帧" 和 "滚动结束帧"
2. 滚动开始帧 → 识别首屏可见行 (含部分露出)
3. 滚动结束帧 → 识别末屏可见行
4. 中间帧 → 识别滚动过程中露出的"新行" (不重复算)
5. 总行数 = 首屏行数 + 中间露出行数 + 末屏行数
```

### S6 决议表必填字段

`s6_coverage.json` 列表项组团这一行要写:

```json
{
  "group": "列表项_排行",
  "reuse_count": 13,                    // ← 必精确, 不写"~6" 或 "可见 6 行"
  "evidence_frames": ["f000", "f016"],  // ← 哪些帧识别出来的
  "abstract_ccb": true,
  ...
}
```

## 自检方法

### 人工查 (S6 review 时)
- S6 报告里写明列表项**总行数** (不是"首屏 N 行")
- 用户 review 时核对: "源视频滚动到底有几行?"

### 机器查 (S10)
- 滚动区子容器内的列表项 INSTANCE 数量 vs S6 reuse_count 一致
