# Lesson: ccb 维度 ≠ 多态维度 (高频混淆, 反复栽)

## 一句话

**"抽不抽 ccb" 和 "有几个多态" 是两个独立维度, 不互相否定。**
- 抽不抽 ccb → 看 3 标准 (复用 / 动态 / 独立), **跟有没有多态无关**
- 有几个多态 → 看离散视觉状态数 (00d / 06_S6 #3)

## 易犯错的场景 (Team Battle 2026-05-18 反复踩)

把 00d "大组团不做排列组合多态" **误读成** "大组团不抽 ccb"。

❌ **错**: 列表项复用 10 次, 但因为"它不做排列组合多态", 就做成扁平 FRAME 平铺在主屏:
```text
容器  ← 列表项_1..10 全是扁平 FRAME (错)
```
后果: 列表项没抽成 ccb, 引擎侧不能复用, 主屏巨大冗余, 改一处要改 10 处。

✅ **对**: 列表项复用 ≥3 → **必抽 ccb** (component); 它自己 0 多态 (1 默认 Variant), 差异下沉到内嵌子 ccb, 行间靠主屏 INSTANCE override:
```text
容器 → INSTANCE 列表项_1..10 → component 列表项 (1V)
列表项 内嵌 7 子 ccb (组_排名4V/组_头像2V/组_礼帽2V/.../组_盾牌分1V)
每行 overrides 选本行各子 ccb variant
```

## 3 条硬判据

| 判据 | 内容 | Team Battle 反面 |
|---|---|---|
| ① | 抽不抽 ccb 只看 3 标准, 跟有没有多态无关 | 列表项复用必抽 ccb, 可 0 多态 |
| ② | **有多态 → 必然是 ccb** (Variant 只能挂 `components[].variants[]`, 裸 FRAME/RECT/TEXT 无 variants 字段) | 用"两个不同命名裸 RECT"(底板_行 / 底板_行高亮)表达多态 → 错, 要多态先抽成 ccb |
| ③ | 同一差异**只在唯一最小单元 ccb** 做一次多态, 外层不重复包 | 列表项 2V(常态/高亮) + 组_行底板 2V(常态/高亮) 同一差异做两遍 → 删列表项那层, 只留组_行底板 |

口诀: **子 ccb 不一定有多态, 但有多态的一定是子 ccb** — 可反用作判据 (看到要离散多态 → 必须抽 ccb)。

## 预防到哪个阶段

- **S3 / S6** (识别+pattern): 看到大组团重复 ≥3 → 直接判"抽 ccb", 不要因为"它内部多态复杂"就退回平铺
- **S6 #3 / 06a**: 抽完 ccb 再单独判每个子单元几个多态, 别在大组团上穷举组合
- **S11 主路径**: 列表项是 component(大CCB), 内嵌子 ccb INSTANCE, 行差异走 overrides
