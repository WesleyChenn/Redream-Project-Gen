# 进度条_多节点 pattern

横向进度条 + N 个里程碑节点沿条分布。**跟单节点进度条`ui_pattern_进度条_横向` 是两个独立 pattern**(单节点只有 1 个左 icon + 1 个右奖励, 这个有 ≥3 个节点)。

## 5 维特征(共性)

| 维度 | 规律 |
|---|---|
| 形状 | 长条横向, 长宽比 **≥ 5:1**(比单节点更长, 才装得下多节点)|
| 构成 | 进度条本体 3 层 + **N 个节点(≥3)** + 可选 N 个底标 |
| 位置 | 节点沿进度条**横向等距分布**(或起点+多奖励点)|
| 量级 | 通常 ≥ 800 px 宽(屏幕级别) |
| 底板 | 必有(进度条本体) |

## 🔴 关键架构(2026-05-12 用户教学补充)

- **进度条最外侧总节点**(`进度条_<XXX>`)仍是 **CCProgressTimer**(新 skill 07c 铁律, 引擎识别 `进度条_` 前缀)
- 🔴 **进度条本体永远是一整根**, 不按节点位置拆段。即使条上压了 N 个节点 icon, Figma 侧 `进度条_<XXX>` **仍只画一整根 100% 满 RECT**, 引擎运行时按 percentage 切割整根。节点 icon 视觉上自然显示"已过/未过", 不需要每段独立 RECT。
- **中间多节点**可以理解为 icon, 但**通常 S11 会抽成同一个 Component 多 Variants**
- **每个节点的 children 可以包含子 CCB**(嵌套结构)
- **每个节点视觉差异可以很大**(不只 fill 变):
  - **完成态**:1 张图(对勾)
  - **待激活态**:绿色 claim 按钮(底板+文本)
  - **未激活态**:底板+文本(灰)
- S7 阶段一: 每个节点画扁平 FRAME, children 100% 一致 (规则 11.5), 不同节点视觉/visible 不同 → S11 自动切多 Variant

⛔ **禁止**: 把 4 节点的进度条画成 3 段 `进度条_段1 / 段2 / 段3` RECT — 引擎拿不到完整 CCProgressTimer, 无法运行时切割; 节点"已过/未过"状态硬编码进设计, 无法按玩家数据动态调整。

```
按钮_<语义> 或 组_<语义> (外层 FRAME)
├── 组_进度_<XXX> (进度条本体, 新 skill 07c 三层)
│   ├── 底板_<XXX>
│   └── 进度条_<XXX>      ← 引擎读取为 CCProgressTimer
├── 节点_1 (FRAME, children=[完整子节点 — 见下注 1])
├── 节点_2 (FRAME, children=[同上, 视觉不同])
├── 节点_3 (FRAME, children=[同上, 不显示的写 visible:false])
└── ...

注 1: 所有 节点_N 的 children 必须 name 100% 一致 (规则 11.5), 否则 S11 抽不出统一 Component。
      "完成态"实例: 显示 图标_对勾 visible:true, 其它子节点 visible:false
      "待激活态"实例: 显示 按钮_claim_底板/文本 visible:true, 其它子节点 visible:false
      "未激活态"实例: 显示 底板_未激活/文本_未激活 visible:true, 其它子节点 visible:false
      整个节点不显示: 节点 FRAME visible:false

S11 抽完后会看到的 Variants 形态 (仅参考, 不是 S7 你要写的):
  节点_<XXX> Component: [常态(多 visual signature → 多 Variant), 空 (从 visible:false 切出)]
```

## 🔴 多段 vs 单段 判定信号 (2026-05-18 用户教学, 锁定)

判 **中间 icon 数 + 两端有无 icon + 段间底板材质**:

| 信号 | 判定 |
|---|---|
| 两端有 icon(起点+终点)**且**中间有 icon | **多段** |
| 中间 **≥2 个** icon(无论两端) | **多段** |
| 只有中间 **1 个** icon、**两端无** icon | **单段** |
| 多根单段**竖排**, **段间能看到底板材质**(露底板纹理/分隔条) | **多个独立单段竖排**, 不是一根多段 |

- 单段竖排 = N 个独立单段进度条上下堆叠(关卡天梯/路径), 每根 1 中间 icon(常是菱形数字), **段间露底板** → 各自独立, **不抽成一根多段**
- 多段 = 一根贯穿条 + 起点 icon + ≥1 中间节点 +(常)终点 icon

## 🔴 节点 ccb 结构 (2026-05-18 用户教学, 锁定)

视觉缩窄第一层: **进度条上的 icon 作为整体 = 第一层 ccb(节点)** — 跟"列表项=大CCB"同理, 节点复用 ≥3 → 抽 ccb。

节点 ccb 内部**最多 2 个子 ccb**(看视频, 不绝对):

| 子 ccb | 内容 | 可能多态 (Variant) |
|---|---|---|
| **icon**(宝箱/道具) | 节点主图 | **已完成 / 可领取 / 未完成** 等(视频实际为准) |
| **数字标记** | 阈值/状态标 | ① 文本+底板 ② icon+文本+底板(=`横排徽章_左图右文` 形态) ③ 某 Variant 是 **"claim" 按钮**(如绿 OPEN) |

- 有的节点**只有 icon 无数字标记**(嵌入式 A 类, 状态靠进度填充覆盖判断)
- 起点 icon(叶子/船舵/金币铃铛圆)通常无数字标记, 是起点节点
- 终点(大盾/月桂)是最后一个节点 icon, 视觉差异大但仍是节点 ccb 的一个 Variant/实例
- ⚠️ 这些是**识别帮助, 不是绝对** — 节点内部几个子 ccb / 几个 Variant **以视频实际为准**

### 对照 2026-05-18 教学 4 例
- 绿(A嵌入式): 节点 ccb 只有 icon 子ccb(彩球/锤/蓝箱), 无数字标记; 状态靠填充覆盖
- 橙(B底部文本式): 节点 = icon(锁箱/锚箱/剑箱 = 未完成/可领取/已完成) + 数字标记(`OPEN`=claim按钮态 / `2500`=文本+底板态 / `✓`=已完成态)
- 蓝紫(C上标式): 节点 = 数字标记(铃铛icon+数字+底板, 在 icon 上方) + icon(陀螺/TNT/球 / 紫盾=终点)
- 紫(C上标式, = Team Tournament): 节点 = 数字标记(铃铛+60/80/100/250+紫底板) + icon(锁箱/盾箱/翼箱 / 月桂=终点)

## 三个子类(用户核心 teaching)

### A. 嵌入式(节点在进度条内, 无底标)

特征:
- 节点**跨在进度条内**(部分穿过底板, 节点高度 ≈ 底板高度 × 1.0~1.3)
- 节点位置**靠进度填充判断状态**(填充覆盖到此节点 = 已过)
- **节点下方无任何附加**
- 起点常是 icon(火焰/闪电), 终点常是宝箱

典型节点构成:
- 起点 icon(可能小, 在条左外侧或左端嵌入)
- 1-N 个中间节点(道具 / 标识)
- 终点 icon(常是宝箱)

例:
- Image 1: 红圆+火焰(起点) → ✓(节点1, 已过) → 紫锤(节点2, 当前) → 蓝宝箱(终点)
- Image 2: 蓝圆+闪电(起点) → 五彩球(节点1) → 紫锤(节点2) → 蓝宝箱(终点)

### B. 底部文本式(节点跨条上 + 下方挂文本/标签)

⚠️ **修正用词**(2026-05-12 用户澄清): 原称"底标式"用词不准。**底标**(narrow)特指 `底标_倒计时` 这种"左钟表 + 右底板+文本"形态。这里下挂的"400/800/1200"数字标签或"✓/OPEN/锁"按钮属于 `icon 带底部文本` pattern, 不是 narrow 底标。

特征:
- 节点**跨在进度条上**(上下都溢出底板, 节点高度 > 底板高度显著)
- 每个节点**下方挂底标**(SKILL 已有"底标_X"前缀)
- 底标内容 2 类:
  - **数字底标**:阈值 / 累计值("400" "800" "1200")
  - **状态底标**:已完成 ✓ / 可领取 [OPEN] / 锁等
- 起点节点**通常无底标**(因为是当前/起点)

典型节点构成:
- 起点 icon(船舵 等, 标识起点)
- N 个奖励节点(宝箱 / 道具)
- 每个奖励节点下方挂底标

例:
- Image 3: 船舵起点 → 棕宝箱(底标 "400") → 蓝宝箱(底标 "800") → 紫宝箱(底标 "1200")
- Image 4: 船舵起点 → 棕宝箱(底标 ✓) → 蓝宝箱(底标 [OPEN]) → 紫宝箱(底标 [OPEN])

### C. 上标式(节点条内 + 阈值标签独立挂上方)

特征:
- 节点在进度条**内嵌入**(像 A 类)
- 但每个节点对应一个**独立标签挂在进度条上方**
- 上方标签**复用 `横排徽章_左图右文` pattern**(icon + 数字 + 胶囊底板)
- 标签跟节点**垂直对齐**(同一 x 坐标)
- 终点节点常单独, 起点节点通常无对应标签

例:
- 2026-05-12 第 5 批 image 5(本张):金圆铃铛起点 → 3 个 ✓(对应上方铃铛 10/20/40 标签) → 紫盾(对应上方铃铛 100)

跟 B 底部文本式 的关键区别:**B 是底标在节点正下方挂载;C 是上方独立标签 + 节点对齐**, 二者位置上下不同。

## 识别信号(≥3 命中即匹配)

- [ ] 横向长条进度条(新 skill 07c 铁律识别)
- [ ] **≥3 个明显节点**沿进度条分布
- [ ] 节点之间间隔大致**等距**(或起点+奖励分布)
- [ ] 跟单节点不同:**没有"X/Y" 中央文本**(进度由节点位置 + 填充判断)
- [ ] 长度通常 **≥ 800 px** 宽

## 区分相邻 pattern

| 看着像但不是 | 区别 |
|---|---|
| `进度条_横向` 单节点 | 只 1 个左 icon + 1 个右奖励, 不是 ≥3 节点 |
| `横排徽章_左图右文` | 中间是底板+文本, 不是双层 RECT |
| 单纯多个 icon 横排 | 没有进度条本体 |

## Component 命名

| 节点 | 命名 |
|---|---|
| 外层容器 | `按钮_<语义>` 或 `组_<语义>`(看可点) |
| 进度条三层 | `组_进度_<语义>` 包 `底板_<语义>` + `进度条_<语义>` |
| 节点 icon | `图标_节点_<N>` 或 `图片_节点_<N>`(数据驱动占位)|
| 节点底标 | `底标_<节点 N>_<内容类型>`(例 `底标_节点1_数字` / `底标_节点1_状态`)|

底标 Variants (S11 抽完后的预期形态):
- 状态底标: S11 抽完 = [常态 (✓/OPEN/锁 视觉签名不同 → 多 Variant), 空 (从 S7 visible:false 切出)]
- 数字底标: S11 抽完 = [常态] (S7 每个 TEXT.content 写实际数字, S11 收集成 overrides)

## 子类组合矩阵

| | A 嵌入式 | B 底部文本式 | C 上标式 |
|---|---|---|---|
| 节点位置 | 进度条内(嵌入)| 跨条上(溢出上下) | 进度条内(嵌入)|
| 节点附加位置 | ❌ 无 | 下方挂底标 | **上方挂独立标签(横排徽章)** |
| 附加内容 | — | 数字/状态(✓/OPEN/锁)| 阈值数字+icon |
| 起点 icon | 通常起点是 icon | 通常起点是 icon, 无底标 | 通常起点是 icon, 无对应上方标签 |
| 当前进度判断 | 进度条填充覆盖到的节点 | 进度条填充 + 底标状态 | 进度条填充 + 节点嵌入 |
| 跟其他 pattern 配合 | — | 用 `底标_X` 系列扁平 FRAME(数字/状态)| **复用 `横排徽章_左图右文`** 当上方标签 |
