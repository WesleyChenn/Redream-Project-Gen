S6 pattern 命中阶段, **每个组团都必须逐项过一遍 memory 的 ui_pattern 库(SKILL 路由 A 表 12 个视觉特征)**, 命中即 Read 对应 pattern.md 以视频为准验证。**禁止**因为"这屏跟之前某个项目长得像"就按那个项目的旧结构类比生成。

**Why:** 2026-05-18 Team Tournament 视频, 中部"60/80/100/250 + 宝箱 + 左仪表 + 右盾牌"面板, 实际是 memory `ui_pattern_进度条_多节点` 的**上标式(C类)**: 彩虹进度条本体(CCProgressTimer)+ 起点 icon + N 里程碑节点 + 上方 4 个 `横排徽章` 阈值标签。我锚定了上一个 Team Battle 项目(无此面板)的结构, 凭类比把它当成普通"奖励档位面板", **整根进度条本体被当 `底板_面板` 背景吞掉**, 4 节点的复用次数虽读对(4≥3 抽 ccb)但语义归错类。用户当场抓出:"你现在能解读到进度条, 为什么生成时没做""我 memory 里早提过这种多段组合进度条"。

**How to apply:**
- ccb **复用次数检测**(同结构≥3→抽)和 **pattern 语义归类**是两件事——复用读对 ≠ 归类对。读到"重复 N 次"后, 必须再走 memory A 表确认它**是什么 pattern**, 不能停在泛化"组_XXX 档位"。
- 看到"长条 + ≥3 个节点沿条分布 / 起点 icon + 终点奖励 / 节点上方或下方挂标签" → 必命中 `ui_pattern_进度条_多节点`, 三子类(A嵌入式/B底部文本式/C上标式)对照视频选。
- **进度条本体永远是独立三层**(`组_进度_X` 包 `底板_X` + `进度条_X`), `进度条_X` 画 100% 满模板交引擎 CCProgressTimer 切割; **绝不能**把它并进面板底板/当背景。条上压几个节点 icon 也不按节点拆段。
- 上标式(C类)= 多节点进度条 + `横排徽章_左图右文` 组合: 上方阈值标签复用(≥3→子ccb component), 数字走 INSTANCE.overrides, icon 占位数据驱动。
- 节点 icon = `图片_节点_N` 占位 RECT 数据驱动(锁/宝箱/盾牌程序换图), 不抽 component; 状态由进度条填充覆盖判断。
- 通用铁律: **以本视频实际为准 > memory pattern 描述 > 上一个相似项目的结构**。相似项目只能借鉴, 不能替代逐项识别。

**反面 / 正面:**
- ❌ 面板 = `底板_面板` + 4×`组_奖励档位`(泛化) + `图标_仪表` + `图标_大盾牌` — 进度条本体丢失
- ✅ 面板 = `底板_面板` + `组_进度_奖励`(底板+进度条双层RECT/CCProgressTimer) + `图标_节点_0_仪表`占位 + 4×`图片_节点_N`占位 + 4×`横排徽章`INSTANCE(数字 overrides)
