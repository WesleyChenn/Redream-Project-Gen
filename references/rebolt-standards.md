# Rebolt 制作规范

来源：飞书文档「Rebolt 制作规范」

---

## 1. Rebolt 必要函数

### 「初始化」（必须）
- 任何 Rebolt 都必须包含
- 程序在 CCB 创建之初直接调用
- **只允许放置**：「绑定节点」+ 「自定义变量」初始化的逻辑块
- 不允许放其他逻辑

### 「更新」（推荐）
- 与样式/时间线更新相关的、涉及程序变量控制的逻辑
- 另起函数调用，推荐使用「更新」函数

---

## 2. 测试逻辑

### 目的
实现美术与程序解耦，帮助美术实时预览不同状态下的运行效果。

### 规则
- 每个 Rebolt 至少一套测试逻辑
- 所有需程序调用的「自定义函数」必须在测试逻辑中出现至少一次
- 测试逻辑中有「程序变量」时，必须用「注释标签」标注变量取值范围和形式

---

## 3. Rebolt Name 命名

Rebolt Name 应尽可能与节点名保持一致，方便 Redream 与 Rebolt 间建立对应关系，降低维护成本。

### CLI 补充硬规则

- 用 CLI 写 `.rebolt` 前，必须先读取 paired `.red`
- 目标节点必须真实存在，且 `reboltName` 不能为空
- 不允许手写猜测的 selector id，也不要把过期历史 id 直接塞回 `.rebolt`
- 节点 selector 必须遵守：`Value = reboltId`，`DisplayName = reboltName`
- 按钮点击块使用 `mathSelector`，其余大多数节点块使用 `baseSelect`；两者都遵守同一套 `Value/DisplayName` 规则
- 不允许把 raw `reboltId` 直接写进 selector 的 `DisplayName`
- 如果 paired `.red` 里的节点还没有 `reboltName`，或 `rebolt.redInfos[*].alias` 还是空字符串，先修 scene 元数据，再写 `.rebolt`
- 换图块必须按资源合同选择：单图路径用 `BTSpriteImageAction.TitleInput`，plist + frame 用 `BTSpritePlistAction.pathInput` + `frameNameInput`
- 改完后必须跑 `rebolt-modify validate`；跨项目批量改动再补 `rebolt validate`

当前推荐的节点类型绑定：

| Rebolt 逻辑 | 允许绑定的节点类型 |
|---|---|
| 按钮点击 / 按钮启用 | `CCControlButton`, `REDNodeButton` |
| 文本标题 / 占位符 / 数字增长 | `CCLabelTTF`, `CCLabelBMFont`, `CCRedLabel`, `CCLabelPlus` |
| 图片替换 / plist 切换 | `CCSprite`, `CCScale9Sprite`, `SpritePlus` |
| 进度条 | `CCProgressTimer` |

## 4. 通知工程师规范

### 类型一：「发送消息」的通知工程师
- 程序通过侦听 Rebolt 发出的特定事件通知，追踪逻辑执行进度
- 典型场景：判定动画播完、捕获按钮交互
- **重要**：涉及资源卸载的通知（如「弹窗退出动画播放完毕」），在该通知后 **严格禁止** 连接任何后续逻辑积木（程序会立即卸载资源，后续积木会导致崩溃）

### 类型二：「传递节点 / 更新子节点变量」的通知工程师
- 命名规范：参数1 = 「绑定节点」，参数2 = 「Rebolt Name」
- 本质：将节点控制权移交程序
- **必须集中在一个独立的「自定义函数」中**（通常是「初始化」），确保流程启动之初就触发

## 5. 按钮逻辑

### 单按钮写法
1. 玩家点击后，先禁用按钮（防连点）
2. 立刻通知程序「XX按钮被点击了」
3. 执行点击后的逻辑
4. 所有逻辑结束后等一定时间再恢复（或视情况不恢复）

### 多按钮写法（同页面多按钮互斥）
- 点击某按钮后，禁用的不只是当前按钮，而是所有不希望产生干涉的按钮
- 将按钮组的启用/禁用逻辑封装为「自定义函数」，点击后统一调用

---

## 6. 嵌套关系中的逻辑标准写法

### 当前标准做法
- 逻辑与程序变量均置于各自层级的 Rebolt 中
- 父级仅需创建一个用于更新子级程序变量的通知
- 子级 CCB 保持可复用性
- 程序变量分层自主管理

### ~~旧写法（已废弃）~~
- ~~所有变量和逻辑集中在父级~~ → 子级无复用性，父级臃肿
- ~~变量在父级，逻辑在子级通过参数传递~~ → 复用性差，维护复杂

---

## 7. 复杂函数规范

- 将逻辑按功能/对象/时序拆分成若干子函数
- 子函数在主函数中进行本地调用
- **单个自定义函数下不超过 20 个逻辑块**

---

## 8. 复杂状态 CCB 创建规范

当 CCB 包含大量互斥状态和图片资源时：
- **阈值**：图片节点 >12 且状态 >5 种
- **必须拆分**：按功能/对象/时序三个维度拆分为若干平级 CCB
- 让程序动态创建和卸载
- 维度选择：依据项目具体情况，将更灵活的维度进行拆分

---

## 9. Redream 中的 Rebolt 引用标注

为绑定 Rebolt Name 的节点设定颜色标记：

| 标记颜色 | 含义 | 限制 |
|---|---|---|
| 红色 | 程序调用 | 节点上不能 K 时间线帧 |
| 蓝色 | 程序赋值 | 文本节点上不能 K 文本内容帧 |
| 黄色 | 程序显隐 | 节点上不能 K 可见帧 |

目的：避免视觉美术与工程美术对同一节点的重复控制。

---

## 10. 互斥文本规范

| 条件 | 做法 |
|---|---|
| 同一位置文本 >5 个 | 放 1 个 Label 节点，通知程序通过动态替换 Label 的 Key 值实现 |
| 同一位置文本 ≤5 个 | 放 1 个 Label 节点，在 Rebolt 中将不同文本的多语言 key 写死在 Label 逻辑块中 |

占位符逻辑在多语言中依然生效。
